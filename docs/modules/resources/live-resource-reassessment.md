# Live 编辑与资源供给：完整重评

状态：2026-10-27，经用户同意重新评估并补充单机资源服务器方向的设计建议。只改方案文档，未实施、构建或运行；不将 B0/B1 的验收扩大为 B2 能力。本页拥有跨进程内容交付与 Live 发布边界，取代材质 Live r2 作为推荐实施方向；具体生产接口、数据库选型、预算和格式尚未冻结。既有 r1/r2 声明制品保留为历史，不继续作为传输实施合同。

本页与 [MS/MI 计划](material-program-plan.md)、[资产路线](asset-system-plan.md)分别负责 Live 边界、材质语义和后续资产生产流程，不重复维护同一套格式。已实现行为仍以 [Play 合同](../editor/projects.md#play-副本与变更批次)与代码为准。IOI 的原始来源及证据边界见[调查记录](../../research/glacier-live-resource-server-20261027.md)；以下不是 IOI 内部协议的复刻。

最新范围以[资产现态与参数撤销](asset-system-plan.md#当前范围资产现态与参数撤销)为准。本页的“精确版本”只指一次请求/实际消费选定的不可变内容，不要求资产历史存档；此前要求 Undo 持有旧导入内容的建议已撤回。持久索引和回收模型应按收窄后的真实操作重新选择。

## 结论

**保留 Live 编辑，保留已验证的材质内核，调整尚未实施的资源传输责任。** Live 的目的，是让作者在游戏继续运行时修改内容，尽快看到结果，同时不丢失编辑工作、运行状态和诊断。它不是多人协作协议，也不是将整个编辑器内存不断镜像到游戏。

重评区分一项已确认的提案限制与一项需要排除的扩大化风险：

1. **把资源字节交付塞进编辑命令。** r1 每次重传图片；r2 通过已确认材质组复用图片，但真实新图仍受命令批次大小限制。ACK 又同时成为采用证明、缓存命中前置和缓存生命周期边界，材质传输开始承担资源系统职责。
2. **不能把一致的发布视图误读成所有草稿一起成功。** 同次更新涉及的父子、程序布局和绑定确实不能混版；这不要求每次重编全场材质、替换整个游戏世界，或让一个无关的非法草稿永久阻止其他合法编辑。原方案已排除通用全图事务；这里进一步收窄“完整组”的解释，不声称原实现已经发生整世界替换。

用户补充希望布局资源服务器，但不需要分布式。相应将同机精确版本供给明确为单机资源服务，独立的无窗口进程作为建议部署形态；它集中内容存取、索引、后台工作和缓存寿命，不只是给零散文件操作换名。分布式构建、远程部署、VFS 或通用 AssetManager 仍不是前置，不因选择独立进程自动引入。

## 已核实的现状及偏差

| 观察 | 证据与判断 |
| --- | --- |
| 编辑器与 Play 已是独立进程 | [play_process](../../../src/application/play_process.cpp) 已有受限句柄继承、Job 与停止协议。崩溃隔离无需再引入资源服务器才成立；这不等于已有游戏崩溃后的自动恢复。 |
| Live 已有有序命令与背压 | [play_link](../../../src/application/play_link.cpp) 使用两条管道、读写线程、4 MiB 消息、16 MiB 批次、256 批/64 MiB 积压；spill 文件仍计入命令限额。没有 ACK 超时规则。 |
| 当前 ACK 不是 GPU 采用证明 | 接收端同步调用 `Session::apply_live` 后回执；[scene.cpp](../../../src/editor/scene.cpp) 逐项改资源/绑定，后续才有渲染准备。当前合同没有许诺全批事务，不能把新材质需求说成原协议已实现却失效的功能。 |
| 资源身份不等于精确内容 | `resource` 与 `add/attach` 等路径仍会从 Play 自己的 Project/缓存解析键；已加载资源、后来刷新目录和外部改盘可得到不同版本。B2 不能只修 `forward_material`，忽略创建/绑定资源的其他入口。 |
| 启动也没有完整资源冻结 | [run_project](../../../src/application/project_execution.cpp) 保存材质、构建并写私有 Scene，随后子进程自己加载；写出 Scene 不代表已经冻结其全部外部内容。 |
| 运行游戏不只是编辑器副本 | `set.properties` 有意稀疏写入，保留游戏改过的其他字段；游戏生成对象没有作者 LocalId，被游戏删除的目标按现有规则跳过/诊断。全世界快照替换会破坏这些行为。 |
| 现有 Reader 不是版本仓库 | [reader](../../../src/assets/reader.cpp) 有按键缓存和目录失效；[ImageCache](../../../src/assets/image_decode.cpp) 按编码源字节 SHA 复用解码 Image。这些能复用，但不提供跨进程按指定版本取内容的合同，不能只换个名字叫服务器。 |
| 不可变内容基础已经存在 | Image、Mesh、Surface 拥有内容；B1 的 ProgramSurface 与显式父解析也已经验证。应沿这些 owner 交接，不序列化 Runtime 根、指针、GPU 索引或代码地址。 |
| 资源大小确实与命令限制冲突 | 2048×2048 RGBA8 是 16 MiB，4096×4096 是 64 MiB；合法 Image 最大尺寸为 8192×8192。r2 可让旧图参数编辑不重传，却仍拒绝超过命令限额的真正新图。这是提案的静态反例，不是已运行 B2 的故障复现。 |
| 游戏代码还有独立的更新路径 | [ProjectCode](../../../src/editor/project_code.cpp) 在各进程冻结源码并自行轮询磁盘。材质的精确交付不能冒称已解决全部游戏代码、UI 源码、Mesh、天空或任意资产的版本同步。 |

已验证的 B0/B1 继续有效：语言纯计算、CPU/HLSL、具名 TextureInput、MS/MI 继承、不可变 Surface、compute/GBV。不重做这些内核，也不把它们当成产品多 pass、Editor、独立 Play 和 Live 的证明。

## 目标责任：单机服务不等于分布式系统

```diagram
┌────────────────────────┐
│ Editor / Session       │
│ 作者草稿、历史、冻结输入 │
└───────────┬────────────┘
            │
      ┌─────┴─────────────────────┐
      ▼                           ▼
┌────────────────────┐  ┌──────────────────────┐
│ 有序编辑命令        │  │ 单机资源服务          │
│ 目标、操作、版本引用│  │ 源码、图片、关系清单  │
└─────────┬──────────┘  └──────────┬───────────┘
          └────────────┬───────────┘
                       ▼
          ┌────────────────────────┐
          │ Play / Session / GPU   │
          │ 校验 → 准备 → 边界采用 │
          └────────────┬───────────┘
                       │ 采用结果 ACK
                       └──────────────→ Editor
```

| 责任 | 拥有什么 | 不拥有什么 |
| --- | --- | --- |
| Editor / Project / Session | 作者身份、草稿、保存、参数历史、当前资产关系；为每次请求冻结输入 | 不让后台任务重新读取活草稿或最新目录；不凭 GPU 表反推来源 |
| assets 内容与交付，由资源服务承载 | 单一作者 codec、精确输入描述、内容校验、当前查询/缓存、同机存取与请求保活 | 不决定哪个草稿应采用，不持客户端 Runtime 根，不保存 Undo，不拥有设备 |
| material / source | 声明、纯解析、CPU/HLSL 编译、不可变执行内容 | 不管理管道、磁盘缓存、整个场景事务 |
| Application / PlayLink | 启动域、命令顺序、背压、候选与内容请求配对、回执、停止和清理 | 不再自己实现材质图片去重或第二套 MS/MI codec |
| Renderer / RHI | 候选所需管线/绑定、准备结果、帧内容与设备退休 | 不选择作者版本，不把“资源已下载”当作 GPU 就绪 |

依赖方向沿已有 `atelier_assets` 边界：内容供给不依赖 Editor、presentation、physics 或 Renderer。若需要共用原子文件写入，将真实低层实现下沉并迁移调用方，不能反向调用 `editor::write_file`，也不另抄一套文件事务。这里规定责任，不规定每行都新建一个类或库。

## 首步落点：单机资源服务与请求内容

建议每个工程缓存域由一个资源服务进程拥有，Editor 按需启动，Editor 与先后启动的 Play 共用。使用本机 IPC，不要求监听网络端口或安装常驻操作系统服务。工程作者文件/GUID 仍由 Project 拥有；服务管理可复用的内容区与派生索引，Cache/Play 继续保存运行私有 Scene/清单及命令域，不把共享内容全部随一次 Play 结束删除。

生产者提交完整内容后，命令只给精确清单引用。客户端向服务取得指定版本及其实际读取期的保活；同机可以使用服务授予的只读内容文件/句柄，不必让大图绕管道复制。Editor/Play 不直接写服务数据库，不自行猜内容路径或驱逐缓存。服务自身负责发表、查找和保活的一致性，不把这些步骤拆成客户端必须正确拼装的一串数据库操作。

首批只接真实材质输入的存取/复用，沿用已有解码和编译实现；后续实际需要时再把导入、构建任务迁入相应模块。不能为了名叫“资源服务器”就首包新增万能任务系统；也不能把 Runtime 对象、JIT 地址或 GPU 资源当作可跨进程缓存产物。

- **冻结在先。** 来源为 Session 实际持有的源码、作者值、父内容、Image 和绑定关系。图片第一次可直接用既有精确 RGBA8，不要求先完成纹理压缩/Cook。不得收到命令后按资产键读取原工程最新版。
- **按内容复用，不按 ACK 猜已有。** 类型/编码版本、尺寸、长度及规范字节共同确定内容引用；同一运行内已有版本可以复用。发送前确保本请求引用的内容确实完整可取，并为请求持有它。接收端无需匹配上一次采用组才能读取，冷缓存也能取得相同结果。
- **一个 schema。** MS/MI 作者记录仍走 assets 的唯一 codec；清单只是精确源码、父图、图片版本和消费绑定的外壳，不新造第二套材质作者值。Scene 继续拥有 LocalId/$ref；内容去重不合并作者身份、父节点、具名输入或槽关系。
- **区分摘要用途。** 发布清单的完整性覆盖全部实际携带记录和内容引用，包括已捕获的休眠图片；不能直接拿可能排除休眠执行依赖的材质内容摘要作为整个包的身份。执行凭据继续核对源码、父内容及同次 Surface，不等于清单校验或编译成功。
- **完整后可见。** 新内容写完并校验后才切换当前条目；不能覆盖仍被请求/消费者读取的字节。冻结内容可由自持字节、受控文件/句柄或有界缓存提供，不预设永久内容地址库。清单只引用本请求可完整取得的内容。接收端验证长度、摘要、关系及实际预算，不接受命令携带的任意文件路径。
- **只搬冷数据。** 不在 UI/帧线程读写/哈希大图，不在每帧重新构造清单。真正的内容变化才产生新产物；仅 MI 数值改变不能重新编码、拷贝或哈希所有旧图片。

这是一条资源数据路径，不是把任意超限操作藏进文件。场景结构操作、字符串/数组写入和操作队列仍受命令预算；只有有明确类型、版本、完整性与生命周期的资源内容走新路径。

### 嵌入式数据库的角色

先从当前资产查询、实际依赖失效、已有构建缓存和预算管理确定需要持久保存什么。请求需要精确内容，不意味着数据库必须保存全部历史版本及其反向图；当前依赖和运行消费者也不能由历史缓存图代替。是否首版就需要数据库，以及 SQLite/LMDB 的选择，须按这些操作重评，不能沿用较重模型作为 SQLite 优先的充分理由。官方约束和可选模型集中在[数据库调查](../../research/local-resource-database-20261027.md)，不是已冻结的实现清单。

若接入数据库，由资源服务独占访问；interface 返回拥有型描述和内容保活，不泄漏事务或映射页指针。事务保持短小，不跨 I/O、编译或帧工作长期持有。作者文件/sidecar 仍为权威，数据库可作为其派生当前索引；资产条目本身不因此成为 Runtime 对象。大内容外置是布局选择，不是 SQLite 的功能限制。

任何布局都须保证获取内容与建立保活相对替换/逐出不可分割，不能先给可变路径再补保活。若选外置内容＋数据库，二者不是同一原子事务；成功确认、发表预留、失败清理和恢复需共同验证，不能让成功索引指向半成品。数据库调查中的完整内容图/tombstone 模型只是其中一种候选，不是不用它就无法保障寿命。

当前索引可从作者记录及有效产物重建；若另承诺保留某个构建缓存命中，才需保留足够来源/关系来重建它。只有图片 hash 不足以恢复父关系或槽顺序；丢失可重建缓存可以重新构建，不能冒称恢复旧请求。这里不增加历史版本恢复或未保存工作断电存档的保证。

### 预算与寿命必须一起实现

命令继续使用现有 4/16 MiB 和 256 批/64 MiB 限额；大资源分别计入磁盘存储、后台在途字节、已解码 CPU 内容和 GPU 的预算。清单本身也限制字节、节点及依赖数量，不能因为图片搬离管道就变成无界图加载。

首步保留现有图像尺寸/编码源/解码规则；新增资源总额和并发上限须在实施时按真实场景确定具体数字并做边界验收。本轮没有测量，不编造“足够快”或新的容量承诺。必须至少让一张实际 2K 新图及合法预算内的更大图不因 16 MiB 命令限制失败；超资源预算仍明确拒绝并保旧。

内容仓库中的文件由真实请求/快照保活，缓存仅持可逐出的附加引用：

1. 生产者在发送前持有请求所需版本，子进程完成读取/准备或取消并结束实际访问前不能删除它们。首步可保守持到该请求的最终 ACK/断开收尾，不新增逐图片释放协议。
2. 接收端已读出的 Image/Source/Surface 自持内容，文件逐出不会销毁这些 owner；若仍借用文件映射/句柄或异步读取，则 owner 必须继续保持该文件，取消也须先结束实际访问。只有 hash 不保活，长期数据库读事务也不是替代品。
3. 当前、候选、accepted-frame 与 GPU 在途各有独立 owner；替换当前组只撤掉当前的持有，不强销毁其余使用者。参数历史保存作者意图，不据此延长旧导入内容寿命。
4. 运行结束后，先停止子进程和相关 I/O，再回收本次运行私有区及请求保活；服务的可复用内容按独立预算回收，不一并删除。失败清理不能误删其他运行或作者文件；异常遗留按独立缓存清理处理，不依赖“退出一定执行完”。

ACK 仍可使某个请求释放传输保活，但**不再定义唯一可以复用的图片集合**。单机服务允许跨 Play 复用完整内容，不需要跨机器缓存、增量补丁或分布式一致性协议。缓存内容是否存在与对端采用了哪个组仍是两个事实。

服务故障不会使客户端已经拥有的 Image/Surface 自动失效；尚未完成的请求须明确失败，不能静默回读原盘或无限等待。数据库恢复不等于恢复客户端采用状态。首版不承诺透明重连：先停止相关读取/Play，再重启服务并建立新请求域；恢复前不按丢失的内存引用计数擅自删除旧文件。以后若要不停 Play 重连，须明确重新登记保活和迟到结果隔离，不顺手引入跨进程租约平台。

## 一致性：保留完整视图，缩小真正需要重做的部分

推荐将一次发布理解为“一个作者操作所影响的依赖闭包”，而不是任意单对象更新，也不是所有打开的草稿。

- 改共享 MS 时，包含实际受影响的父/子链、全部必要使用者及槽绑定；一个必要子 MI 启用失配，就不能把该父的新程序搭配旧子布局发布。
- 改独立材质 A 时，仍沿用其他材质已采用的精确内容。B 的未成功草稿不自动进入 A 的候选。候选最终仍组成一份完整且一致的当前视图；没有新增“允许混版”的例外。
- 同一次作者操作修改两个相关材质或绑定时，按该操作共同校验；共享祖先、共享被更新图片、同一槽变更会使闭包相交，不能错误拆开。
- 不变节点复用内容，依赖没有变化时不重编代码、不重解码图片。Renderer 的 shader 集合/全局表可能仍要求准备完整 batch；“共享完整视图”不等于所有底层工作都能局部更新，也不承诺本轮性能收益。
- 首包可以仍只有一个待准备材质候选和一个有序采用点，不建设并发分支合并或因果调度器。全局请求 serial 使旧结果失效；缓存可复用内容，但不得因此恢复旧请求的采用资格。

这是相对原来“完整组”措辞的必要澄清，也是待实际宿主接线验证的行为选择。作者草稿、当前有效内容和错误必须可区分；严格导出仍检查要导出的完整作者闭包，不因运行时保留旧内容而把非法草稿伪称可发布。

### 不覆盖游戏运行中的其他状态

Live 只改变这次作者操作声明的目标/叶/资源边。不要用 Editor 的整个当前世界替换 Play 世界，也不要因发表一组材质内容就重发所有对象的绑定。

普通 `properties` 的稀疏写入是已有行为；`materials` 当前明确是完整绑定表，不具有逐槽合并保证。首步沿用这个操作粒度：作者确实提交某对象的绑定表时，该表整体覆盖；只更新共享材质内容时，不附带覆盖其他表。若要求保护同一表里游戏改过的其他槽，须另行设计逐槽操作，不能将它伪称为本次保行为迁移已经具备的能力。

材质发布清单与“把它绑定到哪些目标”的操作须配对，实际采用前按 Play 当前目标和边核对：已被游戏销毁的目标沿现有诊断规则处理；有意编辑的同一字段仍按既有作者命令语义覆盖；游戏新增对象、未编辑字段、物理状态及独立运行时材质不应被重建。运行中仍引用被更新共享材质的消费者，也必须纳入真实消费/策略聚合，而不能只枚举 Editor 可见的 LocalId。

后续若开放 Dynamic MI/运行时换绑定，须明确哪些实例跟随共享资产更新、哪些独立持有内容；资源供给模块不代替这项业务语义。目前不为它额外构造一套脚本资源身份。

## 启动、更新、撤销与失败

### 启动

1. 在同一作者观察点冻结 Scene 及本阶段支持的资源版本，并启动后续编辑记录，保住现有“快照与转发没有空隙”的行为。
2. 发表完整内容/清单后启动 runner；runner 用这些精确输入装配并准备首组，完成采用后才 `start`。不能先启动业务再等待首组材质。
3. 首组实际采用须有明确启动确认；进程 running、文件写完或首条普通 ACK 不是这个确认。启动失败给出诊断并结束相应请求，不显示 in sync。

### 更新与撤销

1. 作者修改先形成精确候选；后台不读取随后变化的草稿。素材字节准备不阻塞 UI，命令有序进入 Play。
2. Play 核对运行域、文档、顺序、目标和精确输入，异步准备期间继续运行/显示旧完整内容。帧循环继续响应 Stop，不能为等资源同步阻塞。
3. 准备成功后在既有宿主边界采用，后续命令才越过此顺序屏障；ACK 表达此操作采用，而非 GPU 完成、Present 或屏幕实际显示。
4. Editor 收到正确域/序号/目标的 ACK，记录对端事实；即使本地已有更新草稿，该 ACK 仍可能真实有效，但不得复活本地过时请求。非材质 ACK 不证明材质采用。
5. 参数 Undo 是新的作者操作和新请求，不回滚导入内容或父资产历史。先恢复本地作者值，再按已定引用策略解析当前输入并冻结；冻结后才禁止回读变化的目录。撤销一次参数修改不能顺带把已重导入的 T1 恢复成 T0；即使新输入与早先相同，也不能复用早先请求的采用资格。引用撤销的具体边界仍见资产路线中的待决策项。

accepted-frame 点拾取继续匹配实际接受帧的几何、变换、身份和 Surface；不能因后台准备成功或 ACK 到达，就改用尚未显示的组进行屏幕拾取。

### 失败与恢复：不要借这次重评承诺通用热恢复

- 本地材质草稿编译/解析失败：保留草稿和诊断，当前有效组继续运行，修正后是新请求；不要为此销毁 Play。正式入口尚未找到可自然触发的 ProgramSurface→DXC/PSO 必拒夹具，这项验收缺口照实保留。
- 内容读取/完整性、必要依赖或可恢复 GPU 准备失败：候选不得部分采用。编辑器须收到明确结果，不能提前成功 ACK 或永远 pending。
- 首个跨进程增量建议保留既有保守的 **error → diverged → Restart Play**，而非顺手建立失败操作自动改写/重放系统。旧游戏可继续显示，但后续命令不假装已经应用。它是明确的首包体验限制，不是长期理想。
- 为什么不直接失败后跳过继续？后续 `add/attach/set` 可能依赖失败的新资源/身份，现有普通批次又不承诺全批回滚。没有明确依赖处理就跳过，会造成新的静默分歧。后续可单独设计材质可恢复 NACK、重试/替换屏障，但不能用缓存修复暗带这项协议扩张。
- 上传/编码后的 Renderer 终态错误不保证旧 GPU 可用，沿现有关闭约定处理；设备终态不能包装成普通材质草稿错误。
- 断开/文档替换使本运行请求失效。不能无确认跨运行复用 ACK；是否自动重启恢复是后续工作，不在这里添加重连重放。
- 首包必须提供 loading/preparing/error 等可观察进展及主动 Stop，明确返回的失败必须终结请求；不随意定一个总超时杀死合法的大图准备。长时间无进展的超时/卡死诊断策略在实施前另定，当前代码没有现成保证。

## 保留、撤下、延期

| 项目 | 重评处理 |
| --- | --- |
| 自有语言生成 HLSL、具名纹理、MS/MI、不可变 Surface | 保留 B0/B1；这些不是 Live 传输问题的根因 |
| 显式父候选、精确源码/关系、实际消费期同键多内容、迟到拒绝 | 保留安全寿命与采用前校验，不扩成可回退的资产历史 |
| Scene 作者 codec、LocalId/$ref、严格依赖与休眠诊断 | 保留单一权威；不复制协议 schema |
| 候选配对 MaterialBatch、全 pass、accepted-frame、GPU 退休 | 保留材质计划；“可读取”不代替“可渲染” |
| r2 `MaterialBaseline` 作为图片复用唯一来源 | 撤下；改由明确版本供给与实际 owner 保活 |
| 全部 RGBA/源码字节计入 Live 操作 16 MiB | 撤下；命令预算与资源预算分别执行，不无限放大二者 |
| 单在途材质采用、有序 ACK 屏障 | 首步保留作为简单执行策略，不再是内容缓存的前提 |
| 每次重新验证所有最新草稿/重建全世界 | 不采用；完整视图由受影响闭包加未变已采用内容组成 |
| 通用全图事务、并发命令依赖调度、自动失败重放 | 不做；现有普通 Live 的局部失败合同不偷偷升级 |
| 单机资源服务进程 | 纳入当前规划，集中版本内容、索引与缓存寿命；不是已实施能力 |
| 远程部署、VFS、分布式 Cook | 延期；不随单机服务一起展开 |
| Texture mip/压缩、Model Reimport、正式发行包 | 继续归 C–E；同机精确交付不等于完成这些阶段 |

## 建议实施顺序与停止条件

以下是可审查的范围，不是本次开始改生产代码的授权。

1. **保持 B1，完成材质本地消费。** 原生无纹理多 pass 可以独立验证；产品引用、全阶段采样、唯一 codec、Scene/绑定、Editor 历史按材质计划接通。唯一 loader 切换需要的数据、Examples 和生成器同候选升级；不为接入 Live 另做兼容 loader。
2. **以真实 Play 首次加载接入单机资源服务。** 复用同一材质装配入口，不写测试专用 loader。先证明冻结后改原盘也能启动原版本、首组准备后才 start、失败与停止可收尾，再开放增量传输。服务自身的启动/退出、存取预算及索引/内容恢复随此入口验证，不先做通用构建平台。
3. **接一个完整 Live 材质闭环。** 参数编辑、新图、共享父更新、绑定、Undo；既有 `materials/resource/add/attach/set` 中涉及材质的路径一起迁移到精确版本，旧材质传输被替换而非长期双轨。暂保有序屏障和错误分歧合同。
4. **再决定其他消费者与体验优化。** Mesh/天空/游戏与 UI Source 沿同一内容交付责任逐项接入。全部接通前只能称“材质版本一致的 Live”，不能称任意项目资源热更新或完整冻结游戏。连续预览、无关命令延迟、失败后免重启根据测量和实际编辑流程单独推进。

步骤 2 的先决条件是精确输入和正式材质消费者，不是把整个 C–E 提前实施。若实际改动开始要求通用资产图数据库、构建 farm、整世界事务或第二套资源身份，应停下重新切范围，而不是为了完成一个 Live 参数编辑继续叠框架。

## 必须有区分力的后续验收

这些是待执行场景，不是本轮结果；扩展现有 material/scene/project integration/renderer 入口，不增加 mock 框架。

| 场景 | 必须观察到什么 |
| --- | --- |
| 首次冻结后改原文件；同键两版并存 | runner 使用清单选定的精确源码/像素/父关系，不读新盘，不按 key 合并 |
| 2K 图片仅改参数；更换真正新 2K/4K 图 | 前者不复制/哈希旧大图；后者在资源预算内可用，不因命令 16 MiB 拒绝；记录实际 I/O 字节与延迟，不只看 JSON 大小 |
| 无上次材质基线/冷内容缓存 | 完整已发表内容可取，能得到同一结果；不是必须先构造 r2 baseline |
| 同默认值不同 shade；同 A/B 集合换槽 | 内容/程序及有向绑定关系均参与验证；集合相同不等于候选相同 |
| 共享 MS 合法、必要子 MI 启用失配 | 该闭包整组保旧；关闭失配项后整组恢复；无关合法材质可使用其独立新候选，不被坏草稿强行拖入 |
| 游戏改未编辑字段/其他对象绑定、生成或删除对象 | Live 不重置运行世界；同字段或同绑定表的作者操作及目标消失遵守既有规则；资源策略聚合覆盖实际消费者 |
| A→B→A、文档替换、迟到完成/ACK | 内容可复用，旧请求不能采用；对端真实 ACK 不被新草稿抹掉，不跨运行晋升 |
| pending、渲染 skipped/not_ready、点拾取 | 游戏继续使用旧完整组，拾取匹配 accepted-frame，不消费最新草稿 |
| 错摘要/截断文件/资源超预算/准备失败 | 新组不部分可见，给出明确错误，后续依赖操作不越过屏障；实际后端失败覆盖缺口单独标记 |
| 拖动预览、Undo、Stop、子进程退出 | 待发/在途均有界；测量准备期间帧/UI 响应，取消与退休不悬空；退出清理不删其他运行 |
| 磁盘缓存逐出但旧帧/读任务仍存活 | 自持精确字节的 owner 仍可消费；仍读取文件的 owner 阻止逐出，只有 hash 的记录不能冒充保活；不回读新盘 |
| 接入 Reimport 时：参数修改→贴图 T0→T1→参数 Undo | 恢复参数而保留当前 T1；不恢复旧文件，也不因参数历史保留 T0。该场景不将 Reimport 提前拉入 B |
| 重开 Play、服务异常退出、索引与文件不完整 | 重开可复用已校验内容；旧客户端内容仍有效，在途请求明确失败；恢复不能把半成品标 ready、恢复旧采用 ACK 或误删仍可能读取的内容 |

涉及核心发布寿命的直接入口用 Dev/Release，GPU 变化用实际验证层；视觉结果必须检查实际渲染。不得用 lower-level `#error` 或编译通过代替正式候选失败、窗口、Play 和 Live 证据。

## 本轮留下的真正决策

用户已同意精确版本供给与编辑命令分离，并希望布局不分布式的资源服务器。推荐将其落实为**按需启动的单机资源服务，拥有内容与索引，但不接管作者历史或游戏采用决策**。这会新增必要的有界内容存取责任，同时删除尚未实施的 r2 图片基线协议，不是无成本换名，也不是两套方案叠加。

沿已同意方向，独立坏草稿不阻止其他合法闭包发布；首个跨进程增量仍在明确失败后要求 Restart Play，不假称已有自动修复。数据库具体选型、预算数值、异步准备的无进展诊断和真实场景延迟需由下一轮实现/测量收敛，当前没有证据证明它们已经解决。
