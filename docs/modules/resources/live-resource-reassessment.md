# 单机资源服务：后续设计边界

状态（2026-10-29）：独立资源服务尚未实施。本页保留已同意的方向和待验证决策，不是当前功能清单，也不授权启动下一阶段。现行行为以 [Play 合同](../editor/projects.md#play-副本与变更批次)、[材质合同](../renderer/materials.md)为准；资产范围见[路线](asset-system-plan.md)。

## 起点与目标

当前 Editor/Play 已通过有序 Live 命令交付精确 Source、纹理与网格内容。消息/命令批次分别限 4/16 MiB，大资源经独立 spill 受 256 MiB 在途预算约束；发送方在 ACK/close 后回收。ACK 表示命令应用与 CPU 内容所有权交接，不是 GPU ready、Present 或显示证明。手动 Reimport、参数 Undo 和完整渲染组采用已经实现，不再列作服务的前置开发项。

服务要解决的是跨运行复用、统一内容存取、后台准备、索引与缓存预算，而不是再次解决“大图不能装进命令”。旧 r1/r2 的图片基线协议不再实施；一次请求需要精确输入，不要求持久资产历史。产品约束见[资产现态与参数撤销](asset-system-plan.md#当前范围资产现态与参数撤销)。

建议每个工程缓存域按需启动一个无窗口进程，使用本机 IPC，不安装常驻系统服务、不监听网络。作者文件/sidecar 仍是 Project 的权威数据；服务不持 Runtime 根、JIT 地址、GPU 资源或 Undo。IOI 的来源与证据限制见[调查记录](../../research/glacier-live-resource-server-20261027.md)，不是照搬其私有协议。

## 内容交付与生命周期

1. **先冻结，再交付。** 使用请求实际持有的源码、作者值、父关系和精确 Image/Mesh；收到引用后不能回读原盘最新版。作者记录复用唯一 codec，不序列化业务指针或另造材质 schema。
2. **完整后可见。** 内容写完并校验后才发表；读取与建立保活必须相对替换/逐出不可分割。客户端取得拥有型描述和受保护的字节/文件/只读句柄，不猜缓存路径、不接收任意外部路径。
3. **内容复用不依赖上次 ACK。** 冷缓存或没有上次材质组也应能取得指定输入；hash 本身不保活。内容身份覆盖实际携带记录、长度与规范字节，不能拿排除了休眠执行依赖的摘要代替整个清单的完整性检查。
4. **保留真实 owner。** 当前、候选、读任务、接受帧及 GPU 在途分别保活；取消后先结束实际读取再回收。已自持字节的客户端不受服务文件逐出影响，仍借用映射/句柄者必须继续持有它。
5. **只搬变更内容。** 仅改参数不重复编码、拷贝或哈希旧大图；UI/帧线程不做大图 I/O。命令、清单、磁盘、在途字节、解码内容和设备资源分别有界，不能因换成文件就绕过预算。
6. **失败不冒充恢复。** 服务退出不销毁客户端已有内容；在途请求明确失败。首版不承诺透明重连，重启建立新请求域，不能恢复旧采用 ACK，也不能用丢失的内存计数直接删除可能仍被读取的内容。

内容供给沿 assets 的低层边界，不反向依赖 Editor/presentation/Renderer。实际共用的文件发布机制应迁移单一实现，而不是复制文件事务或建立透传 manager。

## 数据库不是先决条件

先确定当前条目、真实依赖失效、构建命中和预算管理所需的操作，再比较现有文件/内存索引、SQLite 与 LMDB；[数据库调查](../../research/local-resource-database-20261027.md)中的内容图只是候选，不是必须实现的 schema。

若采用数据库，由服务独占短事务；接口不泄漏事务或映射页指针，不跨 I/O/编译持有事务。作者索引可重建，不等于能恢复旧请求。外置内容与数据库不是同一原子事务，必须验证成功确认、半成品清理和恢复，不能确认一个指向缺失文件的条目。

## 采用与回执：待设计的行为变化

- 一次作者操作影响的父子、程序布局和绑定必须一致；无关坏草稿不阻止其他合法更新。完整视图由受影响闭包与未变内容组成，不要求重编所有程序或替换游戏世界。
- Live 只改操作声明的目标/字段；现有 `properties` 是稀疏写入，`materials` 是完整绑定表，不伪称具有逐槽合并。游戏生成对象、未编辑字段及物理状态应保留；目标被游戏删除仍按现有规则处理。
- 若首版增加“材质已采用”回执，须在正式协议区分资源可读、CPU 交接、GPU ready、宿主采用和显示；不能悄悄重定义现有 ACK。启动全资源清单和首组确认同样属于新增合同。
- pending 保留上一完整内容；可恢复内容错误使用对应默认并保留作者数据/诊断。请求域、顺序或关系不可信、无法形成默认候选及设备终态仍失败，不能靠默认显示绕过完整性校验。
- 采用仍在宿主边界进行，旧请求不因 A→B→A 恢复资格；屏幕拾取只跟随实际接受帧。普通 Live 不升级为全批事务、自动失败重放或跨进程同时切换。

## 实施前需要收敛的问题

| 问题 | 必须作出的选择 |
|---|---|
| 产品边界 | 任意换父、导入设置历史、删除在用资产后预览/Play/严格构建的行为；不得删除既有场景和源码 Undo |
| 结构变化 | 模型槽删除/重排、声明改型及失效历史如何诊断与继续；不靠恢复旧导入内容解决歧义 |
| 存储 | 首版是否需要数据库，哪些缓存可重建，内容文件与索引如何共同发布/恢复 |
| 交接 | 自持字节或只读句柄的实际保活与取消规则，服务故障后的最小恢复边界 |
| 协议与预算 | 是否增加采用回执/启动确认，资源与并发上限，无进展诊断及 Stop 响应 |

先选一个真实 Play 首次加载消费者，验证冻结后改原盘仍读取选定内容、关闭能收尾，再替换一个完整增量更新路径。服务启动/退出与预算随消费者一起验证，不先建通用任务平台；迁移完成删除被替代路径，不长期双轨。

## 必要验收

扩展现有端到端入口，不新建 mock 框架。以下是未来服务的验收，不改记为本阶段已通过：

- 冻结后改原文件、同键两版、冷缓存：取得精确源码/像素/父关系，集合相同但 A/B 槽互换仍拒绝。
- 参数编辑与真正新大图：分别测实际 I/O 字节、延迟和预算；不以 JSON 大小代替资源成本。
- 共享父更新、失配覆盖、无关坏草稿：合法内容或默认一致采用，作者值及游戏未编辑状态不丢失。
- A→B→A、文档替换、取消与迟到 ACK：不复活旧请求，不跨运行确认；skipped/not_ready 时拾取仍匹配已显示组。
- 错摘要、截断、超预算、不可写路径、服务退出：明确失败或有诊断的默认采用，不确认半成品；后端准备的自然失败覆盖缺口另记。
- 逐出与在途读取并发、Stop 与重开：活 owner 安全、传输可回收、其他运行不受误删；不承诺崩溃零丢失。
- 参数修改→T0 重导入 T1→Undo：恢复作者参数并使用当前 T1，不让新服务重新引入导入历史。

远程部署、分布式 Cook、VFS、通用依赖调度和自动故障重放不在首版；实际延迟与内存收益必须测量。
