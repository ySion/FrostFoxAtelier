## 当前范围：资产现态与参数撤销

2026-10-27 用户收窄产品要求：**资产导入、删除、Reimport 不提供 Undo，也不提供可选择、回退的资产历史版本。** 以下约束修正此前将精确内容保活扩大到作者历史的建议，不代表生产代码已经迁移。

- **资产定位是数据。** 目录记录稳定资产键、种类和当前来源/产物定位；浏览与保存引用不要求先创建 Runtime 对象。离线数据经读取、解码或装配成为可消费内容，需要业务身份时才进入 Runtime；设备表示仍由 Renderer/RHI 创建。当前并非所有资产都已有独立 Cook 产物。
- **Reimport 更新同一资产的当前内容。** 成功后替换当前产物，不生成另一个可供用户选择的“旧版资产”。失败保留当前可用结果属于操作失败保护，不是 Undo；有实际复用价值的派生缓存可以保留，但不能变成资产历史的持久性承诺。
- **参数历史与导入内容分离。** 参数 Undo 恢复作者值，不恢复旧源文件、导入产物或像素。例如粗糙度 0.2→0.8 后贴图 T 成功重导入 T0→T1，撤销粗糙度应得到 0.2＋T1，而不是 0.2＋T0。历史表示不能仅为撤销参数而长期保留旧导入内容。
- **安全寿命仍然必要。** 当前消费者、准备请求、已接受帧和 GPU 在途工作可继续持有实际使用的旧内容；使用结束后按缓存策略回收。新建一次 Image/Surface 或短暂同键多内容不等于新建资产，也不要求持久版本目录。每次请求开始时冻结输入，冻结后不追随目录变化。
- **尚待确认的边界。** 建议贴图/父材质等引用也按参数处理，Undo 恢复资产键并在新请求中解析其当前已发表内容；缺失则保留缺失引用，不复活被删文件。引用、导入设置及既有场景结构/源码 Undo 的具体范围尚未确认，本次不据资产要求删除这些既有能力。已加载消费者何时跟随 Reimport、删除在用资产的表现同样待定。

当前代码已有普通 `ProjectEntry`、按需 Reader 和不可变内容 owner，没有持久资产修订仓库，正式 Reimport 入口尚未实现；但材质历史仍保存含根和 Image 引用的完整 `material::State`，后续接线必须区分作者参数与导入内容。待决策反例集中在[给 Pro 的问题](../../../to-questionnaire-live-resource-service.md)，不把旧历史图/数据库草图作为新增前置。

## 目标责任与现在就要避免的死路

```diagram
┌──────────────────────┐     ┌──────────────────────┐
│ 引擎发布的定义与内容 │     │ 工程作者文件与身份   │
└──────────┬───────────┘     └──────────┬───────────┘
           └─────────────┬─────────────┘
                         ▼
           ┌──────────────────────────┐
           │ 资产读取与依赖解析       │
           │ 身份 / 种类 / 版本 / 错误│
           └─────────────┬────────────┘
                         ▼
           ┌──────────────────────────┐
           │ 完整候选校验与发布       │
           └─────────────┬────────────┘
                         ▼
           ┌──────────────────────────┐
           │ 各 Runtime 的业务对象    │
           │ 共享不可变内容，不共享 ID│
           └─────────────┬────────────┘
                         ▼
           ┌──────────────────────────┐
           │ Surface / CPU 消费快照   │
           │ Renderer / RHI 设备表示  │
           └──────────────────────────┘
```

- **资产读取 module**拥有来源选择、精确键/种类核对、不可变内容和依赖解析，不拥有编辑历史、World 成员关系或 GPU 上传。引擎与工程是两个真实来源，已有 builtin 网格也进入相同规则；不只为 DefaultWorldGrid 加旁路。引擎定义可为随安装的数据或内嵌内容，物理存储不是资产身份。
- **Project 作者入口**继续拥有工程路径、导入/创建/保存和身份文件；目录读取与创建 sidecar 不能被混作只读安装加载。现有 `Project::open → refresh` 会为新文件生成身份，不能直接把引擎安装伪装成第二个可写 Project。
- **作者文档**拥有草稿、历史与保存点；**资源解析/发布**不隐含“创建可写草稿”。当前先隔离只读定义与这些行为，不为 B 顺带重做多场景 UI。未来共享资产文档按工程与 AssetId 唯一，其详细合同沿[多文档规划](../editor/projects.md#后续方向可响应加载与多场景文档)，不复制另一套撤销规则。
- **材质 module**拥有 Source/Instance 的类型化约束、继承、覆盖、合法内容发布；资产目录不实现着色。引擎 Source 不暴露权威内容的可写镜像，普通 Instance 可编辑；UI、Control、Live 和底层正式发布入口遵守同一保护，不把磁盘只读或 UI 禁用当作 Runtime 冻结。
- **构建责任**当前复用真实导入与碰撞 Cook；未来接管冻结输入、BuildKey、产物校验和缓存。运行读取侧不能永久依赖源美术绝对路径、导入器或编辑器窗口。调整归属时迁移现有实现与消费者，不留下新旧双权威入口。
- **Renderer/RHI**继续拥有设备表示、上传与退休；业务更新产生新内容，不能原地修改在途快照。重置旧 GPU 工作不是普通内容发布的实现方式。

### 身份、版本和依赖的具体约束

1. 继续保留 Project GUID 与精确引擎键的现有身份，不为统一外观批量重发 GUID。资产引用可在未加载/缺失时存在；显示回退不改其作者目标。来源命名域不等于物理目录，不根据搜索路径先后允许工程冒领引擎身份。
2. 引擎默认 Material Source 属于引擎安装；工程引用它或创建 MI，不给每个工程隐式生成默认资产副本。无 Project 也可解析；未知键、错种类、缺版本均有明确错误。
3. 参数键、AssetId、SubAssetId、Scene LocalId、BuildKey、ArtifactKey、Runtime ObjectId、GPU 索引各按自身作用域使用。AssetId 不能用内容摘要替换，否则两个相同内容但独立作者资产会被错误合并。
4. 一次构建可能产生多个输出；BuildKey 标识输入与构建条件，ArtifactKey 标识具体产物，不把二者永久当同义词。未来构建键至少覆盖构建器/产物版本、目标、规范化设置及实际输入/依赖摘要；顺序、浮点编码和路径规范化需明确。基础 [Hash](../../../src/foundation/hash.hpp)已声明仅用于进程内查表，不能直接持久化；沿已有 SHA256 能力计算规范编码摘要，不重写算法。
5. 大小/mtime 可作为快速变更信号，但未来显式 Reimport/正式构建校验内容。当前依赖文件列表也不是完整依赖图：应区分构建输入、产物顺序、运行加载和发布包含；按需加载不等于打包可遗漏。首批只表达实际边，不建立通用图数据库。
6. 内容发布版本、目录 revision、Runtime 写代号与异步请求代次不互相替代。发布只接受完整候选；失败留下旧版本及可见错误。遇到失联可容忍显示，但正式构建的必需依赖不能冒充成功。
7. 内容失效按实际消费传播。材质颜色不能触发碰撞 Cook；纹理像素不应无差别重建几何；Emission/Mask/Opacity 必须更新相应材质快照、采样/覆盖/射线与历史。不能仅替换 Texture 内部图片就声称所有持有旧 Surface 的消费者已更新。

## A：有界资产前置（已集成）

按以下顺序交付真实行为，不先提交空目录、概念类或全能管理器：

1. **先闭合依赖快照反例。** 基线文档持有槽一→A、槽二→B，磁盘 sidecar 改成 B/A 并 Refresh；A/B 文件仍齐全，原导出可通过，重开却读新关系。原 [导出根集](../../../src/application/editor_control.cpp)只核对默认资产文件在集合中，[副本验证](../../../src/application/control_artifacts.cpp)的 mesh hash 不含槽默认关系。A1 已通过真实公开入口红绿验证这条反例及同键混合已加载版本：修补候选逐个比较内容和关系，不一致明确拒绝导出、保留原工程，不偷偷改写作者绑定。恢复重试、同内容多 owner、草稿及缺失资源原合同均有对照；不据此声称已覆盖任意外部并发写入。
2. **收拢真正的读侧解析。** 用现有内置网格与 Project 资产验证来源、类型与错误合同；保留工程身份/导入/缓存。移动实现以解除 Editor/Play 调用方的来源猜测；CMake 划分只随真实依赖调整。不提前创建尚无消费者的 Source/Texture 构建插件；这些实际生产者随 B 接入。
3. **确定发布与作者编辑的 seam。** 源定义、运行资源、可写文档的归属不再由 parent 是否为空推断；引擎解析不进入 MaterialDocument 的保存/撤销/repro 草稿枚举。需要的材质对象表示在 B 一起实现，不把空接口算 A 交付。
4. **明确安装与 repro 的共同合同。** 沿已有 CMake 部署入口和 repro manifest 扩展引擎依赖身份、种类与内容/语义版本；包记录依赖，不覆盖安装定义。现有 engine 语言源码摘要校验保留，不宣称已认证任意未来 C++ 材质实现。只读安装、没有原开发树和变更依赖时拒绝必须有真实验收。

A 不升 Scene/材质格式，不转换 Examples 作者外观。已有 rename 末次 refresh 失败不回滚磁盘改名的静态边界另记待核实，不能以导入回滚概括所有写操作；本次不顺手扩成全文件系统事务工程。

### 已定的读侧骨架与交付拆分

- **A1：依赖快照一致性。** 仅改应用层快照/副本验证及对应验收；冻结实际使用版本与槽→材质关系，逐一比较，不能以同 key 去重掩盖不同已加载版本。不修改 Project/Session 或格式；先用真实反例验证再修补。
- **A2：保行为的读侧迁移。** 新的 `src/assets` / `atelier_assets` 实际拥有类型化读取、纯解码、工程目录索引、不可变内容缓存及依赖收集。`Project` 组合 `assets::Reader`，扫描/写身份后提交完整目录候选，继续拥有配置与作者文件事务；不增加只读 Project 模式，也不让 Reader 回调 Project。目录入口可保留只读视图，不保留两套索引、typed-read 包装或调用方来源 fallback。保留导入预载、图片复用和失败回滚；默认 Reader 只用现有三个内嵌网格证明无工程读取，不预造 Source 类型。
- **依赖方向。** 读侧依赖几何、不可变材质值、天空内容及实际低层文件/codec 工具，不依赖 Editor、presentation、physics 或 Renderer/RHI。共用槽名归 geometry；纯 codec 与文件读取随真实消费者下移；SHA 在 A3 需要时才提取现有实现，不借迁移做全仓工具整改。Cook 与 Runtime 业务资源不移入 Reader。A1 的导出文件先冻结，再接入 A2 的调用点迁移。
- **A3：引擎依赖核对。** 保留精确的 `builtin/cube`、`builtin/sphere`、`builtin/plane` 身份；内嵌生产者拥有显式语义版本，规范内容摘要另有编码版本。repro 增加必需、独立版本化的 `engine_assets`，记录实际依赖的 key、kind、语义版本、内容 SHA256 与摘要编码版本，并在发表候选前核对实际使用集合，不能通过删记录绕过。旧包缺该字段明确要求重新导出；不改 Scene/material 格式，保留 `engine_sources`。未知引擎依赖的严格拒绝属于本阶段行为变化，不伪装成 A2 的机械迁移。

内容摘要只认证所比较的数据；语义版本是生产者的实现兼容声明，不认证任意未来 C++/shader。安装验证需实际排除原开发树，并用真实内容/语义版本变化的第二安装作反例；仅换 CWD 或修改 manifest 不足。不修改共享开发目录或借此改变语言源码的开发树优先合同。

### A3 的实施约束（已实现并验证）

- `EngineDependency` 是拥有型记录，字段为 key、kind、semantic_version、digest_version、content_sha256。Reader 的精确引擎查询核对期望种类，不回退工程。三个现有内嵌网格由一张生产者表拥有身份、版本 1 与生成入口，不将版本写进工程 sidecar，也不预接 B 的三键。
- `engine_assets` 采用 `{version:1,records:[…]}`，包括空集合；kind 使用稳定字符串。缺字段的旧包要求重新导出；结构、重复项、编码版本不合法与内容/种类/语义版本不匹配分开诊断。真实 I/O 或密码提供者故障保持 `storage_error`，不当作依赖不匹配或静默回退。
- 摘要编码 v1 按固定字段顺序、小端整数、长度前缀与有限浮点原始位编码实际发布内容：最终顶点/切线、bounds、有效边、parts、有序槽、完整 Surface（含 opacity）、六路图片/采样与派生统计、槽默认关系。不 hash padding、地址或生成参数。逐字段定义通过有界缓冲批量送入现有 SHA，不逐标量调用 BCrypt，也不分配整个大型网格的临时编码；仅在冷路径使用。SHA 实现下沉 foundation，Control 保留协议错误适配。
- **严格根集来自实际冻结文档和候选，不来自整个缓存或复制目录。** 包括停用对象、已知资源位中的未解析引擎键、真实默认关系，以及按这些根取得的发布材质草稿。`Session::material_assets()` 的全会话枚举本身不是根集。旧磁盘引用已被草稿替换时，宽容 `asset_files` 可以保全旧文件，但不能因此扩大严格依赖集合。普通字符串不解释为资产引用。
- 导出继续逐份保留 A1 已加载版本与槽关系核对；重开在候选发表前比较实际依赖完整集合，不能只遍历 manifest 声明。沿现有 admission，在关闭旧文档前拒绝失败候选。现有 `repro.open` 的未保存文档和运行 Play 前置拒绝不放宽；这些 `unsaved_changes` / `busy` 对照不能冒充依赖检查失败的原子性证明。
- 安装验证采用一次私有源码 Release 宿主构建与两次真实 builtin 增量重链，产生基准、同键内容变化、仅语义版本变化的三个安装。移走仅私有编译源码位置，实际 DACL 只读部署，工程/缓存/报告另置可写目录；创建、修改、删除拒绝须真实验证且异常恢复仅私有权限。三安装使用同一未改 repro 对照；这只证明该私有构建宿主离树运行，不宣称当前主工作树原二进制的 OS 级全盘隔离。执行前核对具体隔离脚本，不改共享源码或目录权限，不增加产品测试后门。

### C–E 需要预留语义，但现在不预造框架

- **构建键与作者设置：**导入设置、子资产映射、人工覆盖是权威作者数据，进入版本控制；索引、缩略图、构建数据库与派生缓存可重建。发布 Catalog 是一次构建的冻结输出，不是活工程目录的别名。产物写盘先完整校验再发布，不能把局部产物作为缓存命中。
- **同图多用途：**颜色/法线/标量/Mask 可需要不同构建变体，但不能把源 Texture 的身份等同一个固定颜色空间。现有 sRGB/线性语义由材质输入决定；UV/采样仍属绑定，不能无缘由进入像素重建键。引入新 mip/压缩政策时核对 CPU/GPU 采样及阈值附近行为，不能“只剩 GPU Blob”就宣布迁移完成。
- **模型身份：**当前槽名或 `slot/<index>` 是现有绑定合同，不代表已有跨 Reimport 的稳定 SlotId。D 才建立权威映射和可审查升级，不为新名字批量改当前模型。导入器写导入层，人工修改在独立 MI/覆盖层；删除、重排、同名输出均需冲突策略。
- **请求与线程：**正在构建的候选和当前已发布版本分开。后台只准备适合并发的拥有型不可变数据；Runtime 访问和引用发布在 owner 阶段。请求代次限制发布资格，关闭/取消/新请求使晚到结果失效；现有并行图片解码不等于完整异步资产系统。
- **可用与驻留：**目录有记录、字节已读、CPU 可用、设备可消费不是一个 bool。目录浏览不默认加载全部内容；对象、请求、编辑文档、缓存、GPU 工作分别说明保活理由，参数历史不因此保留旧导入内容。逐出缓存只能撤去缓存持有，不能销毁仍被消费者持有的业务对象；未来预算实现需覆盖这些理由，不能在 A 先挂一个未执行的“预算”参数。
- **共享作者状态：**未来多文档把资产作者状态提升为按工程/AssetId 唯一的文档；各 Runtime 只消费其发布内容。当前 Session 内历史不复制到多个场景后再声称支持共享编辑。与既有多文档方案一起演进，不建立第二个调度或撤销系统。
- **暂缓基础设施：**远程资产服务器、分布式缓存、复杂补丁、虚拟纹理、任意原生 shader 逃逸/完整节点编辑器和泛化插件框架没有当前前置必要性；B 的受限材质着色程序及真实 Play 所需同机精确内容供给不在此延期清单中。资源服务是责任边界，不自动等于远程基础设施。

## 实施协调与需要真正收敛的事项

总负责人维护本页的跨模块范围和交付判断。资产/编辑器负责目录、作者文件与文档；材质/Renderer 负责 Source/Instance、Surface 及消费失效；Runtime/语言负责受限材质编译及必要 CPU 执行能力，不另造业务对象世界；World/presentation 保持绑定、成员与对象合同；物理继续拥有碰撞内容。阶段性文件归属随任务分配，不能据此推导每个名词都要新库或新代理。

每个增量先明确输入、拥有者、候选发布条件、错误保留及验收入口，再分工。A 的复现一致性修补可先独立验证；读侧责任迁移先保持行为并验证，再在 B 改材质行为与格式。迁移完成删除替代路径；不接受新旧解析长期并行，也不以接口空壳作为交付。

以下是在对应阶段落地前要确定的具体细节，不是重新询问已批准方向：

- A3/B：沿上述已定归属落实摘要规范编码、安装根及真实隔离验收；B 新 Source 的键和实现语义版本由材质生产者与消费合同共同确定。不能只 hash 默认参数就声称 shader 实现也相同。
- B：最终作者格式、参数键与覆盖粒度、支持链/输入预算、受控转换与外部旧工程的处理说明；不静默扩大兼容读取。缺失作者数据的保留和严格失败需一致。
