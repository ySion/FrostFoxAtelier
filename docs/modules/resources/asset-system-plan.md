# 资产系统：当前边界与后续路线

资产读侧、MS/MI 创作与正式消费、手动纹理/模型 Reimport 已实现。实现合同分别由[工程工作流](../editor/projects.md)、[材质系统](../renderer/materials.md)和[项目场景](../world/project-scenes.md)维护；验收限制见[渲染验收](../renderer/acceptance.md)。本页是跨模块决策与后续范围的唯一入口，未实施方向不代表现有功能。

## 当前范围：资产现态与参数撤销

- **资产导入、删除、Reimport 不提供 Undo 或可回退的资产版本。** Reimport 更新同一资产的当前内容；失败保护已提交文件，不表示提供资产历史。
- **参数 Undo 恢复作者值和引用意图。** 粗糙度 0.2→0.8，贴图 T 随后重导入 T0→T1，撤销粗糙度应得到 0.2＋T1。引用撤销恢复资产键并解析其当前内容，不恢复旧文件或像素。
- **安全寿命不等于资产历史。** 请求、代码租约、已接受帧及 GPU 工作可保有实际使用的旧内容；缓存只增加可逐出的持有。不得为减少历史而破坏这些 owner，也不为参数 Undo 长期保存旧导入内容。
- **作者数据与显示结果分离。** 缺失关联、休眠/失配参数保留原意图及诊断；默认替代不写回作者数据。严格加载和 Repro 仍检查格式、身份、内容与关系，见[资源发布与默认替代](../renderer/materials.md#资源发布与默认替代)。
- **资产定位是普通数据。** 浏览目录不创建所有 Runtime 对象；读取、解码、装配按需发生。目录 Refresh 不等于自动 Reimport，设备表示由 Renderer/RHI 创建。

任意换父、导入设置历史及删除在用资产的产品行为仍需具体设计；不因上述资产要求删除已有场景结构或源码 Undo。

## 责任与身份

| 责任 | 拥有的合同 | 不接管 |
|---|---|---|
| assets / Reader | 引擎与工程的类型化读取、目录索引、不可变内容、依赖解析与摘要 | Runtime 根、作者历史、World 成员关系、设备资源 |
| Project | 工程路径、稳定身份文件、导入/创建/保存及文件失败保护 | 引擎定义的可写副本、GPU 采用 |
| Session / 作者文档 | 草稿、历史、保存点、运行资源装配及候选资格 | 另一套资产身份或长期导入历史 |
| material / source | 类型化声明、父链、覆盖、CPU/HLSL 编译及精确消费内容 | 管道、目录扫描或通用资产调度 |
| presentation / Renderer / RHI | 完整消费组、接受帧、设备准备与退休 | 作者文件和资产版本选择 |

Project GUID、引擎键、参数路径、Scene LocalId、Runtime ObjectId、请求代次和 GPU 索引各有作用域。相同内容不合并作者身份；目录 revision、内容摘要、请求序号及 GPU 完成也不能互相替代。引擎定义由引擎拥有，工程不能冒领其身份，无 Project 也能读取内置资产。

Repro 的严格根来自冻结文档、实际 World 成员和网格默认槽关系，而非缓存全集。每份已加载内容及其关系先校验再去重，候选发布前双向核对依赖集合；同键不同内容、A/B 槽互换不能被文件齐全或集合相等掩盖。当前字段及摘要版本只在正式 codec/模块合同维护。

接口与持久格式遵循[单一开发基线](../../engineering.md#当前开发基线)：实现、消费者、Examples、生成器一同升级，旧输入明确拒绝，不保留旧 loader 或产品迁移旁路。未完成文件事务不能发表半成品。

## 后续范围：不自动启动实施

| 方向 | 最小完整结果 | 边界 |

| Model 产物与重映射 | 源文件产生稳定子资产，重排/删除后能保住明确匹配的人工覆盖 | 手动 Reimport 已实现；通用 SlotId、重命名推断、骨架/动画/LOD 尚未承诺，歧义必须诊断 |

| 单机资源服务 | 按需启动，集中当前内容、可重建索引、请求保活及预算 | [服务边界](#单机资源服务待设计)仍是提案；不以现有 Live 大资源传输作为独立服务已实现的证明 |
| 其他资产 | 动画、音频、Prefab、程序化以真实消费者复用上述责任 | 不预建空 importer/serializer，不将程序化内存内容强制伪造成文件资产 |

## 后续实现必须保持的约束

1. **构建与发布分开。** BuildKey 覆盖构建器/格式版本、目标、规范设置和实际输入依赖；ArtifactKey 标识具体产物，二者不是永久同义词。沿现有 SHA256，不持久化进程内 Hash。大小/mtime 只能作变更信号。
2. **后台只处理拥有型输入。** Runtime 访问和引用发布在 owner 阶段；取消、关闭、新请求淘汰迟到结果。内容相同不能恢复旧请求的采用资格。
3. **按实际消费失效。** 材质颜色不触发碰撞 Cook，图片替换不无差别重建几何；Emission/Mask/Opacity 的相关消费和历史必须同步更新。
4. **预算覆盖实际寿命。** 目录记录、CPU 可用、设备可用不是一个状态；请求、文档、缓存、在途帧分别说明持有理由。逐出只能撤去缓存持有，不能销毁活消费者。
5. **未来多文档共享作者状态。** 按工程/AssetId 唯一，沿[多文档规划](../editor/projects.md#后续方向可响应加载与多场景文档)演进；不复制每场景历史后声称支持共享编辑。

下一步先确定具体产品操作、输入/拥有者、失败边界及可区分验收，再选存储和模块。远程服务器、分布式缓存、通用调度器、全图事务及插件框架不是当前前置。

## Texture 到 UI 的共同消费：待接线

已有 Runtime Texture、受保护原生访问、不可变 CPU 图片、`ui::ColorImage` 与 Renderer 上传/退休；剩余缺口是语言跨类型对象目录、对象引用字段访问，以及固定内容版本到 UI 测量和绘制的共同接线。Runtime 能保存引用字段不表示语言已能编译 `UiState.texture.width`。应扩展共同语言目录与执行根，不能用资源专用整数句柄或另一套脚本对象替代。

目标是两个真实 UI 使用位置共享同一个 Texture，由正式 `source::Program` 读写显示参数；文件和程序化内容共用发布链。具体责任在接线前确定，必须保持：

- 借用外解码或生成完整不可变候选，在 `with_native` 内交换内容拥有者；失败保留旧内容。捕获复制独立 owner，结束借用后才交给 UI/Renderer，不带出原生地址，也不暗藏未登记业务引用。默认空 Texture 不可消费，加载失败不伪造零尺寸成功资源。
- 一次 UI 消费冻结内容版本与尺寸。同步 Measure 不加载文件、发布资源或执行业务回调；固定尺寸叶即使不触发 Measure 也须持有内容。像素到逻辑尺寸、宽高比、DPI 与 provider revision 的规则须随消费者确定。
- 图片按现有 [ColorImage 协议](../ui/style-sheets.md)转换，不能无条件复用材质槽的颜色/alpha 解释。布局成功仅发布几何，`LayoutSnapshot` 不保活图片；呈现准备失败保留上一完整输入，不拼旧几何与新内容。
- Runtime 对象、内容版本、设备表示各有寿命；来源记录弱观察活对象，不以缓存永久持根。显式销毁后的业务访问失败，已捕获内容只结束自身消费，不能反向访问已销毁对象。
- 在同一 RHI owner 编码上传与读取，不为普通更新逐次 finish。退出先停请求和业务执行、结束未编码消费、释放 UI 根与呈现持有，再完成资源设施有效期间的 Runtime 退出；设备表示和 Pipeline 释放后排空并关闭 Context。原始 gfx 句柄不保活 Context。

首个贯通结果须观察到同对象共享、固有尺寸/宽高比及固定尺寸叶的持有、内容更新后的正确像素、失败保留、旧 CPU/GPU 消费安全结束与有界关闭；代码更新与内容更新分别记录。首例不要求字体、资源包、后台加载或显存流送。底层合同见[Runtime 原生借用](../../runtime-model.md#同步原生借用)、[语言](../../../LANGUAGE.md)、[RHI](../rhi/contract.md)；资源层次依据见[行业资源研究](../../research/rhi-reassessment/engine-resource-industry.md)。

## 单机资源服务：待设计

现有 Editor/Play 已交付精确 Source、纹理与网格的有序 Live 批次；协议、spill 预算和 ACK 只由 [Play 合同](../editor/projects.md#play-副本与变更批次)维护。独立服务解决跨运行复用、后台准备、索引与缓存预算，不再次解决“大图不能装进命令”。建议每个工程缓存域按需启动无窗口进程，使用本机 IPC，不安装常驻服务或监听网络。作者文件/sidecar 仍由 Project 拥有，服务不持 Runtime 根、JIT 地址、GPU 资源或 Undo。

### 内容交付与回执边界

1. **先冻结，再交付。** 请求持有实际源码、作者值、父关系和精确 Image/Mesh；接收引用后不回读磁盘最新版，复用唯一 codec，不另造材质 schema。hash 本身不保活，内容身份须覆盖实际记录、长度与规范字节，不能用排除休眠依赖的执行摘要替代整份清单校验。
2. **完整后可见。** 写完并校验才发表；读取与建立保活相对替换/逐出不可分割。客户端取得拥有型描述及受保护字节、文件或只读句柄，不猜缓存路径，不接收任意外部路径。冷缓存或没有上次 ACK 也能取得指定输入。
3. **保留真实 owner。** 当前、候选、读任务、接受帧及 GPU 在途分别保活；取消先结束实际读取再回收。自持字节的客户端不受服务文件逐出影响，仍借用映射/句柄者继续持有。参数编辑不重复编码、拷贝或哈希旧大图，UI/帧线程不做大图 I/O；命令、清单、磁盘、在途字节、解码和设备资源分别有界。
4. **失败不冒充恢复。** 服务退出保留客户端已有内容，在途请求明确失败；首版不承诺透明重连，重启建立新请求域，不恢复旧采用 ACK，不凭丢失的内存计数删除可能仍被读取的内容。
5. **采用不混同显示。** 若增加材质采用/启动确认回执，正式协议须区分资源可读、CPU 交接、GPU ready、宿主采用和显示，不重定义现有 ACK。旧请求不因 A→B→A 恢复资格，拾取只跟实际接受帧；普通 Live 不变成全批事务、自动失败重放或跨进程同时切换。

受影响父子、程序布局和绑定要一致，无关坏草稿不阻止合法更新；完整视图由受影响闭包和未变内容组成，不要求重编全部程序或替换游戏世界。Live 只改操作声明的目标/字段，保留游戏生成对象、未编辑字段和物理状态；`properties` 稀疏写入与 `materials` 完整绑定表仍遵守现行协议。pending 保留上一完整内容；可恢复内容错误可用对应默认并保留作者值/诊断，不以默认显示绕过请求域、顺序、关系或设备终态错误。

### 存储与实施终点

先确定当前条目、依赖失效、构建命中及预算操作，再选择文件/内存索引、SQLite 或 LMDB。[数据库调查](../../research/local-resource-database-20261027.md)的内容图是候选，不是既定 schema。若使用数据库，由服务独占短事务，不跨 I/O/编译持有事务，不泄漏映射页指针；外置文件与数据库不是同一原子事务，须覆盖确认、半成品清理与恢复，不能确认缺文件条目。作者索引可重建不等于能恢复旧请求。

实施前还需确定任意换父、导入设置历史、删除在用资产、模型槽删除/重排、声明改型及失效历史的产品规则，以及保活/取消、采用回执、并发预算、无进展诊断和 Stop 响应。先用真实 Play 首次加载验证冻结后改原盘仍读选定内容、关闭能收尾，再替换完整增量路径，不先建通用任务平台；内容供给留在 assets 低层边界，不反向依赖 Editor/presentation/Renderer。

未来验收扩展现有入口：同键两版与冷缓存、槽位互换、参数与新大图的实际 I/O/预算、共享父和失配覆盖、取消/迟到 ACK、截断或超预算、逐出与在途读取、Stop/重开，以及参数修改→重导入 T1→Undo 仍使用 T1。失败必须明确或有诊断地采用默认，不能确认半成品；延迟与内存收益另作真实测量。IOI 依据及其不能证明的私有协议细节见[Glacier 研究](../../research/glacier-live-resource-server-20261027.md)，不把外部证据升级为本项目承诺。
