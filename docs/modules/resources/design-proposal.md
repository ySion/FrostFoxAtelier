# 共享 Runtime Texture 与 UI、RHI 的连接方案

状态：资源连接提案，尚未实施完整的源码到 UI 贯通链。2026-10-11 更新：原生载荷访问、Runtime Texture/Material、CPU 图片、UI 图片绘制和窗口渲染已经可用，接下来需要连接源码与 UI 消费。已落地的资源合同见[材质系统](../renderer/materials.md)；本文不重新建立业务身份、布局或渲染入口，也不将三维材质验收当作 UI 资源贯通验收。

资产身份、引擎/工程来源、Material Source/Instance 与后续构建、重导入和交付的阶段划分见[资产系统计划](asset-system-plan.md)。本文仅负责 Texture 到 UI 的消费链，复用共同资产发布机制；两个计划都不代表尚未实现的能力已经可用。

## 已有机制与剩余缺口

| 层面 | 已有实现 | 本方案剩余工作 |
| --- | --- | --- |
| Runtime 身份与引用 | 共同类型定义、对象身份、持有/观察引用、GC、引用字段与序列操作，以及原生 Texture/Material | 复用现有 TextureResource 和内容捕获，补齐源码与 UI 消费 |
| 原生载荷访问 | `Runtime::with_native<T>` 已提供同步、受保护的对象/内联字段访问 | 用现有接口发布和捕获 Texture 内容，不新增私有存储旁路 |
| 业务语言 | 正式 `source::Program`、原生/描述型对象与同步值能力 | 当前对象环境仍只有一个绑定类型；跨类型对象目录与对象引用字段尚未开放，不能直接编译 `UiState.texture.width` |
| CPU 资源 | 不可变 `geometry::Mesh`、`material::Image`、`material::ProgramSurface` 与共享引用 | 复用已有内容机制；独立内容快照与 Runtime 业务对象分别承担寿命责任 |
| UI 内容与绘制 | 不可变 `ui::ColorImage`、UI 帧持有、样式图片及 Renderer 上传/缓存/退休 | 将 Texture 捕获的固定内容版本接到已有图片消费与测量流程 |
| 布局 | 同步 Measure、content/provider revision、完整几何发布及快照 | 确定固有尺寸政策，并把内容版本与本次几何一起持有 |
| RHI | gfx 设备资源、Context/Pipeline、窗口/离屏执行、有限排空与退休 | 由现有 Renderer 持有设备表示，保证未编码消费和 Context 的寿命关系 |

权威接口：[Runtime](../../../src/runtime/runtime.hpp)、[语言规范](../../../LANGUAGE.md)、[源码宿主](../../../src/source/program.hpp)、[CPU Mesh/图片](../../../src/geometry/mesh.hpp)、[UI 帧](../../../src/ui/frame.hpp)、[布局](../../../src/ui_layout/layout.hpp)、[Renderer](../../../src/renderer/renderer.hpp)、[RHI 合同](../rhi/contract.md)。

Runtime 能保存对象引用字段，不代表语言编译器已经能访问它。当前缺口应在共同语言目录、引用读写与执行根上补齐，不以资源专用整数句柄或重复脚本对象替代。

## 拟实现的端到端结果

宿主加载或生成图片，建立共享 Runtime 中的 Texture 对象。真实业务源码让两个 UI 使用位置共享该对象，并修改显示参数。UI 捕获一个确定的内容版本，以其尺寸完成布局；现有 Renderer 消费匹配的几何和图片，GPU 读回得到预期像素。

图片更新、代码替换、撤去引用或显式销毁后，内容版本、CPU 绘制输入和 GPU 使用期均有明确持有者。文件来源与程序化内容走同一发布和消费流程。本方案不要求先扩展字体、材质、资源包、后台加载或显存流送。

## 资源身份与所有权

| 责任 | 建议语义 |
| --- | --- |
| Texture 业务对象 | 共享 Runtime 中的普通对象，原生与自有语言共用类型、身份和引用规则 |
| 图像内容 | 发布后不可变，包含尺寸、格式和像素；一次消费捕获确定版本 |
| 来源记录 | 解析来源和加载设置，弱观察活对象；来源路径不自动成为永久存档身份，缓存不默认阻止 GC |
| UI 呈现输入 | 持有与几何匹配的 CPU 内容；布局 key 不能替代对象身份或持有关系 |
| 设备表示 | 由 Renderer 在所属 RHI 执行域内创建、缓存和释放，复用现有图片上传/绘制入口 |
| GPU 使用期 | 已编码工作由 gfx 状态与退休机制管理；尚未编码的 CPU 消费由上层保持 |

原生 CPU 资源可以独立于 Runtime 和 GPU 存活。Mesh Shader 管线、引擎 Mesh 内容、业务对象身份和 GPU 句柄各有职责；统一类型世界不要求每个 buffer、mip 或 descriptor 都成为 GC 对象。工业依据见[资源研究](../../research/rhi-reassessment/engine-resource-industry.md)。

## 原生访问与内容发布

直接使用已有 `with_native<T>(object, callback)` 或内联字段重载。回调返回 `Result<R>`，返回数据必须自持有；不得将对象地址或借用视图带出作用域。借用期间可按 Runtime 合同嵌套借用和修改合法字段，创建、销毁、GC 与 JIT 进入受到限制，具体规则只维护于[Runtime 同步原生借用](../../runtime-model.md#同步原生借用)。

拟采用的发布顺序：

1. 在借用外完成解码或程序生成，准备完整的不可变内容候选。
2. 在受保护访问内交换内容拥有者；失败保留原内容，成功后推进对应内容版本。
3. 捕获时复制独立内容拥有者，结束借用后再交给 UI 和 Renderer。内容不能暗藏未登记的业务引用；引用写入继续经过 Runtime 正式入口。

默认空 Texture 尚不可消费，首次加载失败不伪造零尺寸成功资源。首例保留当前 CPU 内容及仍有消费者持有的旧版本，暂不引入预算换出。

UI 图片使用现有 `ColorImage` 的颜色/alpha 协议，材质图片遵守自身槽位的解释规则；接入时明确转换，不能把两个内容类型无条件互换。协议见[UI 图片样式与绘制](../ui/style-sheets.md)。

## 捕获、布局与绘制链

1. **初始化**：共同注册业务和 Texture 类型，建立资源设施、UI 内容绑定与现有 Renderer，然后创建对象。
2. **业务执行**：通过正式源码宿主共享 Texture 引用、更新显示参数，沿已有执行根与错误清理返回。
3. **内容发布**：在规定的宿主阶段发布完整候选；内容版本与代码版本分别记录。
4. **捕获与布局**：捕获业务状态和固定内容版本，提供同步 Measure；测量不加载文件、不发布资源、不执行业务回调。固定尺寸而未触发 Measure 的图片叶也必须持有内容。
5. **呈现准备**：按内容版本取得设备表示，安排上传，并与对应几何组成完整呈现输入。资源更新推进适用的 content/provider revision。
6. **编码与提交**：在同一 RHI owner 上录制，保持上传与读取顺序；正常内容更新不逐次 finish。窗口尺寸沿现有窗口同步合同处理。
7. **回收**：CPU 消费结束后由设备表示的 owner 释放 gfx 句柄，已编码的 GPU 使用继续由 gfx 退休机制保护。

布局成功只表示几何发布；后续绘制准备失败时，由呈现拥有者保持上一完整输入，不回退布局核心，也不能拼接旧几何和新内容。`LayoutSnapshot` 自身不保活图片或业务对象。

显式销毁业务对象后，后续业务访问按 Runtime 规则失败；已捕获的独立内容可结束自身消费，不能借它重新访问已销毁对象。撤去最后一个根不等于立即析构或 GPU 完成。

退出顺序为：停止新请求 → 结束业务调用和未编码消费 → 释放 UI 业务根与呈现持有 → 在资源设施有效期间完成业务资源/Runtime 退出 → 释放设备表示和 Pipeline → 排空并关闭 Context。原始 gfx texture/buffer 不保活 Context，不能提前关闭其执行域。

## 共同接线前需确定

- 确定 Texture 来源/内容发布和 UI 内容绑定的生产位置及唯一拥有者，复用现有 Renderer 图片入口。
- 明确像素尺寸到逻辑尺寸、受限宽度下宽高比及 DPI 的测量政策；实际影响测量的提供者变化才推进 provider revision。
- 在共同语言接口中实现本例所需的跨类型目录和对象引用字段访问，保留失效引用、执行根、错误清理与 GC 屏障语义。原生载荷访问已经可用，不再作为待新增 API。

具体接线由共同实施任务确定；本文不另设业务 Widget 树、全局回调总线或资源专用执行宿主。

## 端到端验收终点

| 场景 | 必须观察到的结果 |
| --- | --- |
| 真实语言共享 | 两个 UI 使用位置引用同一 Runtime Texture 对象，由真实源码读写，未用裸整数模拟身份 |
| 布局到像素 | 固有尺寸和宽高比正确；固定尺寸叶也保有内容；GPU 读回匹配图片 |
| 内容更新 | 尺寸/像素变化令缓存失效，几何、图片和内容版本对应 |
| 失败保留 | 加载、布局或呈现准备失败保留相应旧完整结果，恢复后可继续发布 |
| CPU 与 GPU 使用期 | 未编码消费保持旧内容；替换/撤引用后旧 GPU 工作仍正确结束 |
| GC 与显式销毁 | 撤根后正常回收；显式销毁后业务访问失败；缓存没有永久持有根 |
| 来源与代码独立 | 文件和程序内容共用消费链；兼容代码替换不改变 Texture 身份，失败代码不破坏旧入口 |
| 安全退出 | 未编码消费结束后按拥有关系释放并有界关停 |

以上共同消费者尚未实施。实施时在 Dev/Release 使用生产模块完成这条贯通验收，保留既有 Runtime、语言、UI、布局与 RHI 验收，不建立 mock 或单元测试框架。
