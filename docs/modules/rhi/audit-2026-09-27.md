## Standards

### S1 · P2：创建中途失败可能释放未初始化的原生指针

固定 gfx 的 `command_allocators_`、`fences_` 使用未清零的 `gfxMalloc` 数组。某个 `CreateCommandAllocator/CreateFence` 失败后，`gfxCreateContext` 删除半初始化的 `GfxInternal`；`terminate` 却遍历全部帧槽并检查/Release 指针，可能读取尚未初始化的槽。离屏 back-buffer 拥有数组也有同类不变量缺口。

- 位置：[分配与失败出口](../../../out/dev/_deps/gfx-src/gfx.cpp) 1141–1143、1307–1336；清理 1672–1692、1714–1723。
- 依据：[工程指南](../../engineering.md)“所有权、布局与校验”和原生资源释放责任。
- 最小修正：拥有指针数组零初始化，或只清理成功初始化的槽；覆盖初始化失败退出。
- 证据等级：源码证实；本次没有运行原生分配/创建失败实验。

其余发现也涉及输入检查、借用有效期与释放责任，以下按行为契约报告，不重复计数。没有独立的命名、文件长度、switch、少量 guard 重复或薄封装整改要求。

## Spec

### 执行与生命周期

**E1 · P1：内部缓冲表改变后继续使用旧 `Buffer&`。** `encodeDispatchIndirect` 在 `installShaderState` 前取得参数 Buffer 引用；安装大 CBV 会创建/替换常量池，触发 `GfxArray` 搬移或删除时交换对象，后续 transition/ExecuteIndirect 仍使用旧引用。当前公开普通命令范围即可触发。定位：生成 [gfx.cpp](../../../out/dev/_deps/gfx-src/gfx.cpp) 4369–4375、7771–7791；[GfxArray](../../../out/dev/_deps/gfx-src/gfx_internal_types.h) 216、277–298。MultiDraw、Indexed、MultiDispatch、DrawMeshIndirect 及 buffer→texture 上传有同型路径，应在同一次修正中处理。修法是在所有可能创建/删除 Buffer 的内部操作之后，重新按句柄取引用，保持现有容器和入口。

**E2 · P2：正常关停遗留 DXGI 拥有引用。** 宿主始终向 gfx 传显式 adapter；该路径取得的 `IDXGIFactory4` 没有配平，`EnumAdapterByLuid` 写入的 `adapter_` 也没有在最终清理中释放。D3D12MA 自行 AddRef/Release，不接管这两份引用。定位：[宿主调用](../../../src/rhi/rhi.cpp) 135–136；生成 gfx.cpp 1173–1188、1509–1770。隔离副本的观察结果为原实现剩余引用 2，仅释放 factory 后为 1，再释放 adapter 后为 0，各执行三轮。修正应进入固定 gfx 补丁，覆盖成功和失败出口。

**E3 · P2：反复 `finish()` 不复用已完成的常量池空间。** `finish` 成功 sync/Reset 后不清零当前槽的 `constant_buffer_pool_cursors_`；现有清零只在初始化和 `frame`。合法离屏消费者反复“大常量 dispatch → finish”时，已经完成的常量空间仍按累计游标分配并扩容。定位：生成 gfx.cpp 5202、5210–5223、7775–7790。修法是在完成与 Reset 均成功后复位可复用游标，失败路径保持原终态。源码证实；本次未测长期内存曲线。

### 管线与普通资源

**P1 · P1：`shader_model` 边界可导致栈越界，不能安全返回 `Result`。** [prepare](../../../src/rhi/rhi.cpp) 169–171 只检查非空；gfx.cpp 9533–9545 向每行 16 字节的 profile 数组直接 `strcpy` 后缀。`lib_` 加 12 字节后缀及 NUL 已超过行容量；128 字节输入的隔离进程在打印“before prepare”后以 5 退出，没有返回结果。准确的异常码未捕获，不将退出码 5 命名为某个 Windows 异常。另一个同边界问题是显式 `file_path=""` 经 gfx.cpp 3191 访问 `strlen()-1`；后者仅源码证实。将 model 的格式/长度与空路径处理统一收敛在描述输入边界，或在固定补丁中安全构造；保持默认合法输入与失败保旧行为。

**P2 · P2：Mesh 最低硬件门槛未落实到选卡。** [Context::open](../../../src/rhi/rhi.cpp) 124–127 选中首个支持 FL12_1 的硬件后停止枚举，146–147 只记录 Mesh 能力；仅 `prepare(mesh)` 才拒绝不支持设备。这不满足[本轮目标](../../research/rhi-reassessment/gfx-execution-plan.md)“Mesh Shader 为最低硬件要求”，多卡时还会漏掉后面的合格卡。应将 Mesh tier 纳入候选筛选，没有合格硬件时 open 返回 unsupported。源码证实；没有使用不支持 Mesh 的硬件或多卡环境动态验证。

**P3 · P2：纹理回读忽略目标 BufferRange 的起始偏移。** gfx.cpp 4073 构造 footprint 时使用局部 `buffer_offset`，未加 `gfx_buffer.data_offset_`。64×32 RGBA8 纹理复制到 offset=512 的读回 range，实测前缀 512 字节被改写，目标范围有 512 字节不匹配；debug/GBV 未报错。将 range 基址纳入目标 footprint，并保持复制范围合法即可，无需第二套资源包装。

**P4 · P2：Program 的 buffer 参数数组未释放。** gfx.cpp 557–570 的 `Parameter::set` 分配 `GfxBuffer[]`，636–650 的 `unset` 只有 image/constants 释放分支，遗漏 `kType_Buffer`；Program 退休同样经过此处。反复绑定/替换 Program 会遗留 CPU 参数存储。增加对应释放，纳入同一次普通资源生命周期修正。源码证实；本次未进行堆分配计数实验。

上述 E1–E3、P3–P4 和 S1 是固定上游带入当前集成的缺陷，不表述为现有 guard/timeout 补丁新制造的问题。借用普通资源与命令是[当前契约](contract.md)允许的路径，因此不能仅以“上游问题”排除。

### 构建集成

**I1 · P2：公开 target 未传递 C++23 要求。** [cmake/rhi.cmake](../../../cmake/rhi.cmake) 73–78 对库自身调用 `atelier_target`，但未设置 `PUBLIC cxx_std_23`。只链接 `atelier_rhi` 的消费者目前只继承 gfx 的 C++20，而公开头文件使用 `std::expected`。增加公开编译特性即可。源码证实；现有验收单独调用 `atelier_target`，不受此项阻断。没有据此声称所有当前消费者编译失败。

## 距离 Wave 1 收尾还差什么

范围专家追溯了主线 `docs/research/wave1-meeting/`、当前 Runtime/JIT 文档，以及 RHI、UI 两个工作树的现行决定。原会议的 Wave 1 主线是共享类型、对象/GC、源码与诊断、安全执行、请求/发布/退休；RHI/UI 是可并行支线。材料未形成统一且当前有效的全局退出门槛，因此不报告虚构完成百分比。

| 范围 | 当前状态 | 收尾动作 |
|---|---|---|
| 主线 Runtime/JIT/语言 | 历史成员取址、请求诊断已修；早退清理共享已晋升；共同函数签名、标量结果和版本调用存储有后续双配置证据 | 保留主线当前未提交演进，避免用同 HEAD 的 RHI 旧源码覆盖 |
| RHI 本体 | 正式三管线矩阵已通过；本次确认九项缺陷 | 完成下述一次局部修正及最小相关端到端验收 |
| 自研 UI 布局首增量 | 独立工作树已实现；dev/release 各 17 场景及 minimal 消费者通过 | 纳入实际主线构建和对应验收，不要求先与 RHI 互连 |
| 模块合流 | 主线仍无 `src/rhi`、`src/ui_layout`，三个工作树未合流 | 串行整合模块、根 CMake、唯一依赖锁、README 与部署文件；随后对实际集成树执行 dev/release 聚合 |

**建议只安排三个收尾动作：**

1. **一次 RHI 修正。** 在既有宿主边界落实输入/硬件门禁和 C++23 传递；在固定 gfx 补丁内处理 Buffer 引用、range 基址、拥有资源释放、部分初始化与完成后的池复用。外部入口和 gfx 的资源/状态权威继续保持统一。
2. **修正后的相关验收。** 将确证反例变成最小真实消费者回归，开发/发布均覆盖受影响路径；保留原三管线与超时矩阵。没有相应硬件的负 Mesh/多卡场景继续准确声明边界。
3. **模块合流及最终树验收。** 保护主线语言/函数契约的新改动，串行整合 RHI 与布局首增量，再验证实际组合结果。本次只做审计，没有自动执行合流、提交或推送。

RDG、完整 renderer、Present/resize/HDR、多队列、并行录制、语言渲染绑定、设备恢复，以及布局后续共享轨道/换行/局部调度，没有依据升级成本轮完成条件。JIT 槽复用、名字索引、GC 索引和共享 LLJIT 也仍按实际负载决定，不恢复已被替代的 Recording/Ticket/Publisher 方案。

汇总：Standards 1 项独立发现，最高 P2（部分初始化清理）；Spec 8 项发现，最高 P1（Buffer 引用失效、shader profile 越界）。
