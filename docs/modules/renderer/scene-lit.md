# Scene Lit

Scene Lit 是现有 `Renderer::render(Frame)` 的一种视口着色方式。World 持有材质和 LightComponent，Application 从同一 World 生成拥有 CPU 数据的 SceneSnapshot，Renderer 同步借用快照并经唯一 RHI Context 录制、提交、Present。MatCap、Smooth、Flat 保留各自的显示语义，Edit/Play 不选择着色方式。

实现入口为 [scene_lit.cpp](../../../src/renderer/scene_lit.cpp)，它是 Renderer 私有的 GPU 资源与通道拥有者；没有新增业务对象注册表、原生设备、原生队列或第二套提交接口。纯 UI 和空场景不启动 Scene Lit 管线；相关资源在首次非空 Scene Lit 绘制时准备，关闭与尺寸变化沿既有 gfx 退休机制处理。

## 材质和真实灯光

- 不透明金属度/粗糙度材质：基础色、roughness、metallic、线性 HDR RGB 自发光。自发光在曝光前保留大于 1 的值。
- 点光源使用 candela，矩形面光源使用 cd/m²，方向光使用 lux。点光源半径以米表示，方向光角半径以弧度表示；矩形使用米制宽高与单面/双面设置。
- World 唯一负责层级变换与灯的正交方向；Renderer 接收最终位置、传播方向和矩形切向轴。空间缩放不隐式改变灯的物理尺寸、范围或强度。权威数据约束见 [World lighting](../world/lighting.md)。
- 点光和矩形光使用有界距离衰减；方向光覆盖全场景。直接光使用 GGX 表面响应，矩形光对真实发光面积采样。当前没有 LTC 贴图或 RTXDI 依赖。
- 每帧最多 256 盏灯；局部直接光按屏幕分块筛选。阴影预算限制同时追踪可见性的灯数，默认 4，界面可选 4/8/16，单灯样本数 1～64。方向光优先，再按稳定键排序，超额灯仍正常照明。应用显示实际与请求阴影数，如 `Shadows 4/5`；增加第五盏灯不会拒绝整帧。

LightComponent 表示照明源，当前不自动创建可见发光几何。自发光网格是独立材质输入，也可被 DDGI 射线命中；当前没有“这个发光网格属于哪一盏解析灯”的绑定合同。样例中的发光板与解析面光源是独立光源，不用重合的二者重复表示同一个发光面。

## 同一帧的执行链

1. 紧凑光栅 GBuffer 写入法线/粗糙度、基础色/金属度、HDR 自发光、运动信息及原有场景深度。屏幕坐标使用整个窗口，`scene_viewport` 处理物理像素偏移，支持透视与正交投影。
2. 共享不可变网格缓存 BLAS，稳定实例更新 TLAS。内联 RayQuery 完成灯光可见性和 DDGI 探针射线；能力由 RHI 的 `inline_ray_query` 明确报告。
3. 直接光、预算内真实射线阴影及深度/法线约束的空间与时域可见性过滤。
4. 有限体积 DDGI：规则 XYZ 探针格、八面体方向辐照度与距离矩、可见性加权八探针插值、背面分类、受限位置修正、分帧更新及有界上一轮间接反弹。
5. GTAO 基于深度重建与地平线积分，只调制间接项，保留直接光和自发光。它补充屏幕空间接触遮蔽，不能代替场景阴影。
6. SSSR 使用 GGX 随机反射方向、分层深度遍历、工作列表和间接分派，再做反射时域重投影。屏外、遮挡或追踪失败回退到均匀环境辐射。
7. 原生分辨率 TAA、Bloom、EV 曝光和 SDR 色调映射；随后保留编辑辅助显示与 UI 的既有合成入口。

以上功能通过现有显示菜单独立开关。当前环境是均匀线性 RGB 辐射场，预积分 GGX BRDF LUT 用于其镜面响应；没有方向 HDR 环境图、场景反射探针资产、透明材质、蒙皮 BLAS、ReSTIR DI、全路径追踪或超分辨率接入。低样本面积光的可见性过滤是工程近似，64 样本路径用于实际图像比较，不声称复刻 NRD/SIGMA。

DDGI 默认覆盖 `[-6,-1,-6]` 到 `[6,5,6]` 米，`8×4×8` 个探针，每帧更新 32 个，每个探针 64 条方向射线。每轴支持 2～32 个探针，射线数支持 1～64，体积、网格密度与更新预算均通过 `ViewSettings::lit` 传入。探针命中的灯光采样还可能追踪阴影射线：这些归入 visibility 计数，probe 计数记录主探针查询，因此总射线数超过“探针数×方向数”。灯的 `casts_shadow` 同样控制命中点的直接光阴影，主探针与距离矩的可见性始终保留；主视图的阴影预算不改变探针接收点的照明合同。当前是一个有限体积，不包含相机跟随级联和无限世界流送。

## 身份与历史

World/Runtime 仍是业务对象身份与生命期的唯一权威。Application 将完整组件 ObjectId 映射为快照域内的非零稳定键，并在条目离开快照后移除映射；键不保活对象。场景替换改变 `scene_identity`，几何、成员、材质及灯参数编辑改变 `scene_revision`，普通相机移动和连续位姿更新不会每帧清空历史。

Renderer 用前后相机和实例变换生成运动信息，结合深度、法线与重投影有效性拒绝错误历史。尺寸、视口、模式、效果选项、场景域和拓扑变化沿同一失效机制处理；camera cut 清除表面历史，保留仍有效的世界空间探针。材质/灯编辑和场景替换使受影响的场景历史失效。缺少稳定网格键的旧调用仍可绘制，但不复用该物体的时域对应关系。

## 诊断与性能边界

`FrameStats::scene_lit_gpu_ms` 为八个阶段的原始 GPU 完成样本：GBuffer、AS/上传、直接光/阴影、DDGI、GTAO、HDR/SSSR、TAA、Bloom/色调映射。只有八个 timestamp 与射线读回都对应同一个完成的 RHI 录制序号时，`scene_lit_gpu_timing_valid` 才为 true；`scene_lit_gpu_sample_sequence` 与 `scene_lit_gpu_sample_frame_id` 标识样本。完成结果可能滞后或重复，统计分位数时必须去重；没有用平滑时长计算 p95。

阴影和探针射线数来自 GPU 实际执行计数，与上述完成样本关联。阴影灯数、未获阴影预算的灯数和历史重置数则描述当前编码帧。`scene_lit_resource_bytes` 是资源逻辑字节加 AS 数据量，不包含 GPU 驱动分配开销、scratch 和待退休资源，不能称为显卡实际总显存。

性能入口为 `atelier_renderer_acceptance --scene-lit-benchmark --output <目录>`：原生 2560×1440，预热后收集唯一的原始完成样本，测量阶段关闭验证并且不 Capture。图像验收使用 `--scene-lit --output <目录>`，启用 GPU 验证并导出逐项图片；其同步读回耗时不作为性能结果。实际数据与验证状态见 [验收记录](acceptance.md)。

可打开的真实工程见 [Scene Lit Room](../../../examples/scene-lit/README.md)。性能目标基于 RX 6800 XT；目标帧率与最终本机实测应分开陈述。
