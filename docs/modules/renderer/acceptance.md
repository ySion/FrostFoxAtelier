# Renderer 验收

本页说明 Renderer 的端到端验收入口各自证明什么、怎么运行、哪些还没覆盖，以及当前的性能基线。行为和参数见[显示合同](contract.md)、[Scene Lit](scene-lit.md) 与[材质系统](materials.md)；某次运行的结果看门禁日志，历史过程看 Git。

## 运行

- `renderer_acceptance` 目标包含下面 11 个入口，每个入口一个独立进程，使用真实窗口，限时 1800 s，任一失败即整体失败。每个入口另有单独目标 `renderer_acceptance_<入口>`（`-` 换成 `_`，默认入口是 `renderer_acceptance_default`），按改动只跑相关入口时用它。日志写在构建目录的 `renderer-acceptance-<入口>.log`；Scene Lit 入口的图像与 CSV 证据写在 `renderer-evidence/<入口>/`，默认入口的截图直接写在可执行文件目录。也可以直接运行 `atelier_renderer_acceptance --<入口> --output <绝对目录>`，默认入口不带参数。
- 验证层：默认入口、`--scene-lit` 和 `--material-programs` 请求 GPU-based validation，[验收门禁](../../../tools/acceptance-gate.ps1)对这三个入口保留 GBV。`--scene-lit-stability` 及门禁中的其余窗口入口使用 D3D12 debug layer；`--scene-lit-benchmark` 关闭验证，计时采样期间不读回图像。直接运行时，环境变量 `ATELIER_GPU_VALIDATION=debug` 会把进程内的 GBV 请求降为 debug layer。GBV 下首次准备 Lit 或材质批次管线可能需要几分钟；其余入口在 debug layer 下多为 5–30 s。
- 检查不依赖 `assert`，Dev 和 Release 中同样生效。改动核心运行时或构建链时两种配置都要跑。
- 硬件：RHI 要求同时支持 Mesh Shader、DXR 1.1 inline RayQuery 和 SV_Barycentrics 的 GPU。阈值和下文读数来自 RX 6800 XT，其他 GPU 没有跑过。窗口必须可见，运行期间桌面不能被其他全屏程序占用。
- 期望值由独立真值或参考帧得出：解析或数值积分的真值、同一场景清历史后收敛的终点、关闭被测效果的对照帧，不取自被测实现。帧间比较用 RGB8 最大通道差，mean/p95 在实际几何像素或指定 ROI 上统计。

## `--material-programs`

`renderer_acceptance_material_programs` 是窗口/GPU 入口，门禁对它保留实际 GBV。`material_programs.cpp` 保留原 72 行 CPU/compute LOD0 与 144 行运行期数学对照，分别写入 `outputs.csv` / `math-outputs.csv`；此处的手工坏 HLSL 仅是直接 RHI 失败对照。

同一入口随后执行 `material_batches.inl` 的公开原生 Renderer 消费：两个真实 MS、不同 Params 布局与具名纹理输入、显式父 Surface 的子/孙/兄弟解析；编译 Runtime 销毁后准备批次。检查 pending 不替换 Capture、准备/取消/CPU 拒绝期间旧整组逐像素不变、缺失/不完整/越界槽表和无 batch 网格帧拒绝、准备完成后颜色/coverage 同时变化，以及 live batch 的 close busy 与无 capture 的在途退休。

默认回退用真实 `compile_material` 的未知标识符错误产生缺失定义，保留 `Broken.source` 与原编译诊断，再由 material 的正常解析入口生成引擎默认 ProgramSurface。该程序与正常程序共用批次和 17 条管线；Smooth 与 GBuffer/TAA 编辑深度检查品红外观和完整 Opaque 覆盖，并在修复后恢复原 Mask 孔洞。它证明前端失败到默认消费，不是自然 DXC/PSO 拒绝或 Editor 自动编译调度的证据。

新组贯通 Smooth、Flat/MatCap/Cavity、编辑线深度、GBuffer、TAA 无抖动编辑深度、程序化阴影孔洞。真实 DDGI 房间验证完全离屏的暖/冷发光、仅参数替换、被 Mask 丢弃的亮发光体不照明；同几何 Opaque/Masked 实例换序仍保留非 opaque 候选执行。新增读回写入 `native-outputs.csv`，图像为同目录 `native-*.png`，程序输入为 `NativeMask.source` / `NativeOpaque.source`。

纹理用非对称红/蓝棋盘和坐标图对照：最终缩放 UV、世界位置、变化的法线/切线及纹理驱动坐标在镜像非均匀变换下仍正确过滤；GBuffer 与编辑深度使用过滤 coverage。相同程序集合的参数/图片修改无需重新准备 PSO，已准备但未采用的图片在旧帧连续绘制后仍有效。同一图片的 linear/sRGB 解释、类型化空值、Repeat/Clamp/Mirror 与 orientation 折点分别检查。DDGI 用 LOD0 仅接受蓝纹素、过滤后为紫色且 coverage 为负的输入，区分正确的命中后过滤、错误的 LOD0 着色及错误的二次 coverage 拒绝。

这证明原生纹理多 pass 与批次寿命；正式 Editor/presentation 绑定、保存/历史、accepted-frame 点击由编辑器与 World 入口验证，原生 CPU `evaluate` 对照不称为点击验收。极端掠射、非有限/溢出梯度到最粗 mip 仍缺定向 GPU 用例；合法 ProgramSurface 自然触发 DXC/PSO 失败仍没有确定性夹具，不以取消、前端拒绝或直接 RHI 的 `#error` 代替。必要回归为两配置此入口与 `renderer_acceptance_default` / `renderer_acceptance_scene_lit`；逐轮实际结果以门禁日志为准。旧图像/光照场景通过验收专用 `standard_fixture.inl` 作者夹具构造真实 StandardPBR MS/MI，再提交同一公开批次 API；生产中不存在固定材质兼容入口。

## 默认入口

GPU validation，一个 641×385 的窗口，覆盖 Renderer 的帧合同和工作室显示：

- 帧合同：接受、跳过、最小化、隐藏、resize 时接受旧目标并报告下一目标、过期尺寸不发布 capture、编码前失败可恢复且保留上次 capture、owner 线程限制、关闭幂等且在 HWND 销毁前排空。
- UI：线性预乘混合到 sRGB 目标、半开裁剪、R8 覆盖图带行 padding、绘制顺序、一次 draw 覆盖多 clip 和多张图片、圆角与边框、版本上传一次并退休旧版本、无效形状在编码前拒绝。
- 场景：近处遮挡远处、非对齐宽度的深度读回、left-handed row-major 投影；变换（旋转、非均匀缩放、剪切的逆转置法线、镜像、极端缩放、非法矩阵整帧拒绝后恢复）；网格（只提交可见网格、新版本替换并退休旧 CPU 所有者、缺资源整帧拒绝）；主视锥剔除（可见区间读原实例下标、同几何实例共用 draw、重入镜头、跨眼平面保守保留、空场景清计数）。
- Scene Lit 异步准备：未就绪的 Lit 帧返回 not_ready，不编码、不 Present、不改 capture；准备期间工作室帧照常接受；开启需要新管线组的设置时 total 增加，帧回到 not_ready，组就绪后恢复。
- 材质：分区、负 UV 与图像方向、sRGB 与线性 opacity、Mask 在四种 AA 下与公开 FP32 深度一致、Mask 在光栅和射线阴影中一致、同一几何的 Mask/Opaque 实例交换顺序与增删、法线图、打包粗糙度金属度、单面与双面发光、未用图片随几何一起退休。
- 标准材质默认消费：共享错误 Surface 在 Smooth / Scene Lit 显示品红，完整 Opaque 深度取代原 Mask 孔洞；恢复正常 Surface 后孔洞恢复。图像为 `material-default-smooth.png` / `material-default-lit.png`；资源失效、作者值与诊断的上游行为由 `editor_material_acceptance` / `project_scene_acceptance` 覆盖。
- 材质光输运：DDGI 射线命中把贴图颜色带到中性接收面；只换贴图内容就更新 DDGI；完全位于视锥上方的贴图发光面经 DDGI 照亮接收面（入口先检查发光面四角都在视锥外）；镜像变换下单面发光仍按作者朝向；被 Mask 裁掉的发光纹素不贡献光。
- Cavity：保持 FP32 深度和背景、凸凹不换号、ridge 与 valley 独立、零强度不编码 pass、半径与 resize、透视、纯线框跳过、非法参数在编码前拒绝。
- 选中：四种 AA 和多个相机位置下边线连续；DDGI 叠层后边线和深度不变；跨眼平面、近裁剪面、1e-20/1e20 尺度、镜像和 8 px 线宽下内部不铺色、边线宽度有界；显式线框模式不铺面。
- 视口显示：Flat 与 Smooth 法线、MatCap 不改场景、hidden-line 深度预通道、全部边线、线宽按物理像素、模式切换复用缓存；参考网格与轴线不写深度、共面时几何优先、透视下无斑点、空场景显示网格、奇异相机只跳过网格。

## `--scene-lit`

GPU validation，room 场景：

- 环境：没有天光、灯和发光体时完全黑，不存在隐含环境光；场景天光照亮表面且与阴影源无关；移除天光后收敛到黑，不残留历史。
- 逐项图像：四种光源各自产生几何阴影；矩形尺寸和单面背侧；HDR 发光保留各通道且不在曝光前截断；曝光、粗糙度、金属度；GTAO 不压暗直接光和自发光、只压暗间接接触；DDGI 产生可见反弹并按墙色分开染色、表面变化后更新；SSSR 在环境回退之上加屏幕反射，源离屏后保留有限回退；正交相机。
- 历史：收敛后的组合画面在相隔 8 帧的两帧间 mean ≤ 3、p95 ≤ 8；camera cut 当帧使历史失效，下一帧恢复复用；替换场景不复用另一个世界的历史。相同的 Edit 与 Play 快照收敛到同一画面：两个执行域各取 64 帧逐像素平均后比较，mean ≤ 3、p95 ≤ 8。剩余差异来自几十到上百帧内相关的估计噪声，以及新执行域的多次反弹预热亏量。
- 删灯当帧生效，不留时间鬼影；MatCap 不受材质、灯光和执行域影响；resize 使依赖尺寸的历史失效。
- 光源集合：超过 256 个局部光源和超过 4 个投影光源都进入普通帧；空间提议表有界，焦点在格内移动时不重传、移出后传空提议、回来后重建，都不重置场景域；插灯当帧可见；271 盏三面点光放进 atlas；删除全部光源当帧去掉辐射；96 盏不贡献的局部光不改变太阳的 DDGI 能量。
- 探针诊断：pending、有效零照度（青）、体积外（蓝）、实体内（红）分别标出；探针球和体积边界可见，不改拾取和 capture 深度；X-Ray 只用私有深度；年龄着色；关闭诊断立即恢复光照、不重置历史；诊断只属于 Scene Lit；非法半径在编码前拒绝。
- audit：超界光源和矩形乘积溢出在编码前拒绝并保留历史；一次 GBuffer draw 加一次选中线 draw，capture 只在 temporal AA 下多一次无抖动深度；选中的实例有橙色轮廓，相邻未选中实例没有；只有 64 位表面身份高位不同的物体不被当成同一物体：新显露的接收面当帧与重置帧一致（各通道差 ≤ 1），SSSR 立即拒绝旧的红色来源，独立重置后收敛到新的蓝色发光体；非 2 的幂尺寸的 Hi-Z、337×191 奇数尺寸的反射、小数视口移动与效果开关、单像素视口。

## `--scene-lit-temporal`

- 信号编辑：关闭自发光、等亮度换色、粗糙度跨过 SSSR 上限、改反射上限，都让旧反射及时消失、不留色差拖尾，FP32 深度逐值不变；编辑前要求反射足迹真实存在。
- 移动历史（DDGI 关闭）：面光阴影、红色反射与等亮度灰色反射在物体移动停止后及时收敛，不留长的彩色拖尾；无关物体运动作为对照。
- 时间隔离：all、no-sssr、no-ddgi、direct-only 四种配置相隔 8 帧 mean ≤ 3、p95 ≤ 8，且不重置场景历史。
- 刚体连续运动更新 AS 和探针、改变接收面光照，不重置场景域；运动中写出逐像素表面运动，停止后第一帧的运动向量与静止参考逐值相同（camera cut 参考，阈值 1e-4）。

## `--scene-lit-quality`

- 四种 AA：都保留可见几何、不出黑帧、不碰视口外 HUD；静止时 capture 深度等于公开的无抖动相机；收敛后的反射 ROI 与大面积受光 ROI 满足帧间稳定界；每种 AA 在 camera cut 当帧拒绝不兼容历史并在下一帧恢复。SMAA T2x：静止发光轮廓三帧之间与公开深度一致，两个相位互补、不闪烁。
- 编辑响应：灯位置和强度连续编辑保留全局历史并收敛到可见变化；几何运动保留场景域；亚像素相机运动不产生新场景域。收敛后的直接光逐帧完全相同（mean = p95 = 0）；有色灯光和材质编辑当帧可见，恢复后下一帧逐字节回到基线。
- 深度：有限 Reversed-Z 下远处 FP32 深度低于 .001 仍可见；最后提交的远处近共面几何不覆盖近处；相距 2 cm 的远处表面可区分；正交同一约定。
- 网格发光经 DDGI：照亮不饱和的接收面，DDGI 关闭时不照亮任何表面；等面积不等剖分能量一致；镜像非均匀实例保留世界面积和辐亮度；双面发光反绕序后能量不变；遮挡物挡住探针携带的发光，移走后恢复；删除发光几何不残留探针能量。
- DDGI 质量：移动发光体保留场景域并收敛；整墙在亮发光体下帧间 mean ≤ 3、p95 ≤ 8；墙地接缝没有暗条（p10 ≥ .95）；薄隔墙和亚像素挡板阻断光照；慢速移动不暴露分批更新的块。
- 稳定键：键为 0 的回退实例与完整 uint64 作者键（`UINT64_MAX-4`）混用不冲突，两个遮挡体的深度逐值不变，ROI 的 32 帧平均颜色各通道差 ≤ 3。
- contracts：点球光支持超出中心范围；开放薄片背面不永久禁用地面探针；反绕序和镜像保留几何分类；连续成员变化和提交重排保留表面与探针历史；无效的非 Lit 候选帧和被拒绝的模式切换不污染已接受的 Lit 历史；一条照明射线的预算测得的就是一条（另加 32 条几何射线），收敛后保持常量天空能量；空场景重复提交幂等、关闭可重复。
- 工作量：完成样本按序号去重、属于本 case；屏幕直接光不追射线；非对齐尺寸下最后一行和最后一列被照亮；零漫反射材质不做接收面查询，但覆盖诊断照样显示；每个调度到的探针恰好追 32 条几何射线加请求的照明射线；不活动的探针只追分类射线；封闭接收面后外部光不泄漏，旧表面辐射也不残留。

## `--scene-lit-stability`

D3D12 debug layer。同一 Renderer 上依次跑 DDGI 读回诊断、上一节的 DDGI 质量用例和多体积用例：

- 读回：inspection 属于请求的场景和物理像素、标识已提交的源帧、带自己的采样配置；背景和越界没有接收点；关闭、空场景、DDGI 停用不发布样本，也不留旧样本。
- 冻结对照：hold-irradiance 冻结呈现与运输 RGB，期间不消耗有效响应计数；hold-distance 冻结距离矩；恢复后呈现重新响应。
- 射线记录：所选探针的射线属于当前驻留场和射线预算，sampling.w 是探针到命中点的距离，所选光源端点距离与世界坐标一致；射线预算 1、3、127、128、255、256 都产生有限、有支撑的样本。
- 多体积：第二个体积补上第一个缺的接收面支撑；槽位优先级；共享更新预算；亚格焦点移动保留网格和历史；整格滚动只清进入的切片，负方向多轴滚动清进入的并集一次；瞬移使整个体积失效；有效的黑与缺失支撑区分开；间接增益只作用于最终合成，不重建探针；共享驻留上限在编码前原子拒绝；小缓存不把远处遮挡当成天空 miss。

## `--scene-lit-clustered`

- 解析真值 `analytic_point_plane`：点光照 roughness 1 的电介质平面，参考按平方反比余弦计算 (1−F) 加权的漫反射加 GGX 镜面；每个接收像素都在 HDR 半精度加 ±1 显示码以内，正交与透视都判。
- 灯列表：272 盏光溢出时保留全部贡献；272 盏重合光等于一盏等功率光；光源变少后不复用溢出的旧列表；支持范围外的光不进列表；球面距离和矩形保守范围都按光源表面算；单面矩形背后不发光；删除全部光源后列表和辐射当帧清空；空场景退休后重建列表。
- 矩形光真值 `analytic_rectangle_plane`：与实现无关，对矩形面积按中点规则积分精确 BRDF × cos·cos/r²，近光源像素加密采样；一个样本就是点光极限。带宽是 HDR 半精度加 ±1 显示码，再加镜面部分的 25%（LTC 逐方向近似），面光用例另加全图峰值的 0.5%。用例覆盖点光极限（正交、透视、双面背侧）、电介质和金属的面光（两种投影）、穿过接收平面的矩形。掠射背向用例的视线最大偏离法线 69°，超出了 LTC 镜面的精度，只判漫反射：底色 (1, .5, 0)、白光、电介质时，红减蓝就是红通道的漫反射，按 ±1 码、FP16 存储和半精度反推成区间，再加 2% 余量。

变异（各自单独构建、运行后撤回）：

| 变异 | 失败处 |
|---|---|
| 矩形光改回中心近似 | 面光电介质 2293 像素，最大 42 码 |
| 不做地平线裁剪 | 穿过接收平面 1370 像素，最大 193 码 |
| 查表的粗糙度轴和角度轴互换 | 点光极限正交 3709 像素 |
| LTC 逆矩阵转置 | 斜视金属 3770 像素，最大 127 码 |
| 双面光当单面 | 双面背侧 4745 像素 |
| 漫反射去掉 (1−F) | 掠射背向 692 像素，最大超出 13.8% |

## `--scene-lit-shadows`

阴影真值按遮挡体的几何独立判定每个像素该受光还是被遮挡，遮挡体按 margin 收缩后判。覆盖：

- 缓存：静止时复用全部 face，不重绘；离屏投影者产生实际阴影；改光源 RGB、表面粗糙度或光源半径（远平面不变时）不重画深度；物体首次移动后移入动态层，之后的运动不重画静态层；删除动态投影者不留幽灵阴影；Mask 透明度内容变化使遮挡失效，透明纹素不投影，恢复不透明后遮挡恢复；移动光源使两层都失效；重开世界不复用另一个场景的 atlas。
- 方向光：四级级联完整，每级在自己的遮挡体下投影；移动太阳使所有级联失效；无限远透视相机初始化四级有限级联并复用。级联拟合：最近接收面来回移动只重画动态层；接收面范围向内移动后，32 次规划后收缩一次；camera cut 后所有接收面都在级联内；新露出、级联外的接收面当帧追射线并被照亮，读数到达后级联扩张，稳定后不再追射线。
- 层级与预算：16 盏灯都保持 256 直径层级；超出前 16 的光为 128²；移动的灯在 face 预算内整盏重画，等待最久的优先，所有 tap 都驻留；停下后剩余的过期 face 按同一速率画完；新到的光每帧最多画预算内的 face，pending 的光在 ⌈faces/19⌉+8 帧内清零，期间不贡献直接光，画齐后淡入到无阴影时的精确能量；30 盏无键光不受预算，保持阴影和能量；绘制原点滞后的光保留原点所需的全部 face，没有缺失的 tap。
- 取样：掠射平面（N·L 约 0.013、0.004，低于 128 tile 的偏移比例 0.0161）不自遮挡；70° 掠射、离接收面 1 cm 的 4 cm 鳍产生正确阴影；atlas 压力下整盏放弃，放弃的光不贡献，驻留的光能量精确；点光、太阳、矩形光各贡献一次；球光内部的接收面保持缓存可见性；不投影的球光不占 face 但照样贡献。

## `--scene-lit-cost`

- 确定性直接光在编辑的第一帧就显示稳定值。
- DDGI 的 LOS 缓存：缓存后的图像与每帧重新追踪的参考 mean < .01、p95 ≤ 1，FP32 深度逐值相同；完全复用时不增加段查询；静止接收面复用全部有效段，探针照明照常更新；TAA 与 T2x 下观察到重新追踪的完成样本，无抖动模式下观察到零段查询的复用样本。生命周期覆盖相机、几何增删和移动、Mask 恢复、体积布局与滚动、开关和新场景，每个 case 都有配对的完成样本。

## `--scene-lit-sky`

期望值都由文档写明的贴图空间和旋转约定独立算出：

- 常量贴图：峰值 2^17 的贴图按 2^-2 存储，它照亮的每个表面像素与同辐亮度的均匀天空逐字节相同；背景显示该辐亮度（含 2^k 缩放），误差不超过 1 级；均匀天空的背景为黑。
- 立体角均值：只在 60° 以上为 1 的极冠贴图，均匀消费方读到 (1−sin 60°)/2，不是纹素比例 1/6，与对应均匀天空最多差 1 级。
- 背景几何：0.8° 的标记点在 yaw 0° 和 35° 下都落在期望像素 1 px 以内；纬向平滑的贴图在 −Z 后方 u 接缝两侧相邻像素最多差 2 级；单纹素棋盘格（0/2）在每像素覆盖不少于 2.5 个纹素的区域与均值最多差 2 级；同一场景把贴图置空，当帧背景全黑，渲染器释放贴图。
- 背景运动：相机每帧转 1.5°，同时以 0.5 m 半径绕原点每帧走 25°。T2x 和 TAA 下第 24 帧时，标记的亮度重心距它方向的投影不超过 1 px，能量与同 AA 模式下静止相机的参考差 5% 以内，标记外的拖尾能量不超过 2%。T2x 下背景 motion 全部有限，与按未抖动相机只做旋转重投影算出的值最多差 0.1 px。不切镜头、每帧翻转 180° 的相机，T2x 下标记不能出现在反方向的视野里。正交相机下所有背景像素的 motion 都恰为零。静止相机 TAA 下背景 16 帧的逐通道标准差最多 1 级。
- DDGI 探针 miss：五块倾斜朗伯板，三个通道各是沿 +X、+Y、+Z 的半空间天空，色调 (1, .75, .5)。逐通道辐照度比应为 色调 × (1+n·a)/2，容差 0.08 × 色调，0° 和 90° 都判；同一贴图从 0° 转到 90° 后第 33–48 帧已在容差内。
- 真实 HDRI：kloppenheim_05 在 room 场景里 DDGI 时间偏差的 p95 不超过同均值均匀天空的两倍或 1 级（实测 0.556 对 0.500）。

## `--scene-lit-benchmark`

不开验证，原生 2560×1440 room；计时采样期间不读回图像，结束后保存一张证据图。检查完成样本的合同：异步样本属于已提交的帧，各级 timestamp 有限、非负，子区间属于完成的父区间，DDGI 分类查询是全部可见性查询的子集，固定场景在同一完成样本里执行除阴影 atlas 更新外的每个计时区间。同一入口再测有无天空贴图两种情况。它输出耗时，不以耗时作为通过条件。设了 4K 贴图后 compose 中位数从 0.498 ms 变为 0.576 ms，GPU 合计从 4.04 ms 变为 4.12 ms，DDGI 主追踪不变；贴图上传帧的分项见 [Scene Lit](scene-lit.md)。

## 当前性能

以下是不同阶段的历史测量，不是最新 main（含后续相机／Runtime 集成）的性能承诺。

### P1 之前的历史基线

`atelier_editor --profile-render-performance`，Release，原生 2560×1440 最大化视口，不开验证，VSync 关；两轮交替，取两轮 p50 的均值，单位 ms。场景是 Examples 的新 Sponza（573.6 万三角形，示例相机，DDGI 16×12×14、每帧更新 672，带天空贴图），提交 de6627b2，渲染代码与 63de8635 相同。

| 情形 | GPU 合计 | gbuffer | direct | ddgi（update / gather） | ao | reflections | hdr_resolve | display |
|---|---|---|---|---|---|---|---|---|
| Scene Lit 静止 | 15.20 | 5.33 | 1.41 | 2.87（1.09 / 1.78） | 1.88 | 2.76 | 0.52 | 0.42 |

- 静止时 wall 15.44 ms，约 65 帧/秒。目标是 RX 6800 XT 上 1440p 120 帧/秒，即 8.33 ms。
- 相机环绕时 GPU 合计 23.73 ms，其中 shadow_cache 6.14 ms（级联每帧重画整个网格）、ddgi_gather 4.27 ms。
- Smooth / MatCap 每个几何批次一次 draw，与按 part 绘制的 63de8635 交替测量：wall 4.70 / 4.23 ms（按 part 时 5.01 / 4.47），没有 GPU 计时；draw 由 444 降到 2，CPU `render.encode.scene.draws` 由约 1.56 ms 降到 0.026 ms。CPU 节省大于 wall 的下降，说明这两种模式在 Sponza 上主要受 GPU 限制。Scene Lit 与 Room、Dungeon 两场景没有可分辨的变化。
- 反射比旧 Sponza 多出的约 1.86 ms 是推断，还没有归因；性能报告的每个 Scene Lit 样本带 SSSR 的 `reflection_work_items`，可用于这项归因。

### P1 历史收益与已接受的性能取舍（2026-10-25）

宿主是 Windows 上的正式编辑器 `atelier_editor --profile-render-performance`，不是独立渲染微基准；RX 6800 XT、Release、接收视口 2560×1440、GBV/VSync 关闭。Dungeon 最终四份数据在渲染工作树 `.amp/in/p1/perf/dungeon-finalclean-{p0,p1fixed}-{1,2}/render-performance.json`；顺序为新、旧、旧、新，每边两轮，每个 Lit case 预热 192 accepted 帧、240 个完成 GPU 样本，CPU/wall 为 243 个 accepted-step 记录。下表为两轮分位数的均值，单位 ms，不混合重算分位数。

| Dungeon | GPU p50（旧→新） | CPU Lit p50（旧→新） | wall p50（旧→新） | wall p95（旧→新） |
|---|---|---|---|---|
| 静止 | 7.946→7.956 | 2.370→2.610（+0.240） | 8.289→8.285 | 8.771→9.254 |
| 环绕 | 8.447→8.429 | 4.036→4.627（+0.591） | 8.751→8.708 | 13.186→14.687（+1.501） |

相机、接收尺寸与工作量一致：静止 111 次场景 draw；环绕阴影记录逐项一致，中位 271 面、662 draw、静态／动态各 4 次更新。环绕 wall p95 的旧两轮为 12.690/13.683，新两轮为 14.573/14.802，范围不交叠；静止 wall p95 轮间范围交叠。GPU 中位恢复不等于 CPU 或尾延迟无回退；+1.501 ms 约为 120 FPS 帧预算的 18%，不能宣称稳定 120 FPS，也不据这些分位数保证稳定 60 FPS。

## 未覆盖

- 只在 RX 6800 XT 上运行过；其他厂商、其他驱动和低端硬件没有验证。
- LTC 镜面在视线偏离法线约 65° 以上的精度只做了离线估计，掠射用例只判漫反射。
- 粗糙反射只用一个来源见证；主要来源不变、次要来源改变的情形没有专门用例。
- 贴图流送、大规模材质压力、透明混合、蒙皮几何没有实现，也没有验收。
- DDGI 开启时，Scene Lit 画面在两个进程之间不逐位复现。新 Sponza 在 1600×900、同一相机和设置下，第 2、16、64 帧的截图最多差 3761 个像素、最大差 2 级；再开 SSSR 与 GTAO，最多差 12976 个像素、最大差 4 级。深度逐位相同；关闭 DDGI、SSSR、GTAO、AA 与 Bloom 时画面也逐位相同。原因还没有定位。因此跨进程的 `render.compare` 只有在这些效果关闭时才能证明画面逐位一致。
- 性能只测过 room、Dungeon 和 Sponza 几个场景；`--scene-lit-benchmark` 和 profile 的耗时不是通过条件。
