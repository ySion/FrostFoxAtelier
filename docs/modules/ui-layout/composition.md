# 内容绑定与完整呈现消费

布局核心只拥有几何，不拥有文字、图片或 GPU 资源。正式生产链由 `ui::Session::prepare` 构建 `UiFrame`，宿主经 renderer 接受绘制帧后，再由 `Session::accept` 接受对应 UI 帧。控件、文字、图片与输入的当前合同见[UI 模块](../ui/README.md)，失败与候选校验见[更新协议](../ui/updates.md#候选失败和资源寿命)。

## 几何与资源责任

- `LayoutSnapshot` 独立拥有几何。需要跨发布或 Document 析构消费时显式保存快照；它不保活文字、Runtime 根、Texture 或 GPU 资源。
- 内容拥有者必须按最终节点约束准备文字。固定宽高节点可能完全跳过布局测量，绘制准备仍需取得相应文字；几何复用不等于文字资源复用。
- 内容或字体版本变化不能改写仍被旧帧引用的排版结果。仅给可变 COM 对象 AddRef 不足以固定旧画面。
- 删除缓存不能提前释放仍被帧使用的资源。最后一个拥有者释放后回收；长期保存历史帧也会保存对应资源。GPU 提交和 fence 寿命由 [RHI](../rhi/contract.md) 与渲染层负责。

## 发布边界

核心几何发布与完整呈现帧提交是两个事件。布局成功后，如果图片或绘制准备失败，composition 继续持有上一完整帧，不回退 LayoutDocument 的 publication，也不把旧几何配上新内容。固定尺寸且未触发测量的叶也必须捕获资源。

需要按图片固有尺寸测量时，由提供者读取捕获的内容版本；逻辑尺寸、宽高比和 DPI 政策属于 UI 消费方，资源侧负责内容与设备表示。

当前布局验收只保留几何快照跨 Document 析构的代表，见[验收记录](acceptance.md)。生产段落和 coverage 的关闭寿命由基础 UI 验收负责，不用验收自建的 TextFrame 或模拟编辑器代替生产消费者。
