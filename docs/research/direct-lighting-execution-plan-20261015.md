# 直接光、缓存阴影与 1440p 性能执行计划

状态：2026-10-17 主目录基础链路与精确工作复用已完成本批 GPU 端到端和地牢实测，候选尚未替换默认路径；配置与实际通过范围以[验收记录](../modules/renderer/acceptance.md#基础链路与精确工作复用2026-10-17)为准。原生 1440p、无 VSync、静止相机的默认 Lit 为 40.81 接受帧/秒，A 精确选灯＋RT 为 46.32；DI 仍约 13.04 / 10.30 ms，DDGI 降至 3.43 / 3.18 ms。B 缓存阴影已知成本和地砖自阴影暗楔尚未解决。C 默认迁移/旧实现退役与动态 90 FPS 目标均未完成。规划时主目录为 `5e5d73c8`，包含阶段集成 `1076af8d`；不回退随后进入的编辑器改动。

2026-10-16 用户调整优先级：用户反馈非 Lit 模式同样缓慢，要求暂缓光照路径优化，先排查并优化完整编辑器链路。以同地牢、同相机、原生 1440p 的 Smooth / MatCap 建立无 VSync 基线，分别记录 Application 控件、场景快照、Renderer 命令录制与 RHI 提交/Present/帧槽等待；最大化视口的结果不替代正常停靠布局。应用与编辑器、Renderer、RHI 各自修复实际热点，GPU 验收由渲染负责人串行调度。此前出现游戏竞争负载后的延期已经结束；受竞争影响的旧 FPS 继续排除，10 月 17 日的新测量及桌面后台条件单独记录。

基础链路收口后再恢复直接光优先的执行顺序。GI 阶段仍保留 DDGI 主路线，将较远 SSGI 纳入候选，随后按[统一比较条件](gi-comparison-contract-20261016.md)对照“改良 DDGI＋可靠 SSGI”与“Capsaicin 式表面探针＋世界缓存”；这项比较尚未进行。

2026-10-17 批次已落地：应用/World/UI 修复审查确认的忙重试、稀疏场景预分配、选择查询与结构同步问题；Renderer 加入无随机支持像素的重建旁路和 DDGI 精确 LOS 复用，照度本身不缓存。`direct_clustered` 与 `direct_shadow_cache` 已分离，保留 A 的 RT 对照与 B 的已知质量门槛。混合像素完整信号仍重建，没有完成 C 的全信号分离或旧 ReSTIR 退役。小场景动态图像、缓存失效、主视图剔除与有限源对照通过；地牢最大化 Smooth/MatCap 达 160.65/148.77 接受帧/秒且旧截图逐像素一致，正常停靠布局仍只有 56.81/54.09，控件与 UI 准备的 CPU 成本已交应用负责人继续归因。构建、复审、实际测量及其边界集中在[本批记录](../modules/renderer/acceptance.md#基础链路与精确工作复用2026-10-17)。

设计依据见 [Capsaicin 与阴影路线研究](capsaicin-direct-shadow-roadmap-20261015.md)。当前生产行为仍以 [Scene Lit 契约](../modules/renderer/scene-lit.md) 为准。本计划是执行顺序与验收门槛的权威位置，不将目标耗时写成已实现性能。

## 目标和保留行为

目标为 RX 6800 XT、原生 2560×1440 的正常游戏负载达到约90 FPS，整帧预算约11.11 ms。直接光连同阴影更新、采样和必要滤波，先以2–3 ms为设计预算；整帧必须另留几何、GI、AO、反射、UI和调度成本。上述是目标，不是测量结果或所有极端场景的保证。

- 主几何、材质与输出保持原生分辨率；基准使用SMAA。保持既有D32_FLOAT与深度重建精度，不以降深度精度、帧生成或未声明的超分辨率放大达标。
- 继续支持方向光、点光、矩形面光、发光网格、单个Sky Light；保持颜色、强度、范围、阴影开关和稳定身份的语义。无Sky Light时不引入隐含ambient。
- 继续支持超过256个光源；光源总数、局部重叠数量和发光三角形数量分别计量。不恢复固定四灯阴影槽或截断灯表。
- 保留非零光源半径的软阴影诉求、薄墙和Mask材质行为；近似算法的差异必须在对照中明确，不能以硬阴影替代后宣称等价提速。
- World是作者配置权威，LightFrame是渲染光源快照权威，Renderer只拥有派生列表、缓存和GPU资源。所有GPU操作沿RHI及其授权的gfx入口；需要补充低层能力时由RHI负责人处理。
- Scene Lit、MatCap与Play维持现有独立性。用户项目和当前编辑现场只读，验收使用可追溯的场景副本或既有离屏消费者。

## 执行批次

| 批次 | 产出 | 结束条件 |
|---|---|---|
| A：真实基线与精确局部光照 | 原生1440p基线；实际接收面的灯重叠统计；轻量精确分块／分簇列表；解析直接光求和 | 证明省掉选灯与重采样的收益，列表不丢光；阴影完整成本单列 |
| B：缓存阴影与软阴影 | 点光shadow atlas、稳定方向阴影、变化驱动失效、源尺寸相关软阴影 | 地牢静态与动态负载正确；暖缓存显著复用，冷缓存和失效帧成本有据可查 |
| C：完整光型、默认切换与退役 | 面光和发光网格接入同一新主链；只重建随机信号；删除被替代的全屏ReSTIR DI生产链 | 所有现有光型、身份与编辑生命周期通过；新默认端到端明显提速 |
| D：DDGI稳定与更新效率 | 针对primary采样波动和反馈更新的改进；必要时有限secondary radiance缓存 | 亮峰减少、移动／开关灯收敛更快，且GI总成本下降；无额外暗化补丁 |
| E：整帧收敛与交付 | AO、反射、全屏中间目标的成本优化；完整1440p动态验收；Astra复审 | 以完整帧时间判断90FPS目标，记录剩余瓶颈，代码与当前文档同步收口 |

A→B→C为第一项直接光里程碑。D、E属于达到整帧目标的后续批次。先完成可用的新直接光，再改变GI采样和缓存，避免无法判断亮度或性能变化的来源。

2026-10-16 实测后的执行约束：保留精确选灯的已测收益，不能为了沿用 B 的实现强制把阴影图设为默认。地牢当前每个有效接收像素最多受到 3 个局部解析源支持；该工作负载中逐灯 RT 比现有 PCSS 更便宜。先隔离 CSM 的真实几何误差，并继续 C 中“稳定贡献与随机信号分开重建”的工作，再决定各光型采用的阴影路径。10 月 17 日后测中，直接光重建仍约 6.6 ms，本轮保守旁路在真实地牢未取得显著 DI 收益；DDGI receiver gather 的静止成本已由约 8.2 降至 2.5 ms，但持续移动相机时需重新查询，其 1440p 成本另测。降低 probe update budget 不会直接消除该屏幕成本。没有据此停用软阴影、降低深度精度、删除可见性检查或改写保存场景。

### A：从现有数据建立精确直接光

1. 固定保存地牢的场景、相机、光照和效果配置；读取实际viewport/render extent确认2560×1440，不能以client尺寸代替。正常Release计时与GPU validation验收分开。已有2.82Mpx测量只作历史对照。
2. 在真实GBuffer接收面统计影响灯数P50/P95/max、超出列表容量的区域、有效屏幕覆盖；计数与完成帧sequence对应。已有实体原点统计不替代这一步。不新增常驻CPU逐像素读取或每帧同步等待。
3. 沿LightFrame构造保守局部灯列表：方向光独立处理；范围、深度区间和投影覆盖负责初步剔除。先采用简单GPU列表，不预先加入复杂法线聚类、房间门户或新场景树。由实际深度断裂和构建成本决定最小有效分簇方式。
4. 灯列表不截断。容量不足时受影响区域走完整求值退路并计数，随后调整容量；不能以top32随机proposal代替精确影响域。当前共享proposal继续服务GI等随机求解域。
5. 点光与方向光累加实际贡献，不再为这部分执行全屏reservoir时间／空间复用。保留同一强度、距离衰减和近场参数；有限尺寸光源的积分近似单独比较能量与高光，不能把取消随机端点当作严格等价。
6. 先利用现有RT可见性进行有界质量对照，分开记录列表构建、BRDF着色和阴影成本。该对照用于判断算法收益，不将每灯全像素RT设为未经预算的长期默认。

批次A只增加必要诊断。若几何提交或轻量分块比更复杂cluster方案更合算，采用实测更好的实现，仍保持同一直接光入口。

### B：缓存点光与方向阴影

2026-10-16 实施范围：主目录已有保守点光 cube-face 驻留、四级 CSM、静态/动态 D32 atlas、变化驱动失效与压力分批。cached point、cached sun、endpoint RT 分别编译，避免把 PCSS 与 RayQuery 塞进同一 shader。接收平面按实际 texel 中心修正；固定 DXC 的矩阵标量索引问题已用经过 DXIL/GPU 读回核对的 `mul` 提取消除。独立 Astra 复审补齐了合法无限远相机与分配撤销记录，未扩张低层 Frame 限制。小 ROI 图像与计数已取得通过证据；最终配置与具体范围见[验收记录](../modules/renderer/acceptance.md#精确局部光照与缓存阴影候选2026-10-16)。这些结果不证明地牢性能或所有有限源遮挡等价，默认迁移仍须满足后续质量、时间稳定与整帧成本门槛。

- 使用显式内存预算和分辨率层级管理D32阴影图。根据接收面的投影需求分配点光方向／图块；不为所有灯固定分配六张大图并逐帧重画。太阳使用稳定方向阴影／级联，处理投影对齐、偏置、级联过渡及移动太阳。
- shadow caster集合从完整场景及光源影响域得到；主相机外的物体仍可能投影到可见表面，不能复用主视图可见集代替。
- 光源颜色或强度变化直接影响着色，纯可见性深度可复用。灯的位置、方向、范围或投影相关参数变化按实际依赖失效。
- 物体移动、增删、mesh替换、Mask与遮挡材质变化覆盖旧／新bounds。静态几何与变化频繁的投影者分开缓存，使角色运动不会强制重绘整个静态场景；分类本身不豁免变换失效。
- 先建立稳定、有限采样成本的接触硬化／软阴影方案；PCSS或必要RT的选择要包含完整过滤与时间稳定成本。固定PCF可作为对照，不作为非零source radius的最终等价替代。
- 明确首次分配、camera cut、atlas压力、灯删除和重新创建的退路。无效缓存不能作为有效阴影；缓存不足不能自动当作无遮挡，也不能无界地给全部灯触发RT兜底。
- 在整纹理状态约束下组织“阴影写入批次→着色读取批次”；不在同一draw／dispatch同时读写同一atlas的不同区域。静态／动态合成所需资源由明确owner持有并按完成帧退休。

批次B必须交付shadow请求量、命中率、重绘图块／方向、重绘投影者、内存和完整GPU耗时。完整VSM只有在整图重绘或分辨率浪费明显主导成本时才进入下一项设计，不与此批并行搭建。

### C：完整光型与旧路径退役

- 矩形面光优先验证LTC等确定性面积积分。无遮挡积分与遮挡积分分开论证；把独立平均visibility乘回无遮挡结果不是自动成立的等价变换。保留双面、源面积、方向和材质响应。
- 发光网格保留其直接贡献和材质采样。沿同一源身份与采样基础提供面向发光源的RIS／分层采样；不将全部发光三角形放进逐像素全量循环，也不继续让解析点光承担发光采样成本。
- 只对确有随机噪声的发光／软阴影信号重建，按活跃区域调度；稳定解析直接光不再经过原有全幅radiance denoiser。GI与反射保留各自历史，避免一个局部信号变化重置所有照明。
- 核对直接、间接、表面发光和反射的计能边界；不能因新路径拆分漏算或重复贡献。
- 完整端到端通过后切换默认，删除原屏幕ReSTIR DI专属reservoir、管线、历史、统计、UI开关及无效文档。仍被GI使用的RIS、共享光源求值、空间proposal和身份合同保留。旧方案只由Git历史和固定基线证据保存，不以永久兼容模式留在生产渲染链。
- `direct_candidates`目前也驱动DDGI。退役屏幕ReSTIR不能直接删掉这个共享作者字段；若更名或拆分，先与World／编辑器负责人确认单一新语义、旧Scene读取与新Scene写出规则，不长期双写。

批次C的出口是可打开原地牢和发光板场景的完整新默认，而不是只在关闭发光物体、面光或软阴影时较快的特殊模式。

2026-10-16 Astra 前置核对：优先让零尺寸 point/sun 的确定性贡献脱离重建，有限源先沿原 `sample_uv` 映射验证确定性求积，不能仅凭稳定无噪声判定正确。现有球光是球面端点贡献均值，包含逐端点 range cutoff 和距离下限；当前太阳是切平面圆盘映射，并非均匀球冠测度。[Epic 代表点方法](https://cdn2.unrealengine.com/Resources/files/2013SiggraphPresentationsNotes-26915738.pdf)可作为近似候选，需要高光能量补偿。现成 [LTC GGX fitter](https://github.com/selfshadow/ltc_code/blob/master/fit/brdf_ggx.h) 使用 correlated Smith，本项目采用 separable Smith，且漫反射包含方向相关 Fresnel；标准 [LTC 积分](https://eheitzresearch.wordpress.com/415-2/)也不包含本项目的距离权重。接入必须匹配当前模型拟合/校验，不能借替换求解器暗改全局材质语义。验证先分开无阴影积分与完整端点遮挡积分，再检查低粗糙度金属、掠射、球内/近源、范围边缘和薄遮挡；PCSS scalar visibility 乘积分仍明确属于近似，不声称一般等于 `E[fV]`。

### D：DDGI稳定与更新效率

本批先完成A路线的合理布点、采样与可靠较远SSGI，再与B路线作同预算对照。1.2米只作为旧版SSGI基线，候选评估4／8／16米；不直接扩大当前线性追踪步长。输入／输出、计能、全部GI成本、相机移动、屏幕外发光体、开关灯和薄墙的具体比较要求集中在[GI比较条件](gi-comparison-contract-20261016.md)。Capsaicin式方案不预设为继任者，胜负由实际结果决定。

1. 复用现有ProbeInspection区分primary方向偶遇高radiance、secondary选灯波动和历史响应，按同一场景记录亮峰、收敛时间与总GI耗时。继续使用线性transport作为能量权威。
2. 优先验证方向分层／重要性引导，保留完整方向支持，并修改相应PDF和卷积权重。不能只改随机方向而沿用均匀采样权重。
3. 让已知灯光与几何变化驱动局部有效更新；光照强度变化应快速响应，孤立随机亮峰不触发全局加速。不以永久降低反馈能量或全局夹亮替代采样改进。
4. 只有相同secondary表面的重复着色显著时，增加有内存上限、表面身份／法向约束和明确失效代次的radiance cache。复用现有LightFrame与Geometry权威，不另建灯光或材质世界。
5. DDGI二次命中和屏幕外查询继续使用完整RT场景。屏幕需求生成的shadow资源不保证驻留，不能直接替代其visibility。世界probe转screen probes属于另一个经过测量决定的演进，不直接叠加整套Capsaicin。

灯光收敛同时按毫秒和有效观测次数衡量，避免帧率变化让“多少帧收敛”的比较失真。相同质量下减少成本；相同预算下减少亮峰／响应延迟，两种结果分开报告。

### E：整帧收敛

- 排查Scene Lit中仍按整窗口处理／分配的中间资源，按实际viewport需求减少无效工作；保持拾取、运动矢量、AA、debug显示和UI坐标一致。
- 优化AO和反射的活动区域、无效工作剔除、采样与重建。低频照明可尝试降低求解频率／分辨率，但必须明确记录并验证边缘、细薄几何和运动行为；主几何与输出仍为原生1440p。
- 合并有实际收益的全屏读写，保留清晰的依赖、图像格式和材质调制边界；不为本次引入通用RDG、多队列或另一个资源管理器。
- 正常Release记录GPU阶段、CPU帧、实际呈现间隔与P50/P95/P99，不把异步重叠时间重复求和，不用validation耗时当产品表现。VSync／限帧和后台负载明确记录。
- 普通漫游、角色／门运动和灯光更新均属于90FPS目标负载；冷启动与大规模失效帧另外报告。只有静态暖缓存较快不算完成。

| Renderer（本线程） | 精确灯列表、直接光积分、阴影缓存策略与失效、GI、pass工作统计、端到端图像和性能证据 |

RHI负责人已基于`5e5d73c8`完成核对，并以 `cb90c10b` 实现及独立验收以下两项能力；本轮以补丁接入主目录工作区。D32创建及DSV/SRV、depth-only绘制、comparison sampler、tile viewport/scissor、多实例／multi-draw indirect、完成帧readback与延迟退休原已有入口。

1. **现有clear入口的矩形列表扩展**：当前scissor不会限制整图clear；新接口在指定mip/slice内仅清合法矩形，空列表无操作，非法范围在编码前拒绝，保留范围外内容。沿gfx处理状态与编码，不在Renderer调用原生D3D12。现有depth-only覆盖绘制虽能清tile，但不把它与原生矩形clear长期维护成两条生产路径。
2. **现有DrawState的固定功能depth bias**：constant、slope-scaled、clamp进入现有PSO状态与缓存键，默认零；不暴露原生PSO，也不为每个灯随意创建独立状态变体。

现有indirect批次共享viewport/scissor/PSO，命令数量由CPU提供；不能假设每条命令自动切换灯的viewport，也不为本批提前增加GPU count-buffer入口。比较采样器clamp作用于整张纹理，tile边界由Renderer的保护边或坐标约束保证。图块逻辑身份与有效性仍由Renderer负责，物理资源退休由gfx负责。

## 必要验收与完成标准

只使用现有正式消费者和必要真实场景端到端验收，不建立单元测试／mock或通用基准工程。按阶段覆盖：

- 保存地牢：固定相机、正常移动、暖缓存、首次进入／camera cut。
- 动态：角色、门、移动灯、调色／改强度、开关灯；观察冷／暖缓存和尾延迟。
- 画质：薄墙、小窗、Mask遮挡、阴影接触处、跨点光方向接缝、面光、强发光体与粗糙反射。
- 容量：超过256灯、局部密集灯、灯列表overflow、atlas压力；不漏光、不静默取消阴影。
- 生命周期：灯删建／重排、mesh／材质替换、重复相同设置、场景重开、viewport resize、Lit↔MatCap和Play；无陈旧资源、错误历史或重复更新。

Dev与Release验证必要行为和GPU合法性，性能仅用正常Release。GPU验收短批运行，在首个设备／验证错误出现时停止；不覆盖正在运行的Editor二进制，不改变用户保存现场。

最终交付包含：新默认路径、已退役代码清单、当前模块文档、同条件前后计时与图像证据、Astra复审结论。若尚未达到90FPS，报告真实瓶颈与剩余成本，不把局部pass达标写成整帧达标。提交／推送遵循用户对该批的实际授权，本计划本身不触发它们。
