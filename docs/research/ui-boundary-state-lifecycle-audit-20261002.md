日期：2026-10-02。基线：`c626817`，范围为应用分支本轮未提交的 UI 改动及相邻生产调用链。

## 审查范围

五位 GPT-6.1-sol 专家分别检查几何／需求、输入状态、原生生命周期、规范／旧逻辑，以及端到端覆盖。重点是菜单、停靠、参数编辑、SS、滚动、接受帧和 Windows 消息归属。

几何轴未确认新的布局或命中缺陷；规范轴确认了过期现状描述及冗余样式。以下四项状态／生命周期问题已完成修复。

## 修复

| 问题 | 触发与原行为 | 统一修复 |
| --- | --- | --- |
| 文本焦点返回时缺少输入绑定 | 文本框 → F10 → Esc，焦点编号恢复，Edit/原生输入绑定未立即恢复 | `Session::focus` 对文本字段立即建立输入上下文；相同焦点保留草稿、选择和组合状态，数字恢复被动模式 |
| 空焦点无法恢复 | 初始无焦点 → 打开菜单 → 关闭，`focus(0)` 被忽略，Enter 可重新打开旧菜单 | `focus(0)` 明确清空；无效、禁用或过期非零目标仍被拒绝 |
| 终止键状态跨交互遗留 | 文本 Enter 按下后菜单接管，释放在菜单消费，主会话残留终止键并吞掉后续首次 Enter | 既有取消入口统一清除按键状态；当前 Esc 的重复抑制仍在取消后建立 |
| 弹窗可能消费线程退出 | 菜单打开 → 投递 WM_QUIT → 菜单 capture 自行泵消息，主窗口看不到退出 | `Window::poll` 保持唯一入口：主窗泵线程消息，弹窗只消费自己的已排队记录及回调错误 |

这些修改没有另建焦点、菜单、编辑事务或窗口消息入口。不同焦点的合法提交／非法回滚语义保留；同一焦点不再无故提交或重建编辑上下文。

## 清理与取舍

- 删除没有类生产者的编辑器 `danger` 悬停规则。
- 删除与通用字段完全相同的 `.parameter-field`、`.object-name` padding 规则，保留语义类。
- 删除失焦路径中已由统一取消入口负责的重复终止键清理。
- 修正文档的 stable／overlay 滚动槽及菜单灰／橙状态描述；单行字段最低高度仍为 23 DIP，24 DIP 是数值字段最小宽度。
- 保留实际被消费的共享 popup 协议、参数页签 `joined` 和历史验收记录。PopupHost 继续负责显示器约束和原生窗口定尺寸；未为冷端测量增加另一套入口。
