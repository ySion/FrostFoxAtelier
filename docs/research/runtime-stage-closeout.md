## 测量结论与结构判断

数值、统计口径、机器和规模详见[测量报告](runtime-stage-measurements.md)。本轮是同线程的短时微型负载基线，不作为真实游戏吞吐、长时保留内存或 P99 承诺。

- 公共同步标量路径的 20000 次调用，采样未观察到新增堆分配。
- 1024 个挂起的纯标量协程约增加 1.19 MiB 活跃分配；对象协程约增加 1.27 MiB。三个模型释放所有任务拥有者并完成 GC 后，活跃分配及根/对象计数回到基线。采样前强制收集分配器，不能据此推断未干预的进程内存峰值。
- 最后旧代码租约释放在调用线程承担退休工作，本轮中位值 67.3 微秒、七批最大值 96.2 微秒。发布计时由旧租约保活，未将这部分工作混入发布。
- 根槽扫描成本确实随历史槽位高水位增长；一个活根经过 1024 个额外历史根后，根阶段为 1026 个工作单位。当前扫描仍受既有分步预算控制，后续优化以消费者规模和预算为依据。

本阶段没有遗留已确认但未修复的正确性或模块归属问题。多处分配、历史根槽扫描和同步代码退休属于已量化成本；尚没有真实业务预算证明需要以池化、根表重构或异步退休增加结构。后续若触及预算，应使用同一入口和工作负载对照验证。

## 连续运行补充验收

入口为 [session.cpp](../../acceptance/source/session.cpp)，直接并入现有 `source_acceptance` 和总验收；没有第二套运行时入口或独立测试框架。所有检查使用 Release 也生效的显式条件。独立的 `atelier_source_measure` 专项计时目标保持原有行为。

每个对象模型复用一个 Runtime 和一个 Program，先预热 4 轮，再采样 32 轮。每轮 32 个宿主 tick，每 tick 创建 8 个任务，每 8 tick 发布一个兼容版本。源码任务创建持有对象，跨 2～12 个 yield 后返回；部分在 ready 或 suspended 状态取消，其他任务校验创建时的版本结果。宿主交错推进每步最多 16 个工作单位的 GC。tick 不等待真实时钟，不代表按固定帧率运行。

每轮排尽任务及完整 GC 后，只剩宿主接收者的一个对象和一个根，字段累计值须等于已校验的完成数。随后集中释放四个旧版本的最后租约，逐个确认代码页回到 `MEM_FREE`、展开条目撤销，当前版本仍可用。采样始终处于相同的资源状态，Runtime 没有在轮次之间重建。最后另加入 32 个 ready/suspended 任务，关闭入口并取消，确认最终对象、根、待回收对象和本版本代码均释放。

### 工作负载与检查结果

每个模型的固定总量（含预热，不含最后 32 个关停任务）：

- 1152 个创建任务的 tick，9216 个任务；6451 个完成、1152 个 ready 取消、1613 个 suspended 取消。
- 3686 个完成任务使用旧版本代码；144 次兼容更新及 144 个旧编译单元退休。

### 观测口径

资源采样先在计时区间外执行 `mi_collect(true)`，再读取共享 mimalloc 活跃块统计和进程 PrivateUsage。内存基线取最后一个预热轮次；检查允许最多 64 KiB 的活跃块增量，以捕获该有界规模中的累计保留，实际观察为零。此容差不是生产内存预算，也不能证明任意微小泄漏或长期无泄漏。

集中退休时间包含释放四个最后租约；tick 时间包含任务创建、恢复/取消、结果核验及一个宿主 GC 步，不含编译、checkpoint 强制收集或集中退休。两者仅记录观察值，不用耗时阈值使正常验收依赖机器速度。最大值是本次样本最大值，不是 P99；进程内存快照不能当作未干预的内存峰值。

这是有限轮次、几秒到十几秒的组合运行，用来检查反复更新与任务清理的闭环；长时间真实业务运行仍由后续消费者验证。本阶段没有新增阻塞项。
