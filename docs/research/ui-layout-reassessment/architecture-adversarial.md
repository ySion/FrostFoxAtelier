# 架构对抗评估

本评估不审查代码 diff，不替主席选型。`README.md「共用问题」`及 `probe-plan.md §1` 已明确允许算法组合、区分声明与计算；这些原则成立。以下针对可能由候选结论、筛除措辞或不完整 probe 合同产生的过强推断。**事实**来自报告及直接主源，**推断**是设计判断，全部验证输入均**待执行**；本轮未运行构建、测试、格式化或计时。

## 1. 单一权威不等于单棵树，也不要求全能 solver

**质疑位置：**`native-alternatives.md「结论与证据边界」`、`probe-plan.md §5`，以及将 `yoga.md §8` 的“Flex 子域”理解为整套方案只能承担简单 UI。

**反论据〔事实〕：**Yoga 明确允许叶节点委托外部布局；Taffy 同时提供自有树与宿主树接口。两者都不要求整个产品只能使用一种算法。[Y][T] **风险〔推断〕：**把业务树、派生布局树、渲染树的并存视为双权威，会错误排除镜像树，并过早支付零拷贝适配成本。真正的问题是同一输入或矩形有多个独立写入者、双向反馈及不同步的身份。

**修正：**评价完整候选组合，明确每份状态的唯一可变所有者；允许单向、版本化布局投影，补充算法须在 probe 内实际交付。**反例：**同批移动子树、删除父节点并复用存储槽，比较增量与重建结果；再将外部表单装进固定尺寸 Yoga 叶。即使 measure 未调用，内部 arrange 仍须读取最终盒执行。成功反驳“只能全能 solver”；失配则反驳“组合天然正确”。

## 2. P1 需要共享轨道合同，不是 CSS Grid 门票

**质疑位置：**`taffy.md §3、§7/1`、`native-alternatives.md §七/P1`、`probe-plan.md P1/P4`。现有 Taffy 报告对 subgrid 的否决条件已有前提，不应在汇总时删掉这些前提。

**反论据〔事实〕：**QFormLayout 用专用两列表单规则提供最宽标签对齐与行换行，无须要求产品实现 CSS Grid。[Q] **风险〔推断〕：**“平铺必破坏组件边界”“向各行写宽度就是手工同步”过宽；保持业务身份的布局投影、统一轨道拥有者的批量写入都可能合法。但“虚拟化以后自然列宽免费”同样不成立：未读取的离屏内容不能决定精确最大值。

**修正：**先规定共享范围、折叠项/离屏项是否参与、宽度是精确值还是估计值；区分应用逐行协调与适配器统一投影。**反例：**2,000 行分三组，第 1,500 行最长，两层包装及跨列错误提示；面板 480→220，滚动、删除最长项、折叠组、替换字体。选择全数据精确语义时，首屏就须体现离屏最大值；列宽改变须更新相关行高及 extent。Grid 和专用容器接受同一判据，不能各挑容易的一半通过。

## 3. 自定义布局不能成为无限回调逃生门

**质疑位置：**`probe-plan.md P5`、`industry-editor-ui.md §7`、`industry-game-ui.md §6`。

**反论据〔事实〕：**Flutter 的 `parentUsesSize` 显式表达父对子尺寸的依赖；其 MultiChildLayoutDelegate 又明确不允许自身尺寸取决于孩子布局结果。[F][D] **风险〔推断〕：**一个任意 measure/arrange 回调并不自动覆盖自然尺寸、height-for-width、共享轨道及虚拟视口；允许跨子树读取和反复写约束，会重新引入循环协商与缓存失效难题。反过来，有界的表单、split、时间轴算法也不等于重造浏览器。

**修正：**先用两类真实容器检验测量约束、尺寸依赖和最终排列的表达，不先冻结万能接口；不能把 intrinsic 查询、受限宽度测量和最终 arrange 混成同一动作。**反例：**一组固定外框、一组随子内容增高；嵌套换行文本和自动滚动条，并加入“宽度小于 200 返回 220，否则返回 180”的反馈。应按明确策略拒绝或终止循环，不能凭“两遍”宣称收敛；正常组的 warm/fresh 几何须一致。

## 4. P4/P6 必须统一发布与恢复责任，而非只统一回调形状

**质疑位置：**`yoga.md §4「失败通道」`、`taffy.md §6`、`clay.md §3—4`、`probe-plan.md P4/P6`。

**风险〔推断〕：**“上层负责失败/虚拟化”尚不是可执行合同。只丢弃本次输出，不保证候选内部被写过的结果、缓存和 dirty 状态已恢复；保留旧矩形却配上新身份映射，也不是保留旧成功状态。

**修正〔设计建议〕：**可统一同版本测量的幂等性、内容/字体/provider/约束版本、重入策略和成功发布点，不必统一成一个全局脏位。文本提供者报告失败；适配器负责中止或隔离、清理受污染缓存；发布者不增加成功 revision。虚拟化拥有行高索引、估计/实测 extent 与滚动锚点，轨道拥有者向它传播有效列宽变化。失败不得伪装成合法零尺寸，框架也不能悄悄忽略回调中的树修改。

**反例〔待测〕：**成功帧后保持 fontId 不变更新字体，第三次测量报错并尝试删除节点；恢复后复用该存储槽，再收窄列宽并跳到末行。核对错误可见、无半发布、旧结果身份有效、失败未污染重试，以及行高/extent 与冷算一致。无论哪种 solver，缺一项都不能把责任推给未来控件层。

## 5. 即时声明不强制每帧求解，GPU 寿命也不强制全量布局快照

**质疑位置：**`clay.md §2、§7` 与 `probe-plan.md §1、P6`。原文已区分这些概念，应防止最终筛选再次合并。

**反论据〔事实〕：**Dear ImGui 对其范式的说明明确不排斥持久数据，也不要求持续或全量刷新；Qt Quick 则让独立渲染结构在同步后自行消费。[I][G] **风险〔推断〕：**既不能由“即时式”推导必败，也不能把跳过 Clay 调用说成免费缓存：交互、动画、滚动和内容变化仍需调度。反之，渲染命令携带的外部资源寿命，不应自动扩张为所有纯几何结果都必须拥有文字、纹理或等待 GPU。

**修正：**分别定义布局结果租期/revision、CPU 消费和渲染提交包的资源寿命；稳定几何存储、局部发布、拥有式快照均可对照。**反例：**静态后只改 hover 颜色，再滚动、重排、删除文字源；让渲染消费者滞后两帧。既要避免漏更新，也须证明旧提交包不读失效资源，而新布局无须为无关 GPU 资源阻塞。命令浅复制和每帧全树深复制都不能预先获判合理。

## 6. 原生候选须按接入路径重开，不能沿用旧版缺口

**质疑位置：**`native-alternatives.md §四、§六` 的旧版筛除依据；以原作者当前版补核修正为准。

**事实：**固定 `v1.17.1` changelog 明载：1.15 支持运行时 row/col/span 与 Grid `if/for`；1.16 的 C++ ListView 改用与 Rust 共享、仅实例化可见项的实现。[S] 这些撤销旧排除理由，但不是复杂变高树表已通过验证。

**修正〔推断〕：**分开评价“裸 solver/SDK 抽取”与“完整 toolkit 拥有一个 UI 子树”。private 接口、运行时耦合及实际发行许可仍须按所选方案回答，不能反推动态 Grid 不可用。完整框架最强反论据是它可能一并承担文本、依赖与视图机制；最强反对理由则是这些所有权是否与宿主真实冲突。

**反例：**用补核版本的公开 C++ 路径承载同一 P1/P4，动态增删单元格、语言切换、变高滚动并统计实例数；同时验证嵌入子树的坐标、输入与覆盖。若必须侵入 private solver 才完成，否定该接法；若公开整体路径成立，应计入其全部收益和成本，而非永久排除库名。

## 可先确定与验证优先级

**可先确定：**每项状态单一写入权威；版本及失败显式；布局与渲染寿命分开；组合方案必须交付真实补充机制；不把完整浏览器兼容当门槛。

**优先顺序：**① P1 共享范围与 P6 失败恢复；② P4 变高虚拟化、离屏信息和 P5 尺寸依赖；③ 候选真实接入、消费寿命及端到端测量。镜像树还是自有存储、单算法还是组合、快照形式及最终候选均等待这些结果。**没有本机测量，不给性能赢家；本评估不冻结生产架构。**
