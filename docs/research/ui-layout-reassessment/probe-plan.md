# 真实路径验证方案

状态：原始验证设计，**不是通过清单**。本轮已实现部分的运行、性能样本与真实失败见 [验证结果](validation-results.md)；未实现的基线/逐glyph、完整控件、精确分配计数等仍不得冒称已证。

## 1. 不先把所有候选压成相同实现

先分两类：

- **共同语义路径**：明确等价的 stack/flex、固定尺寸、自然尺寸与文本回流；几何与失败行为对齐后比较开销。
- **产品任务路径**：Inspector 共享列宽、复杂表格、虚拟化、overlay 等；允许候选使用其自然机制，但必须把补充的容器算法、同步、缓存和输出构造算进成本。不能用“原生不支持”直接淘汰可合理组合的方案，也不能把组合实现的成本藏掉。

声明方式（立即式/保留式）和布局计算方式不是一回事。每种候选分别提供最自然的冷启动、静态帧和动态帧路径；禁止强迫某候选每帧重建而允许另一候选跳过全部工作。若跳过依赖自有缓存，须说明缓存拥有者、键和失效条件。

## 2. 先做能淘汰方案的场景

### P1：共享列宽 Inspector + 宽度依赖文本

- 真实内容：英文/中文标签、不同字号的编辑值、可展开组、两行校验说明；使用同一个真实文字测量提供者。
- 布局语义先固定：标签列宽由本组标签的自然宽度共同决定，并受明确最小/最大限制；编辑器列占剩余空间；行高由实际宽度下的内容高度决定。
- 执行动作：增加最长标签、删除最长标签、仅改变提示文本、收窄面板、展开嵌套组。
- 观察：所有行共享同一列边界；文本重排正确；无反复振荡；warm 与 fresh 一致；记录重复测量和重复布局次数。
- 允许实现：单个 grid/shared-track、专门的表单容器，或有界的测量后布置；不要求必须实现完整 CSS Grid/subgrid。
- 否决点：应用代码必须逐行协调最终宽度、无界迭代、同一状态有多个独立可变权威，或把失败测量当合法零尺寸。统一轨道拥有者向各行批量投影是允许的；派生布局树本身不是双权威。
- 共享范围、折叠项是否参与、离屏项采用精确全局宽度还是可见项估计必须作为显式场景参数。两种政策分别比较，不用近似方案冒充全局精确，也不把全局信息获取成本只罚给某一候选。

### P2：HUD、覆盖与尺寸变化

- 逻辑 viewport 改变，四角 HUD、中央叠层、带图标的文本条、锚定在布局节点上的 popup 同时存在。
- 检查不同父坐标和外部 viewport 下的定位；纯像素输出不污染逻辑几何。
- 不是 renderer 验收，也不借此定义全部命中测试/裁剪政策。

### P3：物品格与自适应换行

- 固定大小格子、填充轨道、gap、最小格宽和不足一行的尾部组合；面板宽度跨越换行阈值。
- 分开比较“等宽重复格”和“内容驱动共享轨道”：二者不能用同一个简化样例冒充。
- 明确实际需要的语义；不把浏览器的全部隐式轨道规则引入首版。

### P4：大型树表与虚拟化

- 逻辑数据项与已实例化布局节点分别统计；实验可采用 50k 项、几十至数百个可见实例，但这不是产品规模承诺。
- 固定行高与真实文字形成的可变行高分开；包含滚动、展开、上方行高度变化、滚动锚点保持。
- 检查 viewport extent 与 content extent、复用 ID/内容版本、越界索引、可见区外变化对估计高度的影响。
- 首先验证 solver 能否与上层虚拟化协作；不要求 solver 自带完整列表控件。
- 与 P1 联合执行：离屏唯一最长标签改变或被删除后，统一更新列宽、相关行高和 extent；记录全数据扫描或索引维护成本。横向滚动裁掉某一列不得意外改变同一行的高度。

### P5：自定义容器与失效隔离

- 用专门 split 容器/时间轴或可变行高容器验证自定义测量与布置，而非为每种控件增加通用 solver 属性。
- 一个容器尺寸被固定时，其内部文本变更不应无理由导致所有不相干 sibling 重新测量；父宽度改变时又不能错误复用旧高度。
- 记录传播范围、实际访问节点数（可测时）及测量次数；不以 dirty 标志数量代替执行量。
- 分别验证固定外框容器和由子内容决定高度的容器；区分 intrinsic 查询、有限宽度测量、最终 arrange 和父对子尺寸的依赖。加入宽度在 180/220 间反馈的反例，按明确策略拒绝或终止，不用“两遍”宣称一般收敛。

### P6：失败、寿命和边界

- 真实内容键缺失、测量提供者报告失败、测量期间尝试修改布局、过深树、容量扩张/耗尽、非有限数值。
- 先为候选定义失败/恢复合同，再看能否真实实现；旧合同是输入，不是强制照抄。
- 几何结果需要的寿命先由消费模型决定。比较全量拥有快照、稳定结果存储+revision、分块/局部发布等实际选择，不预设每帧完整复制永远合理。
- 最小失败验证：成功帧后第三次测量失败且尝试删除节点；不发布新成功 revision，旧结果及其身份映射仍保持原版本。重试前验证受污染缓存已清理或重建；无法安全恢复的实例显式失效，不能将丢弃输出等同恢复成功。
- 当帧消费与落后两帧消费分组；为各候选提供等价的租期/资源有效性，记录复制字节、峰值存储和等待。布局结果、CPU 绘制包与 GPU 资源寿命分别定义，不一概要求全量深复制。

## 3. 计时与公平性

### 分项与端到端同时记录

记录一次完整布局更新的墙钟总时间；另外记录：声明/编辑、跨语言及节点同步、文字测量、solver、结果构造/复制与消费。

测量回调通常嵌在 solver 内：分项应明确 inclusive/exclusive，不能把 inclusive solver 与其子调用测量时间相加，造成双重计数。公开 solver-only 数字时同时公开端到端数字。
跨语言布局调用包含回到 C++ 的测量时段。采用嵌套计时与互斥 self time，单列双向调用数和输入/输出字节；不把完整 FFI 时长再加到已包含它的 solver 上。

### 工作负载状态

1. 建树、首次布局、结果消费与释放的冷路径。
2. 相同树、约束和内容版本的静态帧。
3. 修改单叶、少量分散叶、同一小子树。
4. 修改根/局部祖先宽度触发真实文字回流。
5. 重排、增删、展开折叠与节点复用。
6. 大部分可见内容均变更。

规模使用若干公开分档，分别记录逻辑数据项、实际节点、深度、可见项、文本长度、变更项。相同语义必须比较相同工作；不能把一个候选的 50k 逻辑项与另一个候选的 50k 实例节点直接横比。
对 Clay 额外记录配置容量 C、floating roots R、动态文本字节 B、词数 W 与命令数；对各候选运行相同 overlay 产品任务，不仅为某个算法制造人造最坏输入。solver 缓存与文本提供者缓存的冷热状态分开，测量回调次数、真正 shaping 次数和处理字节同时记录。

### 构建和测量约束

- Windows x64、本仓锁定的 C++ 工具链与正式开发/发布配置；记录精确依赖 commit、编译选项及二进制来源。
- 如果引入 Rust，先在隔离实验中固定 Rust/target/CRT/panic 策略；未获集成确认不升级全仓工具链、不写正式依赖锁。
- 同一真实文本提供者、字体文件或字体身份、locale、测量模式与精度政策；真实测量缓存状态显式记录。
- 同一字体提供者不代表相同排版工作。先核对行边界、baseline 和内容范围，再比较词段测量与整段受约束测量；无空格中文、长 URL、相同字体 ID 下更新字体版本是共同反例。空回调只作跨界成本诊断，不用于产品性能排名。
- 正确性在开发/发布都检查；只用发布配置作主要性能对照，所有检查不依赖会被 NDEBUG 删除的断言。
- 串行执行性能样本，避免并行席位编译/跑负载污染测量。记录预热、重复次数、原始样本、median/p95/p99、分配次数/字节/峰值（能可靠计数时）。禁止仅凭一次进程总时长排名。
- 用 checksum 或真实结果消费避免优化移除；检查在计时外还是计时内需统一且写明。
- 不设未经用户确认的“1ms 即合格”等阈值。先拿到覆盖真实表达能力的相对成本，再讨论产品预算和代价取舍。

## 4. 跨语言专项（若 Taffy 进入验证）

至少比较一种简单、责任清楚的所有权方案：Rust 拥有 TaffyTree，C++ 提交批量变更并取得约定寿命的结果。不能尚未证明需求就实现逐节点虚调用/FFI 自有树桥。

记录 C++→Rust 批次数、Rust→C++ 测量次数、跨边界复制量。异常不得跨 C ABI；panic/分配失败与内容错误分别定义。若低层 traits + 自有树有真实收益，再增加第二条对照，而非一开始造通用桥接框架。

## 5. 候选进入与退出门槛

进入真实对照：可固定源码、许可可接受、能定义清楚的输入/输出/寿命合同，并能跑 P1、P2 与至少一项关键产品场景。

退出或暂缓：关键场景无法合理表达；为适配制造多份可变权威；错误无可靠隔离；依赖接入成本明显超过产品收益。性能尚未测量只能写“未知”，不能据此淘汰。

阶段产物：真实 probe 源码与构建入口、精确 pins、原始运行输出、行为对照矩阵、开销分项及反例。只有这些结果齐备，才冻结生产 Interface 与正式依赖。

## 6. 为什么不复用上游排行榜

- Taffy 历史 README 的 Yoga 对照明确在 M1 Pro 上进行，只统计 layout、不包括树创建，Yoga 经 Rust bindings 调用，比较的是两个具体旧 commit。[固定 README](https://github.com/DioxusLabs/taffy/blob/dc9862a93be77bb2af8f5b27f6efe6304f3126e1/README.md)
- 检索到的 Yoga `YGBenchmark.c` 示例在计时块内创建树、计算、释放；其计时范围不能与前者直接拼成当前平台排名。[源码](https://github.com/facebook/yoga/blob/master/benchmark/YGBenchmark.c)

这些是第一手测试方法证据，不是本项目性能结果。Yoga 链接为可变分支，只用于说明已观察到的计时结构；任何正式复现实验均必须重新固定 commit。
