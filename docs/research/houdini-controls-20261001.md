# 从 Houdini 参数控件改进编辑器

日期：2026-10-01。状态：第一、二步基础控件已实现并完成阶段验收、双路 review 与文档收口；后续浮层、面板与停靠仍为建议。

本仓库观察基线：`9ad772ee9069a72ba90e535f598864f7565ea2c5`。已有 UI/SS 能力以 [UI 模块文档](../modules/ui/README.md) 和 [样式表文档](../modules/ui/style-sheets.md) 为准。本记录补充 [UI 基础计划](../ui-foundation-plan.md) 的控件方向，不另立实现规范。

## 判断

### 当前实现

同一编辑器工具条新增 Controls 实验台；通用数值/向量参数行、修改状态、默认值恢复、checkbox 与 foldout 已接入正式 UI/SS。实际位置参数已迁移到共享组合接口，整组 Reset 进入一次场景历史；实验台包括可操作的 Vector3/Vector4，样本有独立提交历史。具体合同与验收入口集中在[编辑器模块](../modules/editor/README.md#控件实验台)和[UI 模块](../modules/ui/README.md#可组合参数控件)，本记录下方保留调研时的依赖顺序。

实现只修改本 UI 工作树，没有修改 World 线程的工作目录。由于本工作树基线尚使用 Transform/Cube，后续集成需将新增的 `Session::reset_position` 接到新 SceneComponent 的同等原子 TRS 接口，并合并 Workspace 的控件组合改动；通用 UI 和实验台不依赖这些业务类型。

最终阶段验收：dev/release UI 15/15、编辑器文档链、普通窗口各 914 个接受帧均通过；真实搜狗输入法双配置通过，包括实验台的 Space 确认“位置”、组合位置查询、折叠及切换面板取消组合、样本/场景历史隔离。报告与截图位于 `out/{dev,release}/editor-evidence/` 的 `acceptance.txt`、`ime-acceptance.txt`、`controls-*.png`。前期被其他窗口占用前台的运行曾安全中断，最终结果来自完整成功运行。新窄面板验收连续发送完整拖动后再观察结果，避免合成消息与系统鼠标移动交错；原有分步拖动预览/取消验收保留。

验收启用真实硬件 D3D12 debug/GBV，不据此宣称产品帧耗时改善；DPI 覆盖为当前显示器及既有过渡政策，未进行多显示器迁移。未保存 Houdini 中的临时场景。提交边界为本工作树的基础控件增量，不含其他线程的 World 迁移或主线集成。

### Standards

规范审查发现 1 项 P2：搜索隐藏唯一修改分量后，整组 Reset 和标题提示被可见字段子集错误决定，不符合统一语义要求。现由 Workspace 在过滤前计算完整组状态，经 `NumberRow.group_modified` 交付组合层；字段仍独立比较默认值。审查者复核确认闭环，无新增阻断项。

### Spec

需求审查发现 2 项 P2：上述整组 Reset 问题，以及四字段主体固定 224 DIP 最小宽度超过窄面板内容宽度。后者改为根据实际字段、标签和间距计算最低宽度，共用绘制布局的尺寸常量；四个带标签字段最低 172 DIP。新增端到端场景覆盖搜索 X 隐藏已修改 Y 后整组 Reset/undo，以及 220 DIP 面板内 Vector4 全字段可见、W 编辑和撤销。审查者复核确认两项均闭环。

规范 1 项、需求 2 项（其中 1 项重合），均已修复并通过对应端到端验收。清理同时移除了手工 XYZ 行的重复布局和独立的最低宽度估算，并把旧阶段分支、旧派发限制与“未运行 Houdini”等说明标明为历史。

从基础控件开始合适。当前引擎已经有布局、文本输入、样式解析、绘制和命中链路；编辑器缺少的是可以反复组合的字段、分组、菜单，以及完整一致的编辑行为。继续把业务面板写成一批临时按钮，会扩大这个缺口。

先让一个参数面板真正好用，再扩展工作区。首轮以数值、向量和折叠分组为真实场景，同时建立可直接操作的控件实验台。实验台复用生产 UI 系统，用于快速检查布局、样式和交互。

## 实机观察

参考程序为已打开的 Houdini Indie 22.0.429 / Py3.13。原场景为空；操作中创建了一个临时 Box，未保存文件。实际查看了 Transform 参数、参数右键菜单、变换顺序下拉框，以及 Edit Parameter Interface 对话框。查看后取消了参数界面编辑，没有修改其定义。

| 观察 | 对本项目的启发 |
| --- | --- |
| Translate、Rotate、Scale 各用一个标签和一行三个字段 | 向量应是组合控件。各分量可独立编辑，同时有明确的整组操作范围。 |
| 非默认的 Translate 值有字重提示；从参数菜单恢复默认值后提示消失 | 默认值、当前值和编辑中的输入是不同概念。修改状态需要稳定来源，不能用焦点或最近操作代替。 |
| 参数菜单集中提供恢复、复制、锁定及更高级的通道操作 | 高频字段操作应统一。首轮只做已有业务能支持的项目，并清楚区分分量与整组目标。 |
| Transform Order 通过紧凑下拉菜单选择；面板同时组合滑条、勾选和标签页 | 不同值域需要不同控件，但焦点、禁用、菜单关闭等行为应保持一致。 |
| Edit Parameter Interface 展示 Float Vector 3、默认值、范围、标签、显示条件等字段，以及参数分组树 | 值的类型与界面呈现可以组合表达。这里是对可见能力的观察，不推断 Houdini 的内部实现。 |

SideFX 文档还说明了中键数值阶梯：在标签上调整整组、在单个字段上调整分量，通过垂直移动选择步长、水平移动改变值。本轮没有实际验证持续按住中键的手势，不能把它列入实机结论。我们已有数字拖动，可先统一步长、提交和取消语义，再判断阶梯是否值得增加。[数值阶梯文档](https://www.sidefx.com/docs/houdini/basics/ladder.html)

参数搜索、恢复默认值和字段编辑是参数面板的通用能力；面板跟随选择或固定目标属于另一个层级。后者应等对象选择与生命周期合同明确后接入。[参数编辑](https://www.sidefx.com/docs/houdini/network/parms.html)、[面板与固定目标](https://www.sidefx.com/docs/houdini/basics/panes.html)、[参数界面编辑器](https://www.sidefx.com/docs/houdini/ref/windows/edit_parameter_interface.html)

## 实施前基础与缺口（9ad772e）

- `ui::Session` 已有稳定控件身份、输入状态与已接受画面的命中依据；继续由它负责焦点、捕获和输入分发。
- 现有文本与数值编辑已有 DirectWrite、选区、光标和 IME 链路。向量字段应组合这些能力，避免复制输入逻辑。
- SS 已统一解析字体、内边距、颜色、边框和状态样式。控件外观继续通过 SS 表达；业务面板不再各自内嵌一套颜色和尺寸。
- `Workspace::describe` 目前承担大量手工控件描述，参数主要是固定的 XYZ 行。应逐步提取承担真实行为的控件组合，业务层保留目标选择、值读写和命令执行。
- 下拉框、菜单等需要公共浮层机制。若每个业务面板自行画菜单并处理鼠标，会分裂命中、裁剪和焦点语义。

不新建绘制器、文本输入系统或业务对象存储。控件的呈现信息也不能成为第二套 Runtime 类型与字段定义。本阶段仍是 C++ 基础系统模块，语言 UI 语法留待实际使用需要驱动。

## 按依赖落地

以下复杂度是工程判断，不是工时承诺。

| 顺序 | 交付内容 | 复杂度与主要难点 |
| --- | --- | --- |
| 1 | 控件实验台、公共参数行、NumberField / Vector3、明确的修改状态和默认值操作 | 中。复用现有输入；重点是稳定身份、窄宽度布局、整组与分量操作，以及一次编辑对应一次业务提交。 |
| 2 | Checkbox、折叠分组；将按钮、文本字段的外观与状态收敛到同一套 SS | 低至中。键盘可达、禁用和折叠后的焦点处理必须完整。实验台提供真实交互示例，不为展示而向 World 增加属性。 |
| 3 | 公共浮层、Menu、ComboBox，再按实际需要增加 Tooltip | 中至高。菜单越过父级裁剪，命中与实际画面一致；外部点击、Esc、IME、焦点恢复和对象失效处理是主要成本。 |
| 4 | 参数面板、对象树、搜索过滤、面板跟随与固定目标 | 中至高。依赖稳定的对象、选择、命令和生命周期合同。 |
| 5 | 标签工作区、停靠、布局保存；有明确需求后再做浮动窗口和节点图 | 高。布局恢复、跨面板焦点与输入路由会显著扩大范围。 |

第一轮不要求通用参数描述语言。先用真实字段组合验证参数行接口，出现重复的呈现需求后，再提取必要的标签、分组、默认值和范围信息。

## 第一轮验收目标

实验台和实际参数面板使用同一套控件实现。开发者可直接调整窄/宽面板、长标签和控件状态；字体变化沿用正式主题入口及既有窗口验收。实验台无需构造业务场景即可查看控件。

首批参数行应完成：

1. Vector3 使用一行三个数值字段；字段身份不随折叠、排序或选中对象改变而串位。
2. 数字输入与拖动遵守现有提交/取消合同；向量组合层不再实现一套文本输入。
3. 默认值与修改状态有明确来源。恢复操作明确作用于分量或整组，进入既有业务命令与撤销链路。
4. 正常、悬停、按下、聚焦、禁用、无效输入和已修改等状态可辨认，且各自含义一致。只读与禁用如有实际需求，应分别定义行为。
5. 面板变窄、滚动或折叠后，显示、裁剪、命中和光标位置仍然一致。

视觉上采用紧凑参数行、对齐的标签列、同一行内的向量分量和克制的分组层级。具体尺寸在实际窗口与缩放比例中确认，不能将 Houdini 截图像素直接当成本项目的 DIP。

验收采用实际端到端操作：编辑、取消、恢复、撤销/重做、切换对象、折叠和滚动；检查开发与发布构建。涉及输入或焦点修改时覆盖实际 IME。沿用既有验收入口，不增加单元测试或 mock 框架。

## 并行工作的边界

调研时 World 线程正在迁移 SceneComponent / StaticMeshComponent 及编辑器消费者。`workspace`、`session`、应用启动与渲染接入是后续合并需要协调的文件；本次未修改该线程的工作目录。

- UI 工作先集中在通用控件、SS 和实验台。实验台通过既有 UI 宿主接入，不自行管理另一套输入或绘制循环。
- World 线程继续稳定对象与组件合同。业务面板接入基于该合同落地，不继续扩大旧 Transform / Cube 界面的实现。
- 每次交付一个可操作的控件族，完成真实接入与端到端验收后再扩展。文件所有权与接口变更先说清楚，避免多线程同时修改同一输入状态机。
- 将行为证据保留在短验收记录中；公共约定更新现有模块文档，不逐轮累积另一套长期规则。

这条路径的收益是缩短“修改控件—看到结果—验证交互”的循环，并让后续业务面板使用已完成的控件。收益尚未测量，不将其写成性能或工期结论。
