# DDGI＋较远 SSGI 与表面探针 GI 的比较条件

日期：2026-10-16。状态：比较设计，尚未实施较远SSGI或第二条GI候选，尚无同预算实机结果。

用户已确认：保留DDGI主路线，在直接光改造之后公平比较“改良DDGI＋可靠SSGI”与“Capsaicin式表面探针＋世界缓存”。

## 较远SSGI的明确需求

原来的近场 Local GI（SSIL，最大半径 1.2 米）已删除，渲染器现在没有屏幕空间间接光；较远 SSGI 需要新实现。

候选距离首先取**4、8、16米**。单位沿现有场景世界尺度；这些是比较档位，不是已选定的最终默认值或永远固定的上限。依据地牢的实际贡献距离、可信命中率和成本决定默认值，不将灯的range直接当作反弹距离，也不以增加强度代替增加有效覆盖。

最大距离、射线数量和追踪步数各自表达不同约束。长距离追踪需要以下改进，不直接扩大现有16步线性追踪的步长：

1. **追踪效率与精度**：利用现有高精度深度／Hi-Z能力跨过空区域，在候选交点细化；核对正交与透视、viewport偏移、近裁面和Reversed-Z。共享深度层级按实际消费者管理，SSGI不能依赖SSSR恰好开启才获得有效数据。保持现有深度精度，不能用很厚的远距离容差把错误表面判为命中。
2. **有效性判定**：考虑交点误差、厚度、几何法线、背面、屏幕边缘与深度断裂。miss、不可信hit和合法零贡献分别处理；只统计成功命中会高估反弹能量。
3. **时域稳定**：同时检查接收面和贡献来源的身份、运动与可见性。复用现有SSSR／表面历史中适用的机制，避免墙面静止但照明来源已经移动时继续保留旧贡献；不以全场景历史清空代替局部失效。
4. **有界重建**：低频照明可采用稀疏或半分辨率求解并做边缘感知重建，主几何／材质／输出仍为原生1440p。所有候选明确记录这些设置，不能仅凭最终图像尺寸声称全率求解。
5. **复用现有入口**：沿World作者配置、ViewOption描述表和Control覆盖机制表达必要距离／质量参数，现有 `ssil`（Local GI）字段没有渲染实现，SSGI 落地时复用或替换它，不并存两个同义开关；名称与 Scene 兼容需要编辑器／World 对齐。

## 两条候选与共同输入

| 候选 | 核心职责 | 必须包含的工作 |
|---|---|---|
| A：改良DDGI＋可靠SSGI | 世界探针维持全局和屏幕外照明；SSGI处理可信的中近距离反弹与细节 | DDGI布点／重定位／更新／反馈／gather，SSGI追踪／重建／合成，以及所有必要visibility |
| B：Capsaicin式表面探针＋世界缓存 | 可见表面分配探针，二次命中复用世界radiance cache | probe布置／重投影／追踪／插值，cache构建／维护／失效，多反弹、必要visibility及重建 |

两者消费同一个场景、Geometry、Material、LightFrame、相机、曝光、直接光和阴影实现。比较期间直接光版本和配置冻结；不将一个候选配高质量直接光、另一个配廉价替代。

共同输出是材质调制前的间接辐照度，沿既有`lit_indirect_source`语义送入同一材质合成；保持坐标、HDR单位、曝光前后位置和有效性语义一致。内部直接产生这个量，不通过除以可能为零的albedo从最终颜色倒推。真实存在两个求解器后才提取必要的内部interface；不预建通用GI插件框架或第二套灯光／资源权威。

本比较针对漫反射GI，主反射路径保持相同。B若启用自己的SSGI等辅助阶段，其成本同样纳入；若某项额外工作不可剥离也如实计费，不把镜面反射等不同功能的差异混作漫反射GI胜负。

“Capsaicin式”必须列出实际实现的能力及固定参考源码。缺少世界cache、历史失效或完整多反弹的极简屏幕算法，不能冒充完整候选B并据此判定路线胜负。若只能运行不同引擎的演示，则只能作为外部参考，不属于同场景对照。

## 计能和融合：先验证，再扩大距离

DDGI保存辐照度；它不是可直接查询任意方向入射辐射度的完整radiance cache。当前以`E/π`作为各向同性基线的残差修正是有界近似。更长距离不能自动使这个近似成为精确的近／远场分解。

实施时先在受控场景验证近／远贡献或残差的共同估计域，再扩大地牢覆盖。允许保持有明确偏差界限的近似，但必须披露它对视角变化、能量和收敛的影响。不得把完整SSGI简单加到完整DDGI上，也不能把缺失的屏幕信息直接当作黑色。

- 发光网格现在只经 DDGI 照亮其他表面。SSGI 命中发光面的路径必须与 DDGI 的发光记录分工，不能重复加光；表面散射之后的反弹仍须保留。
- 屏幕来源应使用定义清晰的辐射信号，不能读取混合镜面、SSR、tone mapping和自身修正的最终颜色。
- 两候选使用相同的光路与材质目标。Capsaicin示例对部分secondary hit的`metallic=0 / roughness=1`处理不能偷偷用于B而让A保留完整高光传输；若评估共同的漫反射近似，单独声明和对照，不与原传输模型混为同一结果。
- 反弹数／反馈系数、环境、光源强度和能量增益对齐；不能通过增益补偿掩盖丢失光路或漏光。
- SSGI涉及的近场遮蔽与GTAO维持统一策略，避免重复压暗。比较中每一份AO／visibility成本和作用范围都明确。
- 若屏幕追踪需要有限RT补充，其工作全部计入所属GI候选。世界空间照明在遮挡与离屏情况下提供连续支持，不将“屏幕外不可见”包装成已解决的几何信息。

## 同预算的执行口径

1. **分辨率与输入固定**：RX6800XT、原生2560×1440、相同相机／材质／光源／曝光、SMAA、相同直接光和反射输入。实际render extent写入结果，不以client大小代替。
2. **统计完整GI成本**：所有GI专属ray、probe更新、cache管理、重定位、反馈、插值、重建、必要visibility与同步均计入。共享工作的归属明确，不能把一方的cache维护移出计时，或重复加总父子scope。
3. **先看质量—成本曲线**：以约2ms为面向90FPS的GI目标档，并保留较高成本档观察上限。实际匹配两候选的完整GI耗时，不能只匹配ray数、probe数或画面输出尺寸。某路线达不到目标档时直接记录，不靠少记阶段强行对齐。
4. **平均和尾延迟同时比较**：以稳定场景的相近实测成本选取参数，再记录动态负载的P50/P95/P99及维护峰值。允许有界跨帧摊还，但不能把未完成工作和长时间收敛隐去。
5. **公平预热**：使用相同事件时间线和墙钟时间观察首次进入与暖缓存；帧率不同不能通过相同帧数获得不同的实际预热时间。光照响应同时报告毫秒与有效观测次数。
6. **内存明确计费**：两者遵守同一产品资源预算；报告常驻、临时与退休中的逻辑资源量，具备可靠采集方式时另报实际驻留。不同内存使用可以是结果，不能视为无关的免费资源。
7. **性能与合法性分开**：正式Release计时，不使用GPU validation或截图读回时长作为性能；GPU合法性另做必要端到端验收。完成帧sequence去重，记录GPU外部负载、限帧与Present条件。

## 场景矩阵与指标

| 必测事件 | 主要观察 |
|---|---|
| 相机平移、旋转、快速切换 | 视角相关能量变化、disocclusion恢复、边缘退出、历史拖影与冷cache成本 |
| 发光物体移出屏幕但仍照亮可见墙面 | 屏幕外照明连续性，SSGI退出到世界照明时的跳变，直接／间接是否重复计能 |
| 灯光开关、等亮度换色、移动灯／发光体 | 墙面响应时间、过冲、残留、局部更新范围和GPU峰值 |
| 薄墙、门洞、楼层、柱子遮挡 | 穿墙、远距离误命中、接触处污渍与明暗泄漏 |
| 完全静止、窄缝强光、点光近场亮面 | probe亮峰、像素方差、热点持续时间，以及滤波是否通过暗化掩盖问题 |
| 无灯、无Sky Light、镜面／金属、零漫反射 | 合法黑色、材质及计能边界，不能凭补光或不正确材质近似增加亮度 |

同一事件脚本先录制状态变化，再分别重放。使用像素／表面ROI的时间序列、空间漏光与边缘指标，并附代表性图像；不只用单张好看的截图判断。

质量参考需要与被比较的GI光路一致。先以受控场景中充分收敛的相应光传输参考校验能量，再用真实地牢检查动态行为和成本；参考本身的近似与缺失光路必须记录。

## 决策和收口

优先保留DDGI生产主线；B只在有界比较范围内存在。A需要先改进布点／支持和SSGI，不能拿当前薄弱版本去对比经过充分调参的B。反之，也不能拿不完整B证明DDGI必胜。

在相同总预算下，依据可见细节、屏幕外稳定性、灯光响应、薄墙正确性、尾延迟、显存和实现复杂度决定是否替换。可能的结论包括保留A、替换为B，或只吸收B中经过验证的机制；不长期叠加两套完整GI。

对照完成后由Astra复审传输定义、预算归属和结论，再更新当前模块合同。失败原型及无实际用途的设置退出生产链，保留必要研究证据。
