# JIT 早退清理共享：历史实验与晋升证据

历史记录：2026-09-25。本文保留当时的两轮对照数据、负对照、验收范围与来源，用于解释正式 SourceLowering 为何共用早退清理块。原第 9.1/9.2 节编号保留以识别当轮证据；本文不维护当前执行合同或新的实施计划。

现行执行/发布合同以 [Runtime 协议](../runtime-model.md#已实现的最小业务执行协议)为准，模块与取舍见[结构说明](../runtime-structure.md)。以下旧探针、路径和复现命令只对应各自输入快照，不能与当前 DLL 混用；当前验收使用 README 的正式入口。
### 9.1 早退清理发射的单因素实验

2026-09-25 第一轮：完成隔离 A/B，**当时未合入生产编译器**；随后的小输入补测与正式晋升见第 9.2 节。A 为改动前实现，B 仅将每个 `return` 重复发射的用户槽清理汇入一个按需生成的 `cleanup.return` 块；仍先清用户槽，再进入原有快照路径。槽分配、词法生命期、清理顺序、错误清理、安全点、宿主适配与独立 LLJIT 所有权不变。不相交作用域的槽复用留作另一个因素，不与本次混合。

发布配置按 A/B/B/A 顺序运行四个独立进程，每进程 14 个源码场景 × 原生/描述型对象，各编译 5 次，总计 560 次；统计剔除每进程第一次编译。执行各预热 2 批，再采集 9 批，每批 128 次。下表为完整源码编译时间的中位数，每格各有 10 个样本；不是单独的 LLVM 优化阶段耗时。

| 早退点 | 强槽数（两版相同） | 静态 IR 清理调用 A → B | 原生编译 ms，A → B | 描述型编译 ms，A → B | 生成函数字节数（两版相同） |
| --- | --- | --- | --- | --- | --- |
| 1 | 3 | 8 → 8 | 3.64 → 4.07 | 4.06 → 3.66 | 564 |
| 16 | 18 | 308 → 68 | 11.44 → 7.51 | 13.46 → 7.09 | 1,780 |
| 64 | 66 | 4,292 → 260 | 121.39 → 19.54 | 131.83 → 18.01 | 5,572 |
| 256 | 258 | 66,308 → 1,028 | 3,851.83 → 69.20 | 4,146.63 → 73.10 | 21,124 |

**裁决：大规模早退的编译收益成立，不是执行或 GC 提速。** 重复清理的 IR 项由“早退数 × 用户槽数”变为单份用户槽清理；28 个场景的槽布局、静态 poll 数和最终函数大小均相同。64 早退原生场景的 128 次调用批次中位数为 235.00 → 234.65 μs，回收为 14.50 → 14.50 μs，退休为 60.40 → 67.50 μs；不能选取部分数字声称执行、回收或退休普遍改善。没有测量分配峰值或常驻内存，也不把 IR 缩小换算成内存收益。

语义与生命周期证据：开发/发布配置各运行两版正式 Business/JIT 验收，均 PASS；未改变的 Runtime 验收每配置运行一次，均 PASS。额外用真实对象覆盖首/中/末早退、正常落尾、原生失败、快照发布失败及合法安全点内完整收集，原生/描述型合计每版每配置 24 条路径、共 96 次。清理次数、槽顺序/根数/poll 的 64 位轨迹指纹和结果完全一致；没有保存完整事件数组，不把指纹称作形式证明。测量探针还逐次检查代码退休后的 Windows 展开表撤销及地址 `MEM_FREE`。

第一轮小输入对照有正负波动：例如原生空函数编译 3.36 → 3.71 ms，描述型空函数 3.56 → 3.23 ms。当时未锁 CPU 频率/亲和性，只有每版两个进程，不能据此证明小输入无回退，也不能把最佳规模倍数推广到真实游戏或编辑器。因此要求先补小输入交错对照，再评估这一窄优化的正式晋升；结果见第 9.2 节，不顺带改槽分配、poll、GC 或共享 LLJIT。

本机证据集中在 `out/review/jit-cleanup-single-factor/summary.json`：包含全部场景的分布、对照条件与验收结果。同目录保留 `contract.json`、源码/构建哈希、两版后端、执行/轨迹探针、CMake 原始参数导出的构建计划和逐进程原始结果；`out/` 不纳入 Git。准备好 README 的两种正式构建后，本机复现入口如下，不改根 CMake、工具链锁或正式输出：

### 9.2 小输入交错对照与清理共享晋升

2026-09-25：用户批准继续补测并落地。`SourceLowering` 已在正式编译路径中采用第 9.1 节验证过的按需共享清理块，未带入实验统计、环境开关或兼容分支。改动局限于首次早退时生成清理块、后续早退跳入同一块，以及保存块指针；原槽分配、词法根、poll、错误处理、快照交接和 LLJIT 所有权不变。

补测让两版真实 DLL 在同一进程、同一线程中交错编译相同源码，每对交换 A/B 顺序、轮换场景；四进程加载顺序为 AB/BA/BA/AB。线程固定到许可的逻辑 CPU 31，未锁频。8 个小输入/中等规模场景 × 原生/描述型，共 16 组；每组每进程预热 5 对、测量 30 对，共 4,480 次编译、1,920 对正式样本。每组有 120 对样本，下表采用每对 B/A 比值的中位数，而不是两个边际中位数相除。

| 场景 | 原生 B/A | 描述型 B/A |
| --- | --- | --- |
| 空函数 | 0.9911 | 1.0052 |
| 无用户槽的直接早退 | 1.0072 | 1.0182 |
| 1 个引用槽、1 个早退 | 0.9964 | 0.9982 |
| 默认循环 | 1.0008 | 1.0045 |
| 强/弱引用、无早退 | 1.0065 | 1.0154 |
| 1 个顺序空引用块、无早退 | 1.0046 | 1.0180 |
| 16 个顺序空引用块、无早退 | 0.9903 | 1.0090 |
| 16 个引用槽、16 个早退 | 0.6073 | 0.6087 |

小输入/无早退对照的配对中位数变化为约 -1.0% 到 +1.8%；原先单早退约 +12% 的偏差没有在该控制下出现。没有稳定的明显小输入退化证据，16 早退的编译耗时则稳定减少约 39%。这支持晋升少量、保持语义的去重代码，不是“任何机器/输入绝不回退”的统计保证，也尚未区分频率、缓存和进程顺序各自的影响。两版始终独立拥有 LLJIT；DLL 分别通过自己的编译、查询、调用和销毁入口工作，不跨 DLL 删除不透明代码对象。每次编译均核对服务/槽布局、真实展开表及退休后的 `MEM_FREE`；计时外实际执行各组首尾样本，检查结果、poll 和显式清理。

正式验收增加 `verify_reference_returns`，每对象来源覆盖 4 个退出位置 × 3 种成功/故障模式。发布回调在结果交接前检查所有用户强/弱槽已空，随后验证正常发布或注入发布失败；原生失败、完整新 GC 周期和已经发生的副作用也一并检查。该验收在改动前实现上 PASS；一次性负对照故意省去早退清理，会以 `Return kept a user root until snapshot publication.` 失败，证明没有让发布后的最终清理或 RAII 掩盖错误。错误变体只留在 `out/`，不进入正式构建。

正式 `dev`、`release` 的 Runtime、Business execution、JIT 验收均 PASS；每配置新增 24 个退出/故障子路径，两配置合计 48 次。正式发布 DLL 另跑 28 场景、140 次编译/退休及执行/回收探针：原生 64/256 早退的编译中位数为 18.06/76.34 ms，描述型为 17.80/67.66 ms。此单进程复测用于确认优化已进入正式产物，不与前轮机器状态直接拼接计算新倍数；执行、GC、退休和内存收益仍不作承诺。

补测原始数据与分布见 `out/review/jit-cleanup-promotion/interleaved-summary.json`，交付状态见 `out/review/jit-cleanup-promotion/verification.json`。同目录保留同进程探针、构建参数、四轮原始结果、负对照和双配置正式日志；历史第一轮证据不覆盖。正式复现继续使用 README 的 `cmake --build --preset dev --target acceptance` 与 release 对应命令。未更改语言规范、Runtime/GC 实现、ABI、根 CMake 或依赖锁，未改动 RHI/布局模块；槽复用仍是独立后续事项。
