# RHI 候选评估与证伪框架

状态：调研阶段的比较工具，不是正式 RHI 契约。与 [research-brief.md](research-brief.md) 一起使用。

## 比较对象和避免的误判

- 原生后端自研、通用低层抽象库、应用级可移植 GPU 层、完整引擎内部设计不是同一种交付；先明确各自替调用者承担的责任，再比较。
- 更长的后端/特性列表不自动带来更合适的 Interface。成熟项目的存在也不证明与本项目目标兼容。
- 不将单个示例可运行、文档宣称支持、源级机制存在和本项目实测通过混为同一级证据。
- 没有确定工作负载前不使用加权总分，也不以厂商性能宣传排名。

## 先分清不变量与策略

必须识别的风险：GPU 使用仍未结束时释放或覆盖存储、录制取消污染已提交状态、重复/错误提交、跨域资源误用、设备失效被解释为成功、持有者提前退出。

仍可选择的策略：公开强句柄或 owner/id、自动/显式状态管理、队列数、录制并发、提交线程、Shader 工具链、frame graph、后端数量、内存池和 descriptor 管理方式。不能由旧占位实现替我们作答。

## 共同评估维度

| 维度 | 必须回答 | 需要的证据 |
| --- | --- | --- |
| 职责 | device、窗口、呈现、shader、资源和调度分别由谁负责？ | 公开 Interface 和官方集成流程 |
| 生命周期 | 录制/提交/GPU 完成各阶段谁持有资源？公开资源释放的实际含义是什么？ | 文档与对应实现 |
| 状态与同步 | 资源访问依赖如何表达？谁维护权威状态？自动机制的前提是什么？ | 状态追踪/提交实现和限制 |
| 绑定 | layout、views、samplers、动态常量、shader 产物如何对应？ | 公开类型、shader/绑定说明 |
| 并发 | 可并行的操作、不可并行的对象、提交排序和线程亲和是什么？ | 明确线程契约，不靠示例猜测 |
| 上传与回读 | 谁负责暂存存储、版本、pitch、完成和映射借用？ | 相关生命周期与数据通路 |
| 故障 | OOM、设备丢失、提交失败和关停能观察到什么？不能保证什么？ | 返回值、回调、源码错误出口 |
| 适配代价 | 自有类型/语言接入是否引入双重身份、引用计数或状态追踪？ | 拟议使用链，明确推断性质 |
| 构建与维护 | 最小依赖闭包、编译配置、许可证、升级约束是什么？ | 固定来源的构建规则与许可 |
| 成本 | 哪些路径会分配、复制、同步或间接调用？ | 源级事实；性能结论另需测量 |

## 对抗评估规则

两条独立论证都必须接受质询：

1. **自研路线**：为何这些机制值得由我们长期维护？如果成熟实现能满足真实语义，应如何推翻自研必要性？不能以“可控”掩盖交付和维护成本。
2. **复用路线**：哪些约束能用小适配化解，哪些会穿透到渲染器/语言？何时包装演变成第二套 RHI？不能以“成熟”跳过集成与故障验证。

每条质疑均记录：被挑战主张、支持/反对证据、适用条件、未知项、能改变结论的最小实验。没有证据时标为待验证，不制造伪分歧。

## 路径验证候选实验

这些是待批准的实验，不是已运行结果；每项只使用候选的真实生产 Interface，不另造 mock backend。

### P1：可重现接入与最小实际消费者

固定版本、依赖、构建选项与许可证；在独立构建目录编译并运行真实消费者。若目标是图形，至少覆盖 shader/管线/绑定/纹理与几何上传的一次绘制，而非仅创建 device。若目标是计算，使用实际 dispatch 与可核对输出。记录系统、adapter、验证层、命令和退出码。

失败判据：必须引入未获批准的大规模平台/资产依赖、无法保持工具链约束、公开 Interface 不足以表达消费者，或只能绕过候选生产机制才成功。

### P2：跨帧更新、持有与释放

在多个提交仍可能在飞时更新或替换资源；覆盖取消/未提交录制、CPU 持有者退出、旧命令继续执行、输出读取与最终资源回收。以实际完成证据与输出验证，不用固定等待帧数或“没崩溃”判定。

失败判据：需要调用方维护第二套未明确的生命列表、发生提前复用、不能解释持有/释放位置，或只能全局 idle 规避普通更新。

### P3：声明范围内的并发与调度

仅在产品确认需要时验证多线程录制、多 pass 依赖或多个队列；先确认候选线程契约。对同一真实负载比较正确性和可观测代价，不从后端数量或线程数推导性能。

失败判据：候选实际语义与所需录制/提交模式冲突，或必须绕过其状态权威才能完成。

### P4：呈现、关停与故障

在已选图形场景中覆盖调整渲染目标/窗口尺寸、正常退出、尚有在飞工作的退出，以及可安全触发且被批准的隔离设备失效。正常过程与故障终态分开记录；故障实验单独进程、有限退出，不影响其他工作。

失败判据：设备失效误判完成、关停只能无限等待、缺少安全持有责任，或重要错误只能被吞掉。

## 阶段决策输出

研究结束只产生条件化短名单及未知项。对抗后提出少量能区分路线的实验；在用户确认首个消费者和关键语义后进入路径验证。正式落地仅承诺已验证范围，不把研究建议升级成生产能力声明。
