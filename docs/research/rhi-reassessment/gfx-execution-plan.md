# gfx 中心路线：实施推进记录

状态：用户已授权按研究分析、独立对抗、实施骨架、细节落地、真实验收推进。工作仅写入本 RHI worktree；不提交、合并或修改主工作区。

## 本轮目标

内部承担 GPU 资源、绑定、状态与在飞寿命复杂性，外部 Interface 尽量简单。以 gfx 的合法惯用方式为起点，不预设必须自研，不创建逐函数转发的第二套图形 API。Vertex、Mesh、Compute 为正式能力，Mesh Shader 为最低硬件要求；不建设旧 GPU 回退。

## 研究分工

- 执行与寿命：比较直接采用 gfx context、原生 interop、局部上游修正，明确提交/完成/退休责任。
- Shader 与绑定：核对反射、动态版本、失败传播及三管线共享数据；判定最新 opacity-micromaps 提交与本轮需求的关系。
- 工业实施：追踪 AMD Capsaicin 的真实 gfx 消费方式，以相关工业机制挑战自有 Module 的必要性。
- 主代理：准备项目工具链、可校验的构建源码和依赖闭包；串行拥有根构建和最终集成。

## 决策与交付顺序

1. 收集会改变路线的源码证据，而非扩大功能清单。
2. 独立挑战“整体复用足够”与“自有执行设施有必要”，记录成立条件和反例。
3. 固定职责、所有权、错误/退出、线程与 RDG 交接契约，写明明确不实现的上层消费者。
4. 实现选定方案与经同一 Interface 进入的真实消费者，不保留伪实现或重复状态权威。
5. 在 dev/release 构建和运行中验证三类管线、GPU 生成间接参数、输出回读、动态数据及安全退休；不以 feature 查询或编译成功代替行为验证。
