- 可以从头重新设计，但这不授权当前调研阶段删除旧代码或修改生产契约。
- 按“多代理搜索调研 → 对抗评估 → 路径验证 → 落地”推进，可以分阶段完成。
- 所有主代理和子代理的外部搜索、文档检索统一使用 Exa。事实回到官方文档、固定源码、论文原文；不以搜索摘要代替关键证据。
- 工作目录：`E:/FrostFoxAtelier-rhi`。主工作区不承载本轮写入。
- 后续讨论已确认：首个消费者是游戏引擎的 3D 视口；本 session 全权负责渲染部分，Renderer 同样可从零设计。UI 布局由另一 session 制作，完成后才归并。

- 用户已确认不建设旧 GPU 的场景渲染回退，即将 Mesh Shader 支持纳入最低硬件要求；这不等于禁止普通 VS/PS 绘制。

- 当前近期交付聚焦 RHI 本体；隔壁引擎专用语言未来用于程序化生成，只作为前置信息，不在本轮展开语言、建模系统或完整 Renderer。RDG 与 RHI 的状态/调度交接仍须明确。

## 项目背景与尚未确认的需求

当前项目方向是 Windows x64 游戏客户端与专用服务器，C++ 提供底层能力，自有语言与原生共享业务类型体系。该背景不是对 RHI 后端、句柄表示、线程模型或是否复用成熟库的预先裁决。

尚未确定：除 Mesh Shader 必需能力外的精确硬件范围、首个后端、其他必需图形/计算能力、第二后端时间表、生产所需并发规模与故障终态；程序化几何的双绘制路径、资源版本发布和 RDG 访问契约正在讨论。不得用假定需求给候选打伪精确总分；首轮报告中的“消费者与高级能力未定”应结合上述后续确认阅读。

## 调研分工

1. 通用低层图形抽象：NVRHI、Diligent Engine；重点是资源/绑定/提交/同步语义与集成成本。
2. 面向应用的可移植 GPU 层：bgfx、SDL GPU、wgpu/wgpu-native；重点是它们替应用承担什么，又限制什么。
3. 工业引擎实践：Unreal、Godot、Filament 的公开一手资料；区分 RHI、Renderer、render graph 和平台职责。
4. 学术与工业研究：真实相关的论文、技术报告和会议演讲；清楚区分同行评审论文与工程演讲，禁止凑数或把渲染算法论文直接当 RHI 架构依据。

## 统一证据格式

每份报告应包含：来源及版本/提交或访问时间、可核对事实、设计推断、与本项目的适用条件、不适用条件、未知项、可证伪的路径实验。

候选对比至少覆盖：公开抽象、CPU/GPU 所有权、状态/同步、资源绑定与 Shader 输入、录制/提交并发、窗口/呈现职责、错误与设备丢失、依赖及许可证、接入成本。未查到的内容标为未知，不以常识填补。

滚动文档只能标为滚动文档；未取得精确提交不得虚构。任何性能结论都需要可比测量，不能由厂商宣传或功能列表推出。

## 阶段门槛

- 搜索调研：形成来源可追踪的候选与机制证据，不选定赢家。
- 对抗评估：独立挑战自研路线与复用路线，列出改变结论的证据和条件；不为了对抗而制造分歧。
- 路径验证：根据讨论批准的候选开展最小真实构建/运行实验，记录版本、命令、退出码、能力和限制；此阶段前不声称集成可用或性能优势。
- 落地：只有目标、关键语义和验证结果明确后才变更生产实现。避免为候选路线先搭通用框架。
