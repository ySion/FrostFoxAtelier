状态：**M0 + M1 位置编辑首版已交付，dev/release 窗口验收通过；M2 待后续**

日期：2026-09-28

基线：`1ddaac3`

本页记录首个编辑器的范围、责任和验收终点。当前交付见[编辑器模块](modules/editor/README.md)；后续 M2 保留为阶段目标。
本轮交付位置 XYZ、列表选择、增删/撤销重做、可调分隔、基本相机及窗口生命周期；旋转缩放编辑、存档、JIT、节点画布、gizmo、视口拾取、自由停靠、多窗口和完整 IME 编辑器留待后续。
长期工程规则沿用 [AGENTS.md](../AGENTS.md) 与[工程指南](engineering.md)；启动和构建命令统一维护在 [README](../README.md)。

## 目标与范围

交付一个真实、可视、可操作的 Windows 单窗口场景编辑器，编辑多个方块并保存重开。
场景、Inspector 和源码行为操作同一 Runtime 对象；布局节点和绘制数据只承担呈现职责。
方块是首个几何类型，既有“生产机器”继续作为验收样例，不成为引擎产品模型。
界面围绕 Houdini 式面板与参数操作演进，先提供对象列表、场景视口、变换输入和状态反馈；下方工作包分别交付能力。
本阶段不做视口拾取、变换 gizmo、完整代码编辑器、连续播放世界、ECS、资产包或插件系统。
SOP 式程序化几何、RDG 和纹理图延后，保留定义、结果与执行的区分，不预建万能节点底座。
[旧图片资源提案](modules/resources/design-proposal.md)是未实施备选，不再是首个编辑器的强制前置；实施启动时由 RHI 负责人同步其状态。

| M1：可编辑检查点 | 可调面板分隔、多对象增删、列表单选与高亮、基本观察/聚焦、数值与向量输入 | 连续拖调同步预览、一次提交只记一次 undo；取消、非法值和焦点路由符合下方操作例 |

## 工作包、依赖与责任

会审基线只有 layout 核心、DirectWrite CPU 示例和 D3D12 原语；本轮已接通正式 UI 绘制、输入、首例控件及工作区。
下表按能力划分当前归属，M0/M1/M2 仍作为产品验收；每份协议文件由单一负责人维护。

| 工作包 | 依赖 | 责任与入口 | 可观察结果 |
| --- | --- | --- | --- |
| Layout（保留既有） | 内容度量 | UI 维护[布局入口](../src/ui_layout/layout.hpp)，只负责几何与布局版本 | 正式面板/控件使用同一 LayoutDocument |
| UI 绘制 | 布局、CPU 内容协议、窗口 RHI | UI 的 `src/ui/` 拥有绘制/文字内容协议；RHI 的 [Context](../src/rhi/rhi.hpp) 与 `src/renderer/` 负责 GPU 消费及 Present | M0 真实文字与按钮可见；矩形、线条、纹理/文字覆盖、clip、混合及 DPI 消费一致 |
| 输入交互基础 | Win32 事件、已接受帧 | 应用 `src/application/` 转换平台事件；UI 集中管理命中、焦点、捕获与路由，区分键盘命令和文本输入 | 按钮可点击；提交/取消、失焦和捕获丢失有统一政策，焦点逻辑不散入每个控件 |
| 通用控件 | 绘制、输入基础 | UI `src/ui/` 按首例交付标签、按钮、数值/向量输入、列表、滚动和分隔条 | M0 标签/按钮；M1 拖调、文字输入、列表选择和分隔操作，其余按实际需要增加 |
| 工作区 | Layout、控件、操作上下文 | 应用 `src/editor/` 组织面板区域、分隔、查看目标和当前操作上下文 | M1 视口+参数/对象列表，可调分隔；后续面板能力见 Houdini 方向 |
| 业务编辑 | Runtime、参数描述、Session；UI 消费其结果 | 应用 `src/scene/`、`src/editor/` 拥有参数语义、场景成员、选择/工具、历史与存取 | M1 同一参数编辑与预览；M2 保存重开和源码行为，全部进入同一正式应用 |

Runtime/JIT 线维护 [Runtime](../src/runtime/runtime.hpp)、[Program](../src/source/program.hpp)及 language/jit，提供既有接口确认和必要端到端支持，无必需前置扩展。
应用负责人拥有主循环、完整帧和整体产品验收，维护根 CMake 总接线；其他负责人维护各自模块 CMake，main 只组装启动。
控件直接使用生产接口并在同一应用验证，随能力交付接场景；不等待完整 UI 框架，也不复制[headless 消费场景](modules/ui-layout/composition.md)另建产品入口。
既有离屏执行与本轮窗口呈现分别见 [RHI 合同](modules/rhi/contract.md)和[renderer 合同](modules/renderer/contract.md)。
本轮已在 Context/gfx 补齐目标查询和帧结果；renderer 表达 accepted/skipped 与终态错误，frameId 留在 renderer 层。原生驱动故障/遮挡注入仍未动态验证。

## Houdini操作方向（首例与后续）

面板展示同一业务数据，同时可以有独立查看上下文，不把所有面板绑到唯一全局 selection。
首例只做可调分隔；pane 标签切换、面板类型切换、跟随/固定查看对象和工作区保存是后续具体能力，不作为 M0 前置。参照 [SideFX 面板文档](https://www.sidefx.com/docs/houdini/basics/panes.html)。
参数支持数值输入与连续拖调，精度调节可参照 [value ladder](https://www.sidefx.com/docs/houdini/basics/ladder.html)；一次连续操作只记一次 undo，Esc 取消并恢复初值。
参数面板与未来视口 handle 修改同一参数、进入同一编辑动作；handle 的操作参照 [SideFX 文档](https://www.sidefx.com/docs/houdini/basics/handles.html)，本期仍延后视口 handle。
视口观察、场景选择、当前工具与键盘焦点具有明确路由；未来 graph 选中、当前编辑对象和显示输出也分别表达，不能混成一个状态。
通用节点画布交互与 SOP/RDG 等领域求值分开，本期不因此实现 graph 框架。
鼠标键绑定和具体皮肤尚未定，这些操作参照不代表复制完整 Houdini。

## 场景身份、字段与编辑操作

Scene 保存持久 ObjectKey 到 Runtime 对象的目录；同一业务状态只存于实际场景对象。
ObjectId 仅在所属会话有效；重开保留 ObjectKey，重新建立 Runtime 身份和映射。
首版 SceneObject 使用内联 Transform；对象标量状态全部纳入同一可编辑字段目录。
数值输入、文件加载和源码执行后的检查复用同一目录及合法域，不各自维护字段清单。
字段 UI 描述由应用参数描述绑定 Runtime 字段，包含范围、默认值、单位和分组；纯 layout 与 Runtime 不承载编辑器规则，控件不复制业务状态。
应用与 RHI 在实施前用一个具体方块例子写定坐标系、单位、旋转/矩阵顺序及有限值、缩放范围。
UI 事件进入 Session 动作；统一的是校验、提交与历史，源码字段访问仍走现有 Runtime::write。
数值编辑具有开始、更新、提交、取消；连续编辑合为一次历史，非法值不能提交。
失焦和捕获丢失必须结束或取消相应交互；未变化的字段操作不新增历史。
撤销/重做重放记录值和成员变化，不重新运行源码。

可撤销删除先取得历史 ObjectRoot，再撤销场景持有并移出成员目录。
选择、绘制、源码 step 和保存都检查当前成员资格；保活不等于仍在场景中。
可撤销期间不调用 Runtime::destroy；撤销恢复同一 ObjectId，历史淘汰时释放对应根。
新增、删除、字段修改及恢复共用 Session 的状态变更规则，不开第二条业务操作路径。

## 源码单步（M2，尚未接入编辑器）

现有 source::Program 足够支持本阶段，无必需的 Runtime/JIT 前置扩展。
首个行为只对选中且仍在场景中的对象执行一步；公开原生 methods 为空，构造/析构没有宿主外部副作用。
执行前记录声明字段，成功返回并通过合法域检查后提交一次历史；失败或校验不通过恢复这些字段。
恢复只保证声明字段；临时分配、GC 和任意外部副作用不属于事务回滚。
源码受信任，Program 没有执行时间限制；CollectionBudget 是 GC 预算，不是执行超时或抢占机制。
显式“编译并执行”若编译失败，本次动作停止；旧版本保留，但不自动调用旧 Entry。
发布 busy 保留候选并报告状态，不执行旧 Entry；重试执行时重新检查目标与成员资格。
源码诊断与当前可执行版本状态对用户可见；行为源码的持久变更也参与 dirty 判定。
沿用[现行语言](../LANGUAGE.md)与[正式源码执行链](runtime-structure.md)，不增加沙箱或第二套语言入口。

## 保存、重开与 dirty（M2，尚未实现）

带格式版本的场景文件保存成员、持久键、变换、几何定义及行为源码内容。
ObjectId、FieldId、布局节点、JIT 地址和 GPU 句柄均不进入存档。
dirty 表示当前文档与保存点是否一致；保存成功才更新保存点，撤销回保存状态也可清除 dirty。
保存失败保留已有存档并显示错误；加载先完整验证、准备成功后才替换当前会话。
加载失败保留当前对象、选择、历史和保存点；成功重开建立新的会话历史。
序列化只覆盖本轮实际场景定义，不以此增设通用资产格式或对象迁移框架。

## 几何与绘制

单窗口内直接绘制场景像素 viewport 和 UI，共用一个 RHI Context。
首例使用共享方块几何、深度和基色。方块几何使用已有 Vertex 管线；完整 Mesh 资产系统延后；现行硬件门禁仍保留。
深度目标采用显式尺寸，与实际 backbuffer 匹配，不依赖纹理自动 resize。
几何参数定义、派生 CPU 几何和设备表示分别承担编辑、计算与执行责任。
变换变化只更新实例数据，不重建几何；几何参数变化才更新相应派生结果。

UI 定义并拥有 CPU 绘制与文字内容协议；文字测量、排版与栅格使用唯一链路，输出不可变覆盖数据。
应用提供实际 backbuffer 尺寸与 DPI；UI 据此生成物理像素 draw/clip，并保存转换与尺寸版本。
renderer 消费这些像素数据及 CPU 资源拥有者，负责矩形、线条、纹理及文字覆盖数据的上传、混合、裁剪、绘制与 Present，不再次做 DPI 换算。
当前共享数据结构与拥有关系以 [UI 协议](../src/ui/frame.hpp)、[控件入口](../src/ui/session.hpp)和 [renderer 入口](../src/renderer/renderer.hpp)为准。

## 完整帧、输入与生命周期

首期由一个 owner 线程推进 Runtime、Program、UI 与 RHI，GPU 异步执行，不每帧调用 finish。
应用拥有完整帧，固定场景数值、布局/文字版本及绘制所需资源；跨帧不持有 Runtime 原生借用地址。
按 renderer 的 frameId 对应完整帧，仅在最终帧结果成功且确认 Present 接受后切换命中 frame，不能以中途 Present 成功判定；skip 不切换，“接受”指逻辑接受而非扫描显示完成。
accepted 帧的 extent 是录制前捕获且实际呈现的尺寸；frame 后 resize 产生的新 extent 只用于下一帧，不能回填旧 frame。
尺寸/DPI 变化期间暂停指针命中并取消 press/capture；释放、失焦、捕获丢失事件继续处理。
新匹配帧最终成功且被接受后恢复命中，不能用旧几何处理新尺寸下的指针输入。
准备失败保留上一完整输出的保证只适用于录制前；上传也属于录制。
上传/编码开始后失败没有回滚，部分命令失败即由 renderer 阻止后续帧；Present 后 resize/wait/reset 失败也进入终态并停止交互，不再重绘旧帧。超时不等于 GPU 完成。
旧 CPU 帧及内容按拥有关系释放，GPU 使用期沿 gfx 现有退休机制管理。
关闭先停止输入与新执行，关闭 Program、取消并等待任务静止，再释放会话持有与执行依赖。
绘制资源和 Pipeline 释放后显式排空并关闭 RHI，再销毁窗口；Runtime 与宿主依赖覆盖全部使用期。

## 启动顺序与验收

1. 用户启动实施后，四线确认字段/坐标例子、窗口事件、CPU 绘制描述及 RHI 帧结果，各文件指定唯一维护者。
2. 首轮推进 Scene/Session 与窗口、UI 绘制/输入基础和标签按钮；RHI 窗口/UI renderer 与方块绘制同步推进，在 M0 汇合同一正式路径。
3. 按 M1、M2 递进演示；Runtime 线提供已有接口支持，只有真实缺口才扩展底层。
4. 应用负责人维护 README 唯一启动入口和整体操作步骤，用户从该入口体验每个检查点。
5. M1 具体验收：启动同一应用→拖动视口/参数区分隔→选方块→连续拖动位置 X、视口同步预览→松开只记一次 undo→撤销一次恢复→另一次拖动按 Esc 恢复初值；文本输入焦点下 Delete 只处理文本，不删除场景对象。
6. 只做真实端到端 dev/release 验收，并完成增删、非法值、撤销重做、保存→关闭→重开，以及源码单步与恢复。
7. M0 验收真实窗口的尺寸/深度/帧生命周期与遮挡；各阶段覆盖 resize/最小化恢复、DPI 输入过渡、编译失败、发布 busy、保存/加载失败和正常关停。
8. 报告各检查点的实际结果与限制；M2 两项均完成才结束本阶段，不建立单元测试或 mock 框架。
