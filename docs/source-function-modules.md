# 同模块多函数

状态：已实现。单源码请求选择一个公开入口；项目快照发布一组具名同步入口。内部函数与所属入口共同编译和退休。现行语法与限制统一见 [LANGUAGE.md](../LANGUAGE.md#同模块函数与入口)。

## 使用方式

```cpp
float process(const Array<float>& input) {
    Array<float> working = input;
    working.add(1.0);
    return sum(working);
}

float sum(const Array<float>& values) {
    float result = 0.0;
    uint index = 0;
    while (index < values.size()) {
        result = result + values[index];
        index = index + 1;
    }
    return result;
}
```

宿主仍使用已有入口：

```cpp
auto request = program.request("algorithm.source", source_text, "process");
```

首次发布前，多函数源码必须明确选择入口；单函数源码可省略。发布后省略名称沿用已冻结的入口。声明顺序和私有助手可以在新版本中调整，公开入口继续接受共享签名与接收者兼容性检查。

## 执行链

1. 前端收集类型、顶层常量声明和完整函数签名，解析常量依赖后再检查各函数体，因此可以前向调用或引用模块常量。函数名唯一，模块最多 1024 个函数和 1024 个常量；未知目标、参数不匹配、常量依赖环、直接/间接递归和内部 async 调用均在编译时报告带位置的错误。常量的类型、纯表达式与局部 const 规则以 [LANGUAGE.md](../LANGUAGE.md#声明与作用域) 为准。
2. 调用图从叶函数向上传播原生值使用、接收者需求和保持借用有效的效果。普通 plain record 按值参数/结果、一般拥有值或聚合借用的调用链只能使用符合 BorrowSafe 契约的原生方法；数学按值参数与局部不产生该限制，数学引用参数仍产生。未知效果无法通过助手绕过。未调用的函数不改变所选入口的执行要求。
3. 一个 LLVM module 包含选定入口和全部可达助手。助手以定型标量、数学值或普通记录存储地址及借用地址直接传参，不构造通用参数描述；公开入口和原生调用沿既有边界协议。编译期间完成各调用签名核对，普通 O2 可内联助手并消除中间值。
4. 每个函数的局部、拥有值、引用实参临时值和失败暂存使用栈存储。普通记录按值实参在调用方创建独立快照，被调函数直接使用快照，不进行二次复制；快照在调用方完整表达式结束时释放。存储分配位置不改变按值语义，也不允许借用逃逸。只为原生调用准备通用实参缓冲，其需求取可达函数中最大的实际原生调用参数数。
5. 单个 Invocation 持有全部引用槽，各可达函数有固定且互不重叠的区间；接收者槽由公开入口保留。同步 Invocation 在执行区间内保存定型身份，协程 Invocation 的持有槽保留根登记。函数只清理自己的引用槽和拥有值，内部同步调用只在自己的栈上建立帧。无环调用图保证同一函数不会同时有两个活动帧。
6. 失败状态与内部标量/数学/普通记录结果分开，原始错误逐层传播；每层先完成清理再返回。只有公开入口执行 begin/finish 策略与最终接收者清理，成功结果仍须通过整次执行资源检查后才交付宿主。
7. Version 持有完整编译模块及编译期求值后固定的模块常量；项目快照里输入未变的单元由新旧 Version 共同持有。活动调用、固定租约和挂起入口始终使用同一版助手与常量；修改常量只影响新版本，私有签名可随模块整体替换；退休仍由最后一个代码持有者负责。

`GetX`／`SetX` 派生的 [Property](../LANGUAGE.md#计算属性-property)在前端展开成上述普通调用，再做调用图与效果分析；赋值不产生一次额外 getter 调用。跨文件依赖按属性名同时纳入两个访问器，显式访问器名字也纳入同名属性候选和冲突声明。因此只写 `X` 的消费者会随 `GetX`／`SetX` 修改重新检查和编译，旧 Lease 仍使用旧访问器；不另建属性调用 ABI 或 Runtime 属性目录。

## 生命周期边界

值、const 引用、可写引用和聚合借用沿用既有契约。内部 const 标量/数学/plain record 引用可绑定临时值，普通记录结果及其字段不能绑定可写引用，临时存活至完整表达式结束，String 字面量存活到当前语句结束；内部助手不能保存或返回借用，也不能改变借用容器的结构。double 及内建数学值的定型运算、公共结果存储和默认值见[数学值规范](math.md)。

Runtime 对象字段可按值传给助手。对象字段借用需要 Runtime 原生调用的存储保护，当前仍仅开放给原生成员调用；源函数间可以传递调用方自有标量、记录/数组叶值及聚合引用。

async 公开入口可调用同步助手，助手退出后才允许 yield。String/Array 和一般拥有型记录仍限定同步执行，不能通过内部调用进入 async 入口；数学局部可跨 yield，数学借用保持同步限制。取消挂起入口时，所有助手帧均已退出，只需清理持久入口帧及其保留的对象根。

当前没有递归、跨模块调用、内部 async 调用、函数值、跨类动态分派、String/Array/资源记录按值返回或 async 聚合参数/结果；内建数学值与 plain record 支持同步按值返回。普通记录按值签名同时要求 Runtime `plain_value` 与保持借用安全的 `can_own` 资格；两者独立，编译时检查。公开结果沿同一 `invoke` 的 `ValueOutput` 交付，并要求准确 Runtime 类型身份。源码 enum/struct 见[类型声明](source-type-declarations.md)。递归需要按实际激活管理 GC 根帧，跨模块调用需要跨版本依赖契约；这些能力不由当前固定槽区间隐式授权。

## 项目快照与多个公开入口

```cpp
source::Program program(runtime);
source::SourceSnapshot snapshot{"game", 1, {
    {"Source/Math.source", 3, math_text},
    {"Source/Move.source", 8, move_text}
}};
auto request = program.request(std::move(snapshot));
if (!request) return std::unexpected(request.error());
auto candidate = source::Program::prepare(*request);
if (!candidate) return std::unexpected(candidate.error());
auto published = program.try_publish(*candidate);
if (!published) return published;
auto tick = program.entry("game.Move.tick");
```

`classes()` 返回 `{name,type,base}`，`entries()` 返回 `{name,signature,parameter_names,code}`，`parameter_names` 按顺序给出源码声明的参数名，不含 `self`；`code` 是入口的代码身份：一个编译单元的编译输入——单元的组装文本、导出名、快照名、`CompileOptions` 和成员目录——与上次发布的同一单元逐字节相同时沿用上次的值，否则取进程内从未用过的新值。组装文本是单元自身的文本（某个 class 的全部方法，或工程文件的全部顶层声明），加上它按名字直接或间接写到的顶层声明，按快照顺序排列。它保守而不精确：改一个全局函数、struct、enum 或常量，只更换写到它的单元的 code，改工程文件的任一顶层声明会更换全部工程全局函数的 code；局部变量与声明同名也算写到；改某个 class 的任一方法会更换该 class 的全部 code；成员目录包含 Runtime 的整个值类型目录，所以 Runtime 新增值类型会更换全部 code；撤销改动也得到新值，不跨进程稳定。`revision()` 是成功发布次数，首次发布前为 0，失败或被拒绝的发布不改变它；宿主可先比较它，再重读 `entries()`。视图在下一次成功发布或 close 后失效。`Candidate` 提供同名只读视图，供宿主在提交前检查业务约束；其预览类身份不可用于正式 Runtime 查询，base 已是注册的原生类型，视图在候选移动、销毁或成功发布后失效。请求拥有不可变快照，`Request::snapshot()` 可用于把诊断关联回原文件版本。`Error::source` 保存 UTF-8 字节定位。运行时错误继续由原执行协议返回。

类型布局、默认值和所有入口共同准备，实际 TypeId 与代码只在无回调提交时一起可见。某个编译单元失败会释放整组候选，旧代码继续使用。`busy` 不消费候选；旧请求、重复提交和关闭后的提交被拒绝。已发布模块只增长：新增 struct/enum、派生原生对象的 class、全局函数，以及已有或新增 class 上的方法（包括 begin/tick/post_physics_tick/late_tick/end）都可兼容发布，新类型在类型安全点（代码发布条件加 GC 空闲）与代码一起提交，已经创建的对象保留。删除或改名已发布的类型、字段、函数或方法，已有类型的字段、基类、默认值、范围、展示文本或定义变化，以及已有入口的签名、执行种类或接收者变化，返回 `ErrorCode::rebuild_required`，不会改写存量对象。参数名不属于签名：只改参数名是兼容发布，发布后 `entries()` 给出新名字。

编译单元有三种：工程单元包含工程文件的全部顶层声明，导出其中的函数，没有函数时只做检查；每个有方法的 class 一个单元，导出它的方法；每个引擎模块一个只做检查的单元，包含该模块的全部顶层声明，不生成代码。每个单元只编译自身文本和它写到的顶层声明闭包，所以生成代码的量只随实际写到的声明增长；每个顶层声明仍在所属单元里通过一次语义检查。方法名与工程全局函数同名、顶层名字重复都在所属单元里由解析器拒绝：方法写到了自己的名字，所以同名的全局声明会进入该类单元；重复的名字总在同一个工程单元或同一个引擎模块单元里。每个生成代码的单元形成一个 LLVM 模块，其中的多个入口共享 LLJIT 和展开表。所有入口复用既有 `Version → Invocation → Runtime` 执行与清理链。借用保护通过内部调用参数传播，同一个助手既可在值区间内运行，也可在普通入口中运行；两条调用链都不在执行区间内推进 GC。

一个单元的输入——组装文本、导出名、快照名、`CompileOptions` 和成员目录——与当前已发布模块里同一单元逐字节相同时，不再检查和编译：它的入口沿用已发布的机器码和 code，只为本次发布新建 Version。新 Version 带本次请求的序号，按新快照重建位置映射、诊断表和调试表，所以单元在文件里挪了位置、或同一文件别处有改动时，故障位置和断点都按当前文件给出。只从当前已发布的模块沿用，不从更早的版本里找。旧租约和新入口共用同一份机器码，机器码在最后一个持有它的 Version 释放后回收。编译出的代码只引用固定的服务符号、自己复制的成员目录和原生类型注册时给出的 `sequence_view` 函数地址（成员目录的比较包含这些地址），不引用编译它时的 Contract 或请求，旧模块释放后照常运行。因此改一个类只编译这个类；改一个引擎函数，只重新检查它所在的模块和写到它的其他引擎模块，只重新编译写到它的类和工程单元。

发布开销（release，`atelier_source_measure --compile-units`，2026-10-23，Ryzen 9 3950X）：合成引擎库由 5 行的函数组成，每 8 个连成一条调用链；类 k 调用第 k 条链的末端，最后一条链没有调用方。表中是重新发布 5 次的中位数，括号里是 code 变化的入口数（每个类两个入口）：

| 引擎库 | 类 | 改一个类 | 改被调用的引擎函数 | 改没被调用的引擎函数 |
| --- | --- | --- | --- | --- |
| 500 行 | 1 | 27.2 ms (2) | 25.8 ms (2) | 0.7 ms (0) |
| 500 行 | 10 | 24.4 ms (2) | 25.6 ms (2) | 0.9 ms (0) |
| 500 行 | 50 | 26.6 ms (2) | 131.7 ms (10) | 2.3 ms (0) |
| 3000 行 | 1 | 25.2 ms (2) | 30.1 ms (2) | 7.6 ms (0) |
| 3000 行 | 10 | 33.3 ms (2) | 36.3 ms (2) | 8.2 ms (0) |
| 3000 行 | 50 | 26.1 ms (2) | 29.6 ms (2) | 6.7 ms (0) |

500 行、50 个类时有 5 个类调用被改的函数，所以重新编译 5 个类。

具名 `Entry` 只在绑定时解析名称，调用时直接按稳定槽位取得当前 Version；候选在提交前对齐已发布槽位，新入口追加在其后。代码租约保留实际使用的旧模块，关闭 Program 后仍可完成调用。Runtime、原生服务和后端 DLL 必须存活到所有租约/任务释放。

语法与限制以 [LANGUAGE.md](../LANGUAGE.md#项目快照与原生派生类) 为准。项目文件、World 生命周期调度和上下文重建由宿主组织；当前没有后台编译或对象布局迁移。

引擎附带的源码放在 `assets/engine/<模块>/**.source`。构建把这些文件原样复制到可执行文件旁的 `engine/`：每次重新配置先清空目标目录，增删或修改 `.source` 文件都会触发重新配置。`source::engine_sources(root)` 按路径排序读取 root 下的 `.source` 文件，快照路径为 `engine/<相对路径>`，root 不存在时没有文件；`source::default_engine_root()` 在源码树的 `assets/engine` 存在时返回它，否则返回可执行文件旁的 `engine/`。工程文件、UI 源码和引擎文件共用 `source::read_source_file`：单文件最多 1 MiB，必须是 UTF-8，版本是所存字节的 `source::content_hash`（FNV-1a 64），正文去掉 UTF-8 BOM。编辑器和 Play 的 `ProjectCode::snapshot` 在工程文件之后追加全部引擎文件，16 MiB 总上限一起计算，轮询也覆盖引擎文件；其他宿主直接调用同一组函数。引擎文件属于每个快照；其中的全局函数和常量只供源码调用，不是入口。改一个引擎函数只更换写到它的单元的 code。

## 端到端验收

[正式消费者](../acceptance/source/modules.cpp)通过公共 Program 接口覆盖：

- 前向、多层与重复助手调用，嵌套实参求值、float/int/uint 值传递、const 标量临时、引用别名及 String 字节临时。
- 原生 Array 的深复制、跨函数借用、BorrowSafe 原生算法、深层原生异常/越界与部分复制失败后的逐层清理；逐项核对返回宿主的原始错误码和原因。
- 调用者与助手对象根的隔离、暂停 GC 中的调用、退出回收，以及挂起和取消时保留/释放正确根。
- 入口显式选择、缺失/歧义入口拒绝、冻结入口拒绝切换、只读/结构修改/递归/async 调用拒绝、传递效果拒绝及未调用助手的隔离。
- 私有助手名称/顺序/签名变化的整模块替换、旧租约执行，以及挂起入口恢复时继续调用旧助手。

模块场景随 `source_acceptance` 和 `jit_acceptance` 运行。

项目快照消费者见 [projects.cpp](../acceptance/source/projects.cpp)。它覆盖跨文件 helper、原生派生类与标量默认值、向量与枚举类字段的默认值和属性（范围、展示文本、编辑后需要重建的边界、按字段定位的拒绝）、具名多入口及其参数名、原子更新、只改参数名的兼容发布、旧租约、入口重排、错误文件定位、无入口语义检查，混合借用入口对 GC 的影响，入口 code 与 revision 随编译输入的变化，值区间内只读 `self` 字段且不改变借用与 GC 规则，以及引擎源码：从磁盘读出排序、带 `engine/` 前缀、去 BOM、版本只随所存字节变化的文件，可执行文件旁的 `engine/` 与 `assets/engine` 逐文件相同，限定名函数与常量的调用和局部遮蔽，工程类派生引擎命名空间里的原生基类，以及各条命名空间、路径和同名规则的拒绝位置；编译单元：引擎函数不是入口，类经引擎助手的传递调用，没被调用的引擎函数和没被使用的工程常量仍做类型检查，重复的顶层名字与方法和全局函数同名被拒绝，改没被调用的引擎函数不更换 code，改被调用的引擎函数只更换调用方的 code 并得到新结果，改一个类只更换该类的 code，引擎函数原样移入工程文件后，工程单元的文本不变、导出增多，全部入口取新 code；输入未变的单元：类挪到文件里更后的行后机器码地址和 code 不变，故障位置与断点按当前文件和版本给出，编译选项变化时重新编译并带上调试点，旧租约照常调用并按各自的文件版本报告位置，释放编译它的旧模块和 Contract 之后沿用的入口照常运行（dev 构建的 mimalloc 用 0xDF 填充释放的内存，悬空引用会在这里失败）。可单独运行 `atelier_source_minimal.exe --projects`；完整覆盖仍在 `source_acceptance` / `jit_acceptance`。
