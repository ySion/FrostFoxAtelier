# 同模块多函数

状态：已实现。一个 Program 选择一个公开入口，内部同步函数共同编译、发布和退休。现行语法与限制统一见 [LANGUAGE.md](../LANGUAGE.md#同模块函数与入口)。

## 使用方式

```cpp
float process(const Array<float>& input) {
    Array<float> working = input;
    working.add(1.0);
    return sum(working);
}

float sum(const Array<float>& values) {
    float result = 0.0;
    uint index = 0;
    while (index < values.size()) {
        result = result + values[index];
        index = index + 1;
    }
    return result;
}
```

宿主仍使用已有入口：

```cpp
auto request = program.request("algorithm.source", source_text, "process");
```

首次发布前，多函数源码必须明确选择入口；单函数源码可省略。发布后省略名称沿用已冻结的入口。声明顺序和私有助手可以在新版本中调整，公开入口继续接受共享签名与接收者兼容性检查。

## 执行链

1. 前端收集完整函数签名，再检查各函数体，因此可以前向调用。函数名唯一，模块最多 1024 个函数；未知目标、参数不匹配、直接/间接递归和内部 async 调用均在编译时报告带位置的错误。
2. 调用图从叶函数向上传播原生值使用、接收者需求和保持借用有效的效果。拥有值或聚合借用的调用链只能使用符合 BorrowSafe 契约的原生方法；未知效果无法通过助手绕过。未调用的函数不改变所选入口的执行要求。
3. 一个 LLVM module 包含选定入口和全部可达助手。助手以定型标量或引用地址直接传参，不构造通用参数描述；公开入口和原生调用沿既有边界协议。编译期间完成各调用签名核对。
4. 每个函数的局部、拥有值、引用实参临时值和失败暂存使用本函数栈存储。只为原生调用准备通用实参缓冲，其需求取可达函数中最大的实际原生调用参数数。
5. 单个 Invocation 持有全部根槽，各可达函数有固定且互不重叠的区间；接收者槽由公开入口保留。函数只清理自己的根和拥有值，内部同步调用只在自己的栈上建立帧。无环调用图保证同一函数不会同时有两个活动帧。
6. 失败状态与内部标量结果分开，原始错误逐层传播；每层先完成清理再返回。只有公开入口执行 begin/finish 策略与最终接收者清理，成功结果仍须通过整次执行资源检查后才交付宿主。
7. Version 拥有完整编译模块。活动调用、固定租约和挂起入口始终使用同一版助手，私有签名可随模块整体替换；退休仍由最后一个代码持有者负责。

## 生命周期边界

值、const 引用、可写引用和聚合借用沿用既有契约。内部 const 标量引用可绑定临时值，String 字面量存活到当前语句结束；内部助手不能保存或返回借用，也不能改变借用容器的结构。

Runtime 对象字段可按值传给助手。对象字段借用需要 Runtime 原生调用的存储保护，当前仍仅开放给原生成员调用；源函数间可以传递调用方自有标量、记录/数组叶值及聚合引用。

async 公开入口可调用同步助手，助手退出后才允许 yield。拥有型原生值仍限定同步执行，不能通过内部调用进入 async 入口。取消挂起入口时，所有助手帧均已退出，只需清理持久入口帧及其保留的对象根。

当前没有递归、跨模块调用、内部 async 调用、函数值、源码 class 或聚合返回。源码 enum/struct 已在[类型声明](source-type-declarations.md)阶段接入。递归需要按实际激活管理 GC 根帧，跨模块调用需要跨版本依赖契约；这些能力不由当前固定槽区间隐式授权。

## 端到端验收

[正式消费者](../acceptance/source/modules.cpp)通过公共 Program 接口覆盖：

- 前向、多层与重复助手调用，嵌套实参求值、float/int/uint 值传递、const 标量临时、引用别名及 String 字节临时。
- 原生 Array 的深复制、跨函数借用、BorrowSafe 原生算法、深层原生异常/越界与部分复制失败后的逐层清理；逐项核对返回宿主的原始错误码和原因。
- 调用者与助手对象根的隔离、暂停 GC 中的调用、退出回收，以及挂起和取消时保留/释放正确根。
- 入口显式选择、缺失/歧义入口拒绝、冻结入口拒绝切换、只读/结构修改/递归/async 调用拒绝、传递效果拒绝及未调用助手的隔离。
- 私有助手名称/顺序/签名变化的整模块替换、旧租约执行，以及挂起入口恢复时继续调用旧助手。

本阶段 dev/release 均已通过上述模块场景及原有源码、JIT 平台和业务验收；相关反射、World 和无窗口编辑器文档消费者也已使用同一工作树配套重建并通过。可通过 `jit_acceptance` 运行模块与 JIT 场景。日志为 `out/function-modules-final-dev.log` 与 `out/function-modules-final-release.log`。没有测量本阶段的业务吞吐收益。
