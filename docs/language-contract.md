# 业务语言设计契约

状态：已实现最小源码编译与 JIT 执行子集，包括标量/枚举的值、只读引用与可写引用调用，原生记录/Array/只读 String 的同步借用与直接存储访问、String/Array/记录拥有型局部、源码 enum/struct、原生派生 class、跨文件快照、受控原生算法调用和同模块同步函数，共同函数签名、共享 Runtime 成员绑定、单入口兼容方法体发布，以及[显式协程](../LANGUAGE.md#显式协程)；首次发布固定接收者要求和执行种类。完整语言、源码类之间的继承、借用返回与资源聚合值按值调用、通用方法分派及布局迁移尚未实现。术语见 [CONTEXT](../CONTEXT.md)，已实现能力见 [README](../README.md)。

当前基线是已经贯通的[类型与对象运行时](runtime-model.md)及最小源码子集；后续语言能力由精简游戏 kit 的真实需求推动。[字段契约](runtime-model.md#字段契约)已确认，模块分工和执行路径见[结构说明](runtime-structure.md)。以下已确认语义保留，不以先完成通用语言或完整复刻 UObject 体系为前提。

## 已确认契约

以下是已确认的设计方向，其中包括尚未开放的声明与程序组织能力；实际可编译范围以 [LANGUAGE.md](../LANGUAGE.md) 为准。

### 统一类型体系

原生注册与语言编译共同产生同一权威类型体系的定义。反射访问与编译后的直接执行共享语义。语言从 AngelScript 风格的简单核心起步，以真实业务推动后续特性；待定项不是首版功能清单，也不意味着每项运行时机制都要新增语法。

所有业务对象，包括完全由业务语言定义的类实例，都由引擎共享核心运行时管理类型、身份、分配、构造和销毁。编译后的对象创建操作使用同一机制；执行中的局部持有和临时持有参与同一套根管理，不另建脚本对象世界。值仍按值语义存储，不要求逐值创建对象身份。

当前函数实现共用[签名与结果契约](runtime-model.md#共享函数签名与结果)：原生注册推导实际 C++ 声明，源码首次发布使用真实编译产物建立声明，宿主消费者期望另外核验。共同语义不要求共用调用 ABI；编译分类及私有接口表示不能变成另一套权威业务定义。

### 编译与执行

- 业务语言只采用 JIT 执行，不建设解释器或字节码 VM。JIT 是当前执行方向，不是字节码执行器之后的可选加速层。
- 准备执行的代码必须先完成必要的类型检查、机器码生成、链接与发布校验；失败不能进入该新版本执行，也不回退到解释执行。首次调用前编译与提前批量编译的具体策略尚待验证，不把此要求解释为必须在启动时编译全部程序。
- 语言用于游戏业务和编辑器工具。修改编译成功后无需关闭引擎即可使用新代码是设计目标；Play / 非 Play 不直接决定代码是否在执行、是否有存量对象或能否安全更新。
- 执行性能与修改到生效的延迟分别验收。机器码已生成不代表已经达到性能目标；后台编译时旧版本仍可执行，也不代表新版本已经生效。
- 不为不存在的解释器预先确定栈式或寄存器式字节码。源码前端产出定型语法树后降低为 LLVM IR，执行链见[业务执行闭环](../README.md#jit-业务执行闭环)。

### 程序、名称与访问

- 工程配置纳入源码与原生定义，编译器收集声明并追踪依赖；语言没有 `import`、`include`，无需手写前置声明。
- 语言没有 `file` 或文件级声明、访问作用域。文件用于组织源码、诊断与增量编译；保持声明作用域和目标归属不变地移动文件，不改变名称或可见性。
- 类型名按作用域查找，同命名空间可用短名，跨命名空间使用限定名；不按全程序唯一短名隐式回退。例如 `Ship` 中可引用 `Industry.Pump`，不能仅因全程序只有一个 `Pump` 就直接用这个短名。
- 同一程序、同一声明作用域中的同名普通类定义冲突，跨文件也一样。若后续支持显式 `partial`，合法片段组成同一个类型；同名本身不触发合并。
- `private` 保护所属类型内部，限定名称不能绕过访问限制。同一类型的不同 `partial` 片段共享其私有成员。顶层定义正常参与程序内引用，不具有文件或命名空间私有边界。

命名空间负责组织名称，不自动承担分配、对象生命周期或代码卸载职责。顶层辅助声明因此不能仅对某个文件隐藏；需要严格私有的辅助行为由类型成员表达。文件路径和全限定名称不直接作为永久存档身份。

### 值与赋值

类型声明区分值数据与有身份的对象，普通赋值按类型语义处理：

| 场景 | `b = a` 的行为 |
| --- | --- |
| 坐标等值数据 | 复制值；修改 B 的自有数据不改变 A |
| 机器等对象引用 | 复制引用；二者仍指向同一对象 |
| 含数量与对象引用的组合值 | 数量独立复制，引用继续指向原对象 |

创建或克隆独立对象需要显式操作，值复制不递归克隆对象图。值语义不规定栈分配，对象身份不规定逐对象分配；编译器可消除不影响可观察行为的复制。

### 所有权与销毁

普通业务对象由有效的持有引用保持存活，不再被需要时由运行时自动回收。世界管理对象保留显式销毁能力，销毁后遵循下述失效句柄规则。两类需求共用统一的类型与身份机制；当前引用语法见 LANGUAGE.md，源码显式销毁的权限与接口仍另行确定，具体收集算法不固定为语言语义。

采用 GC 自动回收从外部持有入口沿持有引用无法到达的普通业务对象，包括它们之间的持有环。GC 工作随 Tick 渐进推进；失去可达性不意味着立即执行析构或释放内存。当前运行时的屏障、分步收集与软预算实现见[分步回收](runtime-model.md#已实现的分步回收)；执行根与安全点已接入生成的业务函数，引擎 Tick 调度和通用语言帧尚未实现。

GC 不搬迁存活对象，活对象的存储地址不因 GC 改变。地址稳定不替代持有关系或句柄有效性检查：对象仍可被显式销毁，或在不可达后被回收。

普通业务对象的变量与字段默认使用持有引用；观察引用须显式表达，不阻止目标自动回收。两者可指向同一对象，区别在引用关系的生命周期作用。缓存和回调按其实际需求选择，不自动全部采用观察引用。

持有引用与观察引用都允许为空，默认初始化为空。空引用没有目标身份，与保留旧身份的失效引用不同；目标销毁不自动清空引用。非空引用约束后续按需求增加，具体语言写法另定。

观察引用支持非抛出式“尝试取得”：成功返回临时持有引用，失败返回失败结果。检查与取得共同保证普通业务对象不在两者之间被自动回收；临时持有不阻止世界管理对象的显式销毁，也不等于对象数据加锁。源码以 `try_acquire` 返回可空持有引用表示有无目标，具体类型、写法与操作错误的区分见 [现行引用规则](../LANGUAGE.md#空值失效与失败结果)，不在这里维护另一份语法表。

### 失效句柄

句柄在所属运行时上下文中以登记位置和对象代际识别目标。对象失效后，旧句柄保留原身份与代际，既不自动变为空值，也不指向复用位置的新对象。实际解引用失效句柄时返回可诊断的执行错误；当前宿主使用 Result 错误通道，尚无源码异常捕获。仅复制、保存句柄不会访问对象，也不会因目标失效而收到异步错误。

对象代际独立于类型定义版本和代码版本。类型或代码更新本身不代表对象身份被替换；热更新能否保持身份取决于具体迁移语义。

代际校验只识别身份有效性，访问期间仍需保证存储有效，包括并发销毁、回调重入和热更新场景。在可证明对象持续有效的区间内可以合并检查；一次校验不授权无限期缓存裸指针。

## 已实现的最小源码子集

当前词法、语法和已实现语义统一由 [LANGUAGE.md](../LANGUAGE.md) 描述；编译器只有一种语言模式。本页记录设计方向及尚待落实的合同，不维护第二份平行语法表。

当前支持单绑定对象类型的持有/观察局部、空值、创建、取得、身份比较及生成清理；入口参数支持现有标量/枚举及其同步借用，并支持已注册原生记录/Array/只读 String 的同步借用，显式标量结果与失败状态分开，成员表来自宿主共享类型元数据。同步体还可创建拥有型 String/Array/记录，调用声明保持借用有效的原生方法，并在各退出路径执行值清理。另支持[单入口兼容方法体发布](runtime-model.md#单入口兼容方法体发布)。同模块函数已支持前向调用、效果传播和逐层清理；源码 enum/struct 和原生派生 class 已通过 Runtime 类型发布接通，项目快照支持跨文件和多个同步入口的整组替换；跨发布单元调用、递归、源码类之间的继承、多对象类型/含引用记录值帧和结构迁移仍未完成；运行时能力不自动等于语言已开放对应语法。

[现行协程规范](../LANGUAGE.md#显式协程)定义 `async` 入口和 `yield` 语句。执行种类参与共享签名及发布兼容检查；宿主同线程恢复，挂起根与旧版本代码保持有效，取消和完成分别处理。核心协议见[协程核心协议](runtime-model.md#协程核心协议)，没有引入业务调度器或原生深层挂起。

## 待定规则

- **生命周期扩展**：外部根、引用登记、显式销毁与分步 GC 已有[当前协议](runtime-model.md#已实现的分步回收)。待定的是更完整引擎阶段、多线程参与、并发/分代回收及一般值帧的安全条件，现有机制不重新列为未定。
- **源码与查找细则**：目标输入筛选、命名空间跨文件组织语法、局部变量使用顺序、精确遮蔽优先级、别名，以及标识符编码与规范化。
- **访问与声明**：成员默认 `private`、显式 `public` 是当前建议；顶层 `public` 写法、嵌套类型访问、编辑器反射可见性和 `partial` 的引入时机待定。
- **函数与依赖**：重载、类型推导和隐式转换。建议原生与语言声明统一检查冲突，重复签名或歧义报错；增量依赖覆盖候选集变化；名称互引不强制文件无环，布局、继承和初始化环分别检查。
- **引用与调用**：非空约束的引入时机、一般函数参数与返回值的复制/借用、移动与复制控制，以及异常捕获和原生调用边界。现有观察取得的源码范围见 LANGUAGE.md；可空性与目标存活性分别描述。
- **实现契约**：一般布局、通用 ABI、并发访问期间的生命周期和结构迁移仍待明确；单入口兼容方法体已在 Runtime 无活动执行且通过发布准入时提交。挂起协程不占活动执行计数，但继续持有旧版本。不承诺任意布局变化均可在线生效。
- **扩展函数与运算**：当前最小函数、严格类型、无符号回绕和浮点规则见已实现子集；一般函数形式、数值转换、除零及进一步浮点优化约束仍须按真实需求确认，不能把 LLVM 的默认行为直接当作语言规范。

当前 JIT 接入能力与边界见[运行时协议](runtime-model.md#jit-执行)，模块分工及现行取舍见[结构说明](runtime-structure.md)。
